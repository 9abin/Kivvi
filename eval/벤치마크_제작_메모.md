# 평가셋 제작 메모 (val 30건 + 최종 벤치마크 100건)

## 목적
기능 2(조 개정 시 영향받는 조 찾기)의 후보 찾기 단계를 평가한다. 후보 찾기 = RAG + 규칙 그래프(PR #11) + 도메인 그래프(PR #12)로 앵커당 50개.
판단 모델/LLM으로 거르는 단계는 나중이므로 이번 평가셋에는 쓰지 않는다. RAG와 그래프는 다른 팀원이 개발 중이다.

## 두 평가셋
| | val셋 (개발용) | 최종 벤치마크 |
|---|---|---|
| 규모 | 30건 | 100건 |
| 시작 조가 4개 도메인(인사/보수/휴가/휴직)인 문항 | 약 25% (7~8건) | 25건 |
| 나머지 | 전체 규정 90건에서 무작위 | 75건, 전체 규정에서 무작위 |
| 정답 개수 분포 | 지수 형태 | 지수 형태 |

- 형식은 PR #11 평가셋 그대로: 개정문 1건당 `changes.jsonl`(수정) + `labels_final.jsonl`(영향 조 목록, 근거 문장은 원문 발췌). 도구는 `eval/impact_label_kit_dom/`(지시서.md, validate.py)를 복사해 쓴다.
- 정답은 도메인 안으로 제한하지 않는다(실제 영향은 도메인 경계를 넘는다).
- val셋과 최종 벤치마크는 개정 조가 겹치면 안 된다. 둘 다 아래 "제외 목록"과도 겹치면 안 된다.

## 제외 목록 (개정 조로 뽑지 않는다)
- PR #11 평가셋 24건의 개정 조
- PR #12의 개정 항목(120문항, 단일 변경 60문항)의 조
- 이미 만든 4도메인 신규 30건(`eval/impact_label_kit_dom/산출/changes.jsonl`)의 개정 조. 이 30건은 4개 도메인 한정이라 val셋 도메인분으로 재사용 가능한지는 따로 판단한다.

## 시작 조 뽑기
- 도메인 문항: PR #12 도메인 DB(`domain_ontology.reviewed.db`)에서 개념에 "정의" 또는 "근거"로 연결된 조(약한 "언급"만인 조는 제외)에서 난수로 뽑는다.
- 나머지: 규정 90건 전체의 조에서 무작위. 규정별 쏠림이 크면 규정 단위로 상한을 둔다.
- 난수 시드는 기록해 둔다.

## 정답 개수 분포 (지수 형태)
- 구간 할당이나 균일 분포는 쓰지 않는다. 개정 종류(값 변경, 삭제, 번호 이동, 정의 변경, 위임·법령 변경, 표현 수정, 고립 수정)를 자연스럽게 섞어서 대략 다음 모양이 나오게 한다: 0개 약 30%, 1개 약 23%, 2개 약 14%, 3개 약 8%, 4~7개 약 15%, 8개 이상 약 10%.
- 정답 개수는 라벨링이 끝나야 알 수 있다. 끝난 뒤 분포를 보고 모양이 크게 어긋나면 개정문을 추가하거나 교체한다.
- 정답이 19개 이상인 개정(번호 이동, 정의 변경)은 많아야 몇 건만 둔다.

## 집계 규칙 (미리 정함)
- 기본 지표: 문항 평균 재현율(정답이 있는 문항만), 상위 k = 10, 20, 50.
- 합산(정답 쌍 전체) 지표를 같이 낸다면 한 문항의 정답 쌍을 최대 15쌍으로 자른 값으로 낸다. 앞서 D07 한 건이 정답의 43%(31/72), I04가 63%(24/38)를 차지했다.
- 정답 0개 문항: 재현율을 계산하지 않고 "낸 후보 수"로 따로 본다.
- 결과는 4개 도메인 문항과 그 밖의 문항을 나눠서도 보고한다.

## 제작 절차와 역할 분리 (독립성이 핵심)
1. A: 뽑힌 조 본문만 읽고 개정문을 쓴다. 영향받는 조는 찾지 않는다. 후보 찾기 결과나 이전 실험 결과를 보지 않는다.
2. B1, B2: 서로의 산출물을 보지 않는 별도 서브에이전트가 규정 전문만 읽고 "함께 확인해야 하는 조"를 찾는다. 근거 문장은 원문에서 그대로 복사한다. `validate.py`를 통과해야 한다.
3. C: 두 라벨러가 한쪽만 낸 항목을 원문 기준으로 판정하고 `결정이유`를 남긴다. 합집합과 일치 비율(이전 30건은 72%)을 기록한다.
4. 사람 검토 전의 AI 초안임을 문서에 적는다.

## 작성자 편향 방지
- 개정문을 쓰는 세션/에이전트는 후보 찾기 코드, 평가 결과, 그래프 구조를 보지 않는다.
- 개정문은 가능하면 서로 다른 서브에이전트 여러 개가 나눠 쓴다(한 에이전트의 문체 쏠림 방지).
