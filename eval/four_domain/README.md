# 휴직 원본 보존 · 인사/보수/휴가 확장 평가

**현재 문항 구성은 [한 문항·한 곳 변경 60문항](single_change/README.md)이다.** 모든 문항이 수정 연산 1개이며, 범주를 섞은 종합 문항은 사용하지 않는다. 새 구성의 모델 평가는 실행 전이다. 아래 120문항 구성·점수는 보존된 이전 실험 기록이다.

사용자가 만든 휴직 온톨로지와 원본 수정 이력을 보존하고, 인사·보수·휴가를 원문 기반 AI 검토로 확장한 **실험 패키지**다. 애플리케이션의 기본 검색 경로를 변경하지 않는다. PR #11의 `regcheck` 그래프·인용 코드를 사용하므로 `feature/impact-candidates`를 기준으로 한다.

## 이전 120문항 실험의 전체 결과

| 방식 | 기존 지시 · 전체 120문항 | 전후 비교 수정 지시 · 전체 120문항 |
|---|---:|---:|
| RAG | 77/120 | 83/120 · 69.2% |
| PR #11 그래프 + RAG | 80/120 · 검토 대기 1문항 | 78/120 · 검토 대기 3문항 |
| 복원·재검토 도메인 그래프 + RAG | 88/120 | 93/120 · 77.5% |

수정 지시는 개정 전후의 문제 유무를 각각 확인하도록 명확히 했으며, 세 방식에 똑같이 적용했다. DB·검색 후보·모델·정답·채점기는 고정했다. 도메인 그래프 방식은 6문항 개선·1문항 퇴행으로 순증 5문항이다. 같은 수정 지시의 RAG 대비 차이는 **8.33%p**이며 10%p 향상을 달성했다고 해석하지 않는다.

기존 실패 사례를 보고 수정한 같은 개발 집합의 단회 재평가다. 미사용 문항에서의 일반화 성능은 확인하지 않았다. [새 결과와 재현 기록](results/state-compare-v2/README.md), [실험 계획·실행 방법](STATE_COMPARE_EXPERIMENT.md)을 참고한다. 기존 결과는 `results/reviewed/`에 그대로 보존했다.

문항 성공은 그 문항의 알려진 새 문제·해소 문제를 모두 맞혔을 때 인정한다. 정답은 사람 검수 전 AI 초안이다. 정답 목록 밖 발견은 자동 오탐 처리하지 않고 검토 대기로 둔다.

## 실제 문제 구성

문제 유형은 개정 전후 **검사 대상 관계**의 변화로 나눈다. 전후 상태는 원문과 overlay에 들어 있다.

| 유형 | 개정 전 → 개정 후 | 문항 수 |
|---|---|---:|
| 새 문제 발생 | 없던 불일치/깨진 인용이 생김 | 40 |
| 정상 변경 | 전후 모두 해당 문제가 없음 | 40 |
| 기존 문제 해소 | 있던 불일치/깨진 인용이 없어짐 | 40 |

- 개별 60문항: 규칙 변경 **한 묶음**을 검사한다. 비교 상대나 정답은 여러 조항일 수 있다.
- 종합 60문항: 인사·보수·휴가·휴직에서 서로 다른 변경 **네 묶음**을 한 개정안에 넣는다. 맞춰 고친 부분과 일부만 고친 부분을 섞었다. 네 분야의 단일 인과 사슬을 뜻하지 않는다.
- 각 집합에 위 세 유형이 20개씩 있다. ‘범주별’은 개별 60개를 주된 주제에 따라 인사/보수/휴가/휴직 15개씩 나눈 구분이며 추가 문항이 아니다.
- 20개 관계(주 범주별 5개)를 상태·조합으로 바꾼 120문항이다. 같은 관계를 개발/평가에 무작위로 나누면 안 된다. 변경과 무관하게 유지되는 기존 문제는 보고 대상이 아니다.

### 예시: 새 문제 발생 (Q015 중 보수 부분)

인사규정의 업무 외 질병 휴직 기본급만 **1/2 → 2/3**으로 바꾸고 급여규정의 **1/2**는 둔다. 기대 정답은 새 지급률 불일치다.

### 예시: 정상 변경 (Q022)

복무규정과 근로계약서 두 서식의 연차 기본일수를 **전부 15일 → 16일**로 바꾼다. 기대 정답은 이번 변경의 새 문제/해소 문제 없음이다.

### 예시: 기존 문제 해소 (Q029)

가상 시작 상태의 가족돌봄휴직 최소기간이 **인사규정 15일 / 취업규칙 30일**일 때, 취업규칙도 **15일**로 고친다. 기대 정답은 기존 불일치 해소다.

질문에서는 비교 상대·오류 개수·정답 유형을 따로 알려주지 않는다. 위의 정답은 설명용이다. 실제 질문은 [questions.md](questions.md), 전후 근거는 [review.md](review.md), 네 범주 일괄 개정 예시는 [팀 공유 문서](TEAM_HANDOFF.md)에 있다. 외부 법령 적법성은 이 내부 정합성 시험의 범위 밖이다.

## DB와 원문

- `hyujik-user-original.db`: 사용자 원본 스냅샷. 6개 개념, 연결 151개, 속성 설명 38개, 대표근거 7개, 상위항 38개, 수정이력 46개를 보존한다.
- `domain_ontology.reviewed.db`: 원본 모든 테이블의 기존 행을 그대로 보존하고 새 연결 1,846개를 추가한 통합본. 사람 확정판이 아니다. 의미 검토 대기 연결은 기본 탐색에서 제외한다.
- `schema.sql`, `schema-data.jsonl`, `reviewed-nonleave-edges.jsonl`: 바이너리 DB의 구조와 실제 개념/연결을 텍스트로 검토할 수 있다.
- `base_corpus.jsonl`, `sources/text/`: 전체 90개 문서의 고정 검색 단위 3,244개와 추출 원문. 실제 개정 대상은 그중 9개 문서다.
- `cases/`: 각 문제의 가상 시작 상태 및 적용 후 상태. 원본 HWP를 수정하지 않는다.

검증 내역과 알려진 파싱/범위 문제는 [GRAPH_VALIDATION.md](GRAPH_VALIDATION.md)를 참고한다. 원문 문구 일치는 모든 의미 판단의 정확성을 보증하지 않는다.

## API 없이 검증/결과 재채점

저장소 루트에서 Python 3.12 이상으로 실행한다. 가벼운 검증에는 프로젝트 전체 ML 의존성이 필요하지 않다.

```powershell
python eval/four_domain/validate_dataset.py
uv run --no-project --with numpy --with pytest python -m pytest eval/four_domain/test_reviewed_graph.py eval/four_domain/test_pipeline.py -q
python eval/four_domain/replay_results.py
```

재채점은 게시된 응답과 압축된 검색 문맥을 `runs/replay/`에 풀어 동일 채점기로 집계한다. API 키·네트워크 호출이 없다. 전체 결과 Markdown만 표시하고 원시 JSON 기록은 재검토용으로 보존한다. `results/reviewed/`는 기존 실행의 스냅샷이며 이 패키징으로 API를 다시 실행했다고 주장하지 않는다.

## 모델 평가를 새로 실행

```powershell
Copy-Item eval/four_domain/.env.example eval/four_domain/.env
# .env에 본인 API 설정 입력
uv run --no-project --with numpy python eval/four_domain/run_evaluation.py --phase all
```

`--env`, `--cache`, `--results`, `--cases`, `--workers`를 지원한다. 실제 비밀값은 커밋하지 않는다. 기본 출력은 `runs/luna-reviewed/`, API 캐시는 `.cache/`이며 둘 다 Git에서 제외한다. 게시된 `results/`는 덮어쓰지 않는다. 120문항 × 세 방식의 모델 평가이므로 실행 전 설정된 API/모델을 확인한다.

평가에는 동일 문맥·프롬프트·모델 설정인 요청의 캐시 재사용이 허용된다. 기록된 실행의 RAG/PR 대조군 240개는 이전 실행과 완전히 같은지 확인했다. 사용자 휴직 원본을 사용하지 않았던 이전 자동 생성 그래프의 결과와 혼동하지 않는다. 이 평가 점수는 그래프 자체 정확도가 아니라 검색과 Luna 판정을 합친 파이프라인 점수다.

전후 비교 수정 지시를 새로 실행하려면 `run_state_compare.py --env YOUR_LOCAL_ENV`를 사용한다. 새 결과를 API 없이 재채점하려면 `python eval/four_domain/replay_results.py --variant state-compare-v2`를 실행한다.
