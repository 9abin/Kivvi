# 도메인 그래프 재검증 결과

**이전 확장 구현은 사용자 휴직 원본을 보존하지 않았습니다.** 원본 파일은 변경되지 않았고, 별도로 만든 확장 DB와 실제 평가 코드에서 내용이 재생성됐습니다. 이번에는 원본 DB에서 출발해 다른 범주를 추가했습니다.

## 휴직 원본 보존

| 항목 | 사용자 원본 | 이전 확장본 | 이번 복원본의 원본 행 |
|---|---:|---:|---:|
| 휴직 연결 | 151 | 자동 생성 93 | **151/151 그대로** |
| 원본 개념 속성값 | 38 | 원본 설명값 대신 자동 필드 사용 | **38/38 그대로** |
| 대표 근거 | 7 | 0 | **7/7 그대로** |
| 상위 항 연결 | 38 | 0 | **38/38 그대로** |
| 수정 이력 | 46 | 0 | **46/46 그대로** |

원본 연결 67개가 이전 자동 그래프에서 빠졌고, 그중 **64개는 휴직 공통 노드의 연결**이었습니다. 나머지는 명령휴직 2개, 청원휴직 1개입니다. 원본의 모든 테이블을 행 단위로 비교해 기존 값이 하나도 바뀌지 않았음을 확인했습니다. 원본 자체의 모든 의미를 새로 사람 검수했다는 뜻은 아닙니다.

## 인사·보수·휴가 재검토

전체 90개 문서·3,244개 단위를 스캔하고, 기존 비휴직 연결 전부와 도메인 문서 전체·키워드 누락 후보를 포함한 72개 문서의 2,998개 원문 단위를 재검토했습니다. Luna로 144묶음의 독립 원문 검토와 공통 규칙 12묶음(150단위)의 추가 검토를 수행했습니다. 기존 평가 정답·모델 판정은 제공하지 않았습니다.

| 범주 | 원문 재검토 후 연결 수 |
|---|---:|
| 인사 | 1,190 |
| 보수 | 469 |
| 휴가 | 187 |

기존 2,105개 연결 중 656개는 같은 항·호·개념으로 재채택되지 않았고, 1337개는 관계/속성 표현이 달라졌으며, 112개는 문자 기준 동일했습니다. 새 연결 식별자는 397개입니다. **이 수치는 오류율이 아닙니다.** 속성 명칭 변경, 개념 분리와 공통 노드 보완도 포함합니다.

단순 별칭 대신 개념별 관계·속성·값·대상·조건·예외와 실제 근거 구절을 기록했습니다. 보상휴가/포상휴가, 특별휴가/장기재직휴가, 기본급/기본연봉도 구별했습니다. 속성값은 출처와 조건을 가진 목록으로 보존하고 모든 문서에 하나의 값이 적용된다고 합치지 않았습니다.

## 실제 확인한 문제

- **24024:12-2-0-0 / 인사위원회**: 의결 정족수 3분의2는 급여 지급률이 아니다.
  - 이전: 근거 / 인용, 절차, 지급률
  - 재검토: 근거 / 절차, 제외
- **23411:11-2-0-0 / 인사위원회**: 등급 특별조정 1회/7회는 휴가·보수의 분할 횟수가 아니다.
  - 이전: 근거 / 분할, 절차, 평가
  - 재검토: 근거 / 제한
- **10770:3의1-1-0-0 / 채용**: 정의 대상은 4촌 이내 친족이며, 이 문장은 채용자 확인 절차를 정한다.
  - 이전: 정의 / 기한, 대상, 인용
  - 재검토: 근거 / 기한, 절차
- **23438:3-0-10-0 / 면직**: 소송대리인 선임·해임 심의기구의 정의를 직원 면직 정의로 연결하지 않는다.
  - 이전: 정의 / 절차
  - 재검토: 해당 개념 연결을 재채택하지 않음
- **24047:13-0-0-0 / 보수**: 계속 집무기간의 일할 계산은 금액 산정 방식이며 분할 사용이 아니다.
  - 이전: 이전 공통 노드 미생성
  - 재검토: 근거 / 금액

추가로 일할 계산과 퇴직금 중간정산을 분할 속성에서 분리했고, 임금피크제 대상자·기준급여의 누락과 보수 공통 정의를 원문에서 직접 대조해 보완했습니다. 이 직접 수정도 AI 검토이며 사용자/사람 검수로 표시하지 않았습니다.

## 검증과 남은 항목

- 원본 파일 SHA-256 및 모든 기존 테이블 행 보존 확인.
- 추가 연결과 속성 근거의 인용문을 원문 본문 또는 실제 제목과 대조. 제목 근거는 위치를 따로 기록.
- SQL 무결성·참조 무결성 통과. 실제 DB를 읽는 탐색기로 원본 151개와 휴직 공통 64개를 읽는지 확인.
- 실제 오연결 회귀 검증을 포함한 **9개 테스트 통과**.

**남은 검토 사항은 명시적으로 분리했습니다.** 임원 퇴직금 규정의 ‘징계 해직’을 직원 면직 개념과 같게 볼 수 있는지 확정하지 않은 연결 1개는 needs_review이며 기본 탐색에서 제외합니다. 부칙의 참조 대상 문맥 1단위와 원문 파싱 잘림 1단위도 별도 기록했습니다. 삭제된 원문 4개·시행일 기록 25개·현재 고정 분류 범위 밖/서문 18개는 새 활성 연결을 억지로 만들지 않았습니다.

파싱 사례: `24024:부칙40:2-0-0-0`는 문장이 중간에서 끝납니다. 실제 원문의 다음 행에는 “"[별표3] 경력환산기준 에 대한 개정사항은 2020년 1월 1일 이후 입사자부터 적용한다."”가 이어집니다. 이 문제는 source-parsing-issue.json과 source-evidence/24024.txt에 남겼습니다. 기존 120문항의 원문·정답을 조용히 바꾸지 않았습니다.

**나머지 세 범주는 원문 대조 AI 검토본이며, 사람이 정리한 휴직과 동급의 완전성·정확도를 인증한 것은 아닙니다.** 원문 일치 검사는 인용 정확성을 확인할 뿐 의미 판단을 모두 증명하지 않습니다. 현재 하위 개념 35개의 범위 밖에 있는 임원 임명/임기·정원·연수 등은 자동으로 새로운 개념에 끼워 넣지 않았습니다.

## 파일과 실행

- `domain_ontology.reviewed.db`: 사용자 원본 전체를 보존한 별도 복원·재검토 DB.
- `hyujik-user-original.db`: 사용자 원본 스냅샷. 다운로드 원본은 수정하지 않음.
- `reviewed-nonleave-edges.jsonl`: 인사·보수·휴가 연결 및 조건·원문.
- `confirmed-examples.json`, `direct-source-corrections.jsonl`: 실제 오류 사례와 직접 대조 수정.
- `confirmed-examples.json`, `direct-source-corrections.jsonl`: 원문 대조 오류와 수정 내역.
- `uncertainty-resolution.jsonl`, `source-parsing-issue.json`: 제외 사유와 확인 필요 내용.
- 연결별 검토 결과는 `reviewed-nonleave-edges.jsonl`과 `direct-source-corrections.jsonl`에 보존. 원래 대량 모델 검토 로그는 이 PR 패키지에 포함하지 않음.
- 대표근거는 실제 개념명 제목/명시적 정의인 경우를 채택하며 원본 대표근거 7개는 그대로 유지.
- `validated_graph.py`: DB를 직접 읽는 탐색기. 이전처럼 원본 휴직 간선을 정규식으로 다시 만들지 않음. 개념별 속성과 원본 상위 항 연결을 사용하며 불확실/과거 기록은 새 활성 근거에서 제외.
- `run_evaluation.py`: 이 그래프를 기존 120문항 실행기에 연결하는 **별도 진입점**. 기존 결과를 덮어쓰지 않고 DB/실행기 해시를 기록.

```powershell
python -m pytest test_reviewed_graph.py -q
# 명시적으로 다시 평가할 때만 실행:
python run_evaluation.py --phase all
```
