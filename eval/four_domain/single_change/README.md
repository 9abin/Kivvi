# 한 문항·한 곳 변경 평가 — 현재 구성

각 문항에서 **한 조항·항호·서식의 한 곳만 수정**한다. 다른 주제의 변경을 함께 넣지 않는다. 변경 한 곳이 여러 조항에 영향을 주면 그 연결 영향은 모두 정답에 포함한다.

| 범주 | 새 문제 발생 | 문제 없는 변경 | 기존 문제 해소 | 합계 |
|---|---:|---:|---:|---:|
| 인사 | 5 | 5 | 5 | 15 |
| 보수 | 5 | 5 | 5 | 15 |
| 휴가 | 5 | 5 | 5 | 15 |
| 휴직 | 5 | 5 | 5 | 15 |
| 전체 | 20 | 20 | 20 | 60 |

기존에 확인한 20개 관계에서 세 상태를 만든 60문항이다. 서로 독립적인 관계 60개를 뜻하지 않는다. 검색 대상은 그대로 전체 90개 문서다. 정답은 원문에 근거한 AI 초안이며 사람 검수 전이다.

예를 들어 질병휴직 기본급의 새 문제 문항은 인사규정의 1/2만 2/3으로 바꾸고 급여규정은 수정하지 않는다. 해소 문항은 가상 시작 상태의 인사규정 2/3·급여규정 1/2에서 인사규정 한 곳을 1/2로 되돌린다. 시작 상태 준비는 입력 원문에 이미 적용되어 있고, 모델에게 요청하는 개정은 정확히 한 번이다.

조문 이동도 한 곳의 번호만 바꾼다. 새 문제에서는 옛 번호를 인용하는 조항들을 찾고, 해소에서는 가상 시작 상태에서 옮겨진 조문을 옛 번호로 되돌려 기존 인용을 복구한다. 여러 인용문을 동시에 고치지 않는다.

**문제 없는 변경 20개는 의미를 유지하는 띄어쓰기 수정 대조군이다.** 한 곳만 바꾸면서 관련 규정의 값이 일치하는 상태를 유지하기 위해 이렇게 제한했다. 실질적인 정책 변경인데도 문제가 생기지 않는 사례 전반을 평가하지는 않는다. 기존 문제를 그대로 유지하는 유형은 넣지 않았다.

- [실제 모델 질문](questions.md): 정답·범주·유형·비교 상대를 알려주지 않는다.
- [정답과 전후 원문](review.md): 가상 시작 상태와 기대 변화, 양쪽 조항 근거를 담는다.
- `inputs.jsonl`: 모든 문항의 `amendment_ops` 길이는 1이다.
- `validation-summary.json`: 실제로 달라진 논리 조항도 각 1개임을 검증한다.

## 전체 결과

| 방식 | 전체 60문항 결과 |
|---|---:|
| RAG | 46/60 · 76.7% |
| PR 그래프 + RAG | 52/60 · 86.7% |
| 복원·재검토 도메인 그래프 + RAG | 53/60 · 88.3% |

세 방식 합계 180개 응답을 완료했다. [실제 응답·채점·재현 기록](results/luna/README.md)을 참고한다. 기존 120문항의 88/120·93/120 등 점수는 다른 구성의 성능이며, 상위 폴더에 보존한다.

저장소 루트에서 실행한다.

```powershell
python eval/four_domain/single_change/validate_dataset.py
uv run --no-project --with numpy python eval/four_domain/single_change/run_evaluation.py --env YOUR_LOCAL_ENV
```

같은 Luna·후보 10개·전후 상태 비교 지시로 RAG, PR 그래프+RAG, 복원 도메인 그래프+RAG를 비교한다. 출력은 무시되는 `single_change/runs/`에 저장하며, 원본 DB와 기존 평가 스냅샷은 변경하지 않는다.

API 없는 결과 재채점: `python eval/four_domain/single_change/replay_results.py`
