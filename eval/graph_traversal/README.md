## 확인한 사실

1. **PR12 정답 짝은 전부 가까이 있다.** 시작 조에서 정답 짝까지: 깨진 인용 104쌍은 모두 `CITES` 1홉(52쌍은 시작 조를 인용하는 쪽, 52쌍은 시작 조가 인용하는 쪽), 값 불일치 112쌍은 제목 언급(`MENTIONS_TITLE`) 1홉 78쌍, 용어 거친 2홉 18쌍, `CITES` 1홉 16쌍. 그래서 이 평가에서 후보 찾기는 어렵지 않고, **방향 하나만 보는 규칙표가 한쪽 방향 정답을 놓친다**(값 변경 표에는 `CITES`로 나가는 방향과 `MENTIONS_TITLE`로 나가는 방향이 없다).
2. **PageRank의 이득은 대부분 인용(`CITES`) 선에서 나온다.** 관계를 하나씩 빼 보면 `CITES`를 빼면 상위 10 적중이 143건에서 92건으로 떨어지고, 다른 관계는 하나씩 빼도 -4~+1건이다.
3. **관계 가중치를 학습해도 이득이 작다.** 관계 묶음 20개를 5겹으로 나눠 교차검증: 상위 10 적중 학습한 가중치 82.5%, 팀 가중치 80.8%, 모든 관계 같은 가중치 70.6%. 팀 가중치가 이미 쓸 만하다(+1.7%p는 표본 177에서 잡음 수준).
4. **개정 종류를 알아야 하는 규칙표는 종류를 틀리면 손해다.** 모든 종류의 규칙표 후보를 합치면(B) 두 평가셋 평균 +10%p(@10).
5. **정의 변경은 규칙표가 낫다.** 팀 문항 정의 변경 7건(정답 47)에서 상위 20 적중: 규칙표 94%, PageRank 74%. PageRank는 같은 용어를 쓰는 많은 조에 점수를 흩뿌린다. 그래서 규칙 후보를 앞에 두는 F가 안전하다.
6. **법령 변경은 모든 방법이 약하다.** 위임·법령 변경 5건(정답 18)의 상위 20 적중이 11~22%. PageRank 상위 20에서 놓친 38건 중 14건이 이 종류다. 법령 조 노드가 규정이 인용한 조에서만 시작되기 때문이다.
7. **RAG를 더해도 이 평가에서는 이득이 없다.** 저장된 PR12의 RAG 순위로 합쳤을 때: RAG만 상위 10 55%, PageRank만 81%, RAG 2자리 + PageRank 80%, RAG와 PageRank를 순위 합치기(RRF)하면 73%. PR12 정답이 인용·제목·용어로 이어진 것이라 그래프만으로 거의 다 잡히는 설계의 영향이다. 팀 문항에서는 RAG 순위가 저장되어 있지 않아 시험하지 못했다.

## 논문에서 가져온 탐색 방식 비교 (2026-11-09 추가, `traverse6.py`, 결과 `out9_literature.txt`)

앞의 방법들은 일반적인 탐색 방법을 직접 구현한 것이라 논문 조사가 빠져 있었다. 그래프 RAG와 규정 그래프 논문에서 탐색 방식을 찾아, 질의 때 LLM을 쓰지 않는 우리 설정에 맞춰 단순화해서 구현했다(논문의 전체 방법이 아니라 핵심 아이디어만 옮긴 것이다). 같은 두 평가셋, 같은 지표다.

| 가져온 아이디어 | 출처 | 우리 구현 | 두 평가셋 평균 @10 / @20 |
|---|---|---|---|
| 허브 감쇠 (이웃이 많은 노드에서 퍼지는 양을 줄임, 노드 특이도) | [HippoRAG](https://aws.amazon.com/blogs/machine-learning/hipporag-neurobiologically-inspired-rag-using-amazon-bedrock-amazon-neptune-and-personalized-pagerank/), [BeamRAG](https://arxiv.org/pdf/2504.18070)류 | PageRank 전이에서 이웃 수의 거듭제곱으로 나눔 (0.25, 0.5, 1.0) | 66~67% / 79~81% (기준 C 66% / 78%) |
| 퍼짐 활성화 (홉 감쇠, 발화 임계값) | [Query-Aware Spreading Activation](https://arxiv.org/pdf/2606.30133) | 3홉, 감쇠 0.5~0.7, 허브 0.5, 임계 0~0.05 | 66~67% / 78~81%. 임계 0.05는 57% / 64%로 무너짐 |
| 인용 폐쇄 | [Citation-Closure Retrieval](https://arxiv.org/pdf/2605.29742) | CITES 관계만 2~3홉 | 36% / 37% (단독). 규칙 먼저 + 폐쇄 + PageRank는 66% / 80%로 기준 F와 같음 |
| 단계적 확대 (1홉, K홉, PageRank 순) | [A2RAG](https://arxiv.org/html/2601.21162v2) | 1홉 후보가 5개 또는 10개 미만이면 2홉을 더하고 PageRank로 채움 | 65% / 79~80% (기준 F와 같음) |

- **결론: 논문 방식은 기준선(C, F)을 의미 있게 넘지 못했다.** 최고값이 평균 @20에서 81%로 기준 80%와 1%p 차이다. 평가셋 크기를 보면 잡음 범위다.
- 허브 감쇠(1.0)는 팀 문항에서 PageRank를 올렸지만(@20 64% → 72%, @30 68% → 76%) PR12에서는 약간 내렸다(@10 81% → 79%, @20 92% → 91%). 평균으로는 @20 78% → 81%이고, 규칙 먼저 + PageRank 채움(F)의 팀 문항 @20 72%와 같다. 한 평가셋에서만 이득이라 확정할 근거는 부족하다.
- 인용 폐쇄만으로는 PR12 정답의 60%, 팀 문항 정답의 13%만 찾는다. 팀 문항은 정의, 법령 변경이 많아 인용이 아닌 용어, 제목, 법령 관계로 이어진 정답이 많기 때문으로 보이지만 확인한 것은 아니다.
- 단계적 확대는 규칙 먼저 + PageRank 채움(F)과 같은 결과를 내서 새로운 이득이 없다.
- 못 한 것: 질의에 따라 간선 가중치를 바꾸는 쿼리 인식 방식(개정 종류별 가중치 D가 가장 가까움), LLM이 탐색을 조종하는 방식(A2RAG, Think-on-Graph, RLM-on-KG)은 질의 때 LLM을 쓰지 않는 현재 단계 범위 밖이라 돌리지 않았다. 논문 전체를 읽고 재현한 것이 아니라 검색 요약과 초록 수준에서 아이디어를 가져왔다.

### 연결된 부분 그래프 고르기 (PCST, G-Retriever식) (`traverse7.py`, 결과 `out10_pcst.txt`)

노드마다 상금(개정된 조에서의 PageRank), 선마다 비용(1 / 관계 정밀도)을 주고, 상금이 큰 노드를 최소 비용으로 잇는 연결 부분 트리를 고른다. 논문 구현(`pcst_fast`)이 아니라 개정된 조를 뿌리로 한 최단경로 트리 위의 동적계획법으로 근사했고, 후보 집합을 순위로 바꾸려고 비용 배율을 키워 가며 끝까지 남는 정도로 정렬했다. 기준선과 같은 두 평가셋이다.

| 방법 | 두 평가셋 평균 @5 / @10 / @20 | 팀 @20 |
|---|---|---|
| C PageRank (기준선) | 52% / 66% / 78% | 64% |
| F 규칙 먼저 + PageRank (기준선) | 47% / 65% / 80% | 72% |
| P1 PCST (상금 = PageRank) | 49% / 65% / 75% | 63% |
| P2 PCST (상금 = 허브 감쇠 PageRank) | 49% / 67% / 80% | 72% |
| P3 PCST (선 비용에 허브 벌점) | 49% / 65% / 77% | 64% |
| P4 규칙 먼저 + PCST 채움 | 47% / 64% / 79% | 72% |

- **재현율 이득은 없다.** 가장 좋은 P2가 기준선 F와 같은 80% (@20)다.
- **부산물 이득은 확인했다.** 선택된 후보마다 개정된 조까지의 경로(부모 사슬)가 나온다. 예: `23970:26 <- 23970:부칙23:1 <- 23970:30`. 사람이 "왜 후보인지"를 바로 볼 수 있다. 다른 탐색 방법도 경로를 낼 수는 있지만 PCST는 연결된 한 덩어리로 묶어 낸다는 점이 다르다.
- 한계: 상금이 PageRank라 질의와의 의미 관련도를 쓰지 않았다. 판단 모델 점수를 상금으로 쓰는 변형은 돌리지 않았다. 근사 구현이라 논문 구현과 결과가 다를 수 있다.
