# 시험 100 (test) 결과

작성 261112. 역할: **시험셋**. 가빈 `share_test100`(T001~T100, val · bm과 겹치지 않음, 제작 기록은 [`README_제작.md`](README_제작.md)). 개발 100에서 정한 설정을 고정하고 한 번 쟀다. **보고 숫자는 이 세트다.**
주의: 놓친 정답을 들여다봤으므로(아래), 이후 이 세트를 보고 고치면 개발셋이 된다. 다음 독립 평가는 새 세트(또는 실제 개정 이력 · 현업 검수)로 한다.
관련: [리포트 94](../../../docs/reports/261111-2100-94-eval-metrics.md), [개발 100 결과](../bm/RESULTS.md)

## 설정
개발 100과 같다(커밋 `0905d80`). 판정 모델 solar-pro4.
정답: `gold.jsonl` 56개 중 id 50(별지 서식 · 별표 6개 대응 없음), 확신 높음 15 · 중간 35. 정답 있는 문항 34, 정답 0 문항 66. 확신 낮음 48개(46%)는 `gold_low.jsonl`, 평가에서 뺌.
**아래 재현율은 id가 있는 정답 50개 기준이다.** id 없는 6개(시스템 단위로 표현하지 못한 별지 · 별표)를 놓친 것으로 치면 최종 재현율은 43/56 = **0.768**이다. 둘을 함께 보고한다(261112 Codex 교차검증, [리포트 96](../../../docs/reports/261112-2000-96-codex-cross-review.md)).

## 찾기
| 지표 | 시험 100 (95% 구간) | 개발 100 |
|---|---|---|
| 검색 재현율: 검색 후보 전부 (문항당) | 0.940 (97) | 0.989 (88) |
| 검색 재현율: 규칙 후보 전부 + luna 입력 (문항당) | 0.940 (60) | 0.978 (58) |
| **최종 재현율** (문항당 보임) | **0.860** (5.4) | 0.934 (5.3) |
| └ 확신 높음 라벨 | 15/15 = 1.000 | 34/34 = 1.000 |
| └ 확신 중간 라벨 | 28/35 = 0.800 | 51/57 = 0.895 |
| (평가 제외) 확신 낮음 | 43/48 | 25/31 |
| Recall@5 | 0.740 (0.627~0.844) | 0.780 |
| Recall@10 | 0.840 (0.744~0.927) | 0.912 |
| Hit@5 | 0.824 (0.684~0.943) | 0.964 |
| MRR | 0.589 (0.462~0.719) | 0.734 |
| MAP / nDCG@10 | 0.522 / 0.619 | 0.689 / 0.769 |

- 개발 대비 -7%p: 차이 구간(약 -0.18~+0.04)이 0을 포함, 정답 수로 3~4개. 개발셋에 맞춘 만큼의 하락으로 본다.
- 확신별: 「확신 높음」 라벨 정답은 15/15를 찾았다. 15개뿐이라 표본이 작고, 확신은 라벨러가 관계를 얼마나 확신했는지이지 업무상 「반드시 확인할 조」인지가 아니다(필수성은 현업 검수 항목). 주 지표는 높음 + 중간 0.860. 목록을 다 보여 주므로 MRR은 참고.
- 현업 판정에 따른 범위: 놓친 중간 · 낮음 12개(중간 7, 낮음 5)가 모두 「없음」이면 1.000, 낮음까지 모두 정답이면 0.878 (id 있는 정답 기준).
- 화면을 늘리면(전부 보인 것으로 셈): 판단 모델이 숨긴 규칙 후보까지 전부 0.920(10.7개), + luna 입력 중 안 고른 상위 10 0.940(20.6개), 검색 후보 전부 0.940(97개) → 상한은 검색. (261112 정정: 이전 0.880 · 0.900은 숨긴 규칙 후보 중 RAG · 그래프도 찾은 것을 빼고 센 값)
- 문항당 10개를 꽉 채우면(모자란 칸을 숨긴 규칙 후보 판단 점수 순 → luna 입력 순으로): Recall@10 0.840 → 0.880, 문항당 4.5 → 9.9개, 라벨 정밀도 0.093 → 0.044. 채우는 순서는 임의로 정한 것이라 쓰려면 개발셋에서 정한다(261112).
- 종류별 상위 10: 값 변경 8/8, 고립 수정 6/6, 정의 변경 1/1, 표현 수정 1/1, 번호 이동 4/5, 삭제 11/13, **위임 · 법령 변경 11/16**.

### 판단 모델 문턱 (261112, [리포트 95](../../../docs/reports/261112-1800-95-decide-threshold.md))
- 판단 모델이 걸러 낸 시험 정답 3개(T030 · T073 · T076). 판단 모델 자체는 개발 · 시험 모두 AUC 0.87 · 0.88로 같고, 0.7 아래 정답 비율도 11 · 12%로 같다. 개발은 그 정답들이 USES_TERM 예외로 살았고 시험은 다른 유형이라 빠졌다.
- 문턱만 바꾸면(전부 보인 것으로 셈): 0.7 → 0.860, 0.3 → 0.900, 거르지 않음 → 0.920. 이 숫자들은 시험을 보고 낸 것이라 독립 수치가 아니다. 설정은 0.7을 유지했다(10개 화면 기준 개발 최적, 차이가 구간 안).

## 정밀도 (solar-pro4 판정 보완)
| 지표 | ① 라벨만 | ② 라벨 + Solar 「예」 | 개발 ① / ② |
|---|---|---|---|
| 목록 전체 | 0.080 | 0.595 | 0.161 / 0.592 |
| Precision@5 | 0.097 | 0.623 | 0.251 / 0.641 |
| Context Precision 식 | 0.223 | 0.727 | 0.430 / 0.750 |

- Precision@5 정의: 빈 목록 문항은 빼고, 분모는 min(5, 목록 길이). 분모를 5로 고정하고 100문항 모두 넣으면 ① 0.074 · ② 0.414 (개발 0.142 · 0.416).
- Solar 신뢰도: 라벨 정답에 「예」 36/43(0.837), 라벨에 없는 후보에 「예」 277/495(0.560). ②는 참고용 추정이고 실제 정밀도의 상한도 하한도 아니다(Solar가 라벨 정답 7개에 「아니오」, Solar 「아니오」 중에도 정답이 있을 수 있음). 사람 검수는 「예」 · 「아니오」 양쪽에서 뽑아야 한다.
- ①이 반으로 준 것은 정답 0 문항이 66개(개발 45)라서. 빈 목록 13, 정답 0 문항당 3.6개.

### 규칙 답변 근거 보강 후 (261112)
원인: 원문 인용을 인용 · 정의 용어 · 새 문구 경로에서만 뽑아, 규칙 답변 대부분이 확인 대상 조문을 못 보고 경로 이름만 옮겨 썼다. 고친 것: 제목 언급 · 지워진 말 · 규정 이름 경로도 인용, 고쳐지는 조 쪽 경로(`_out`)는 그쪽 문장, 인용이 없으면 조문 앞부분 400자, 「경로 이름을 문장으로 옮기지 않는다」. 개발 100에서 고치고 확인한 뒤 시험 100은 한 번만 쟀다(검색 · luna 결과는 그대로, 규칙 답변만 다시 씀).

## 결론
- 일반화: 확신 높음 라벨 정답 15/15, 높음 + 중간 86%(구간 0.74~0.93, id 없는 정답까지 넣으면 0.768)를 문항당 5개 남짓으로 찾는다. 답변 품질 · 정밀도 ②는 개발과 비슷하다(둘 다 판정 방식의 한계가 있음, 위 주의). 정답 있는 문항이 34개라 수준은 넓은 범위로만 말할 수 있다.
- 한계: 검색 상한 0.94는 그래프 연결 유형이 정한다(연결 유형 추가로 개선 가능성). 정답은 AI 초안(확신 높음 15개뿐). 답변 충실도는 다시 판정 필요.
- 다음: 놓친 12개 현업 판정, 답변 충실도 다시 판정, 연결 유형 2개 추가, 큰 평가셋(실제 개정 이력)으로 새로 재기. 이 세트는 놓친 정답을 들여다봤으므로 이제 개발용이다.
