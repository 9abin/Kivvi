# 영향 후보 평가셋 v2 (val 30 · 최종 100)

작성 261111 박형건. 관련: [리포트 93](../../docs/reports/261111-1500-93-candidate-state-pipeline.md), [TODO](../../docs/todo/candidate-state-pipeline.md)

개정 하나마다 「담당자가 함께 살펴봐야 하는 조」를 다시 라벨링한 세트다. 라벨러는 AI(B1 · B2 독립 → C 불일치 결정)이고, 지시서는 [`../relabel_kit/지시서.md`](../relabel_kit/지시서.md)(v2.1). **AI 초안이다.** 업무 판단은 현업 검수로 확정한다.

## 쓰는 법
- `val/`: 값 · 프롬프트를 정할 때만 쓴다.
- `bm/`: 최종 확인용. 정한 값 그대로 한 번만 잰다. 이걸 보고 고치지 않는다.

## 파일 (폴더마다)
| 파일 | 내용 |
|---|---|
| `changes.jsonl` | 개정 (이전 세트와 같음). `수정.규정` · `수정.조` · `수정.개정문` |
| `gold.jsonl` | **평가 정답.** `labels_final`에서 확신 높음 · 중간만 남김 (val 42 · bm 94) |
| `gold_low.jsonl` | 확신 낮음 (val 25 · bm 31). 평가에서 뺀다. 현업 검수 대상 |
| `labels_final.jsonl` | C 결과 원본 (낮음 포함, 결정 · 결정이유 · 제외목록) |
| `labels_B1.jsonl` · `labels_B2.jsonl` | 라벨러 원본 |

정답 항목: `규정` · `조`(조 단위, 별표 · 별지는 `별표2`처럼) · `관계`(인용 / 준용·위임 / 같은 사항 / 정의 용어 / 전제 / 2단계) · `찾은방법` · `이유` · `근거문장` · `확신`.

## 정답 규칙
- 정답 = `gold.jsonl`의 조. 확신 낮음은 정답도 오답도 아니게 빼는 대신 **평가셋에서 제외**했다(261111 결정). 시스템이 낮음 조를 보여 주면 오답으로 센다.
- 조 id 대응: `out/parsed/*.json`의 (규정 이름, 조 label). 별지 서식 정답(val 4 · bm 1)은 조 단위 시스템에 대응이 없어 빠진다.
- 정답 0개 문항: val 11 · bm 45 (높음 · 중간 기준). 정밀도 상한이 낮은 이유다.
