# 4도메인(인사·보수·휴가·휴직) 기능 2 평가셋 40건 - 사람 검토 전 AI 초안

조를 개정하면 함께 확인해야 하는 조를 찾는 문제. 평가 대상은 후보 찾기 단계(RAG + 규칙 그래프 + 도메인 그래프)이고 판단 모델 단계는 쓰지 않는다. **사람 검토 전의 AI 초안**이다.

- 형식은 `eval/domain_set_30`과 같다: `산출/changes.jsonl`(개정 E001~E040, 전부 분할=봉인), `산출/labels_final.jsonl`(영향 조, 근거는 원문 발췌), `산출/labels_B1.jsonl`, `산출/labels_B2.jsonl`. 검사 `python validate.py changes 산출/changes.jsonl`, `python validate.py labels 산출/labels_final.jsonl 산출/changes.jsonl` 모두 통과.
- 도구: `eval/impact_label_kit_dom/`은 저장소에 없어서 같은 도구가 들어 있는 `eval/domain_set_30`의 `지시서.md`, `validate.py`를 복사해 40건용으로 고쳐 썼다.
- 조 뽑기: `kit_sample.py` 시드 **20261112**. 도메인 DB(`_src/domain_ontology.reviewed.db`)에서 해당 도메인 개념(루트 기준, 하위 유형 포함)에 '정의'/'근거'로 연결된 조만 후보(약한 '언급'만인 조 제외). 도메인당 10건, 규정 한 개 상한은 도메인당 3건·전체 5건. 정답은 도메인으로 제한하지 않았다.
- 제외(겹침 0건 확인, 제외 조 287개): val_set_30(+교체분), benchmark_100, domain_set_30(교체 전후 모두), PR #11 24건(r2·r3·징계층 포함), PR #12 개정 항목. 쓰인 조는 `used_articles.json`.
- 종류 배분: 도메인마다 종류가 섞이도록 정했고 정답 개수는 뽑을 때 쓰지 않았다. 휴직은 '정의 변경'에 맞는 조가 0개라 그 1건을 표현 수정으로 대신했다(휴직 표현 수정 3건).
- 제작: A(개정문) 서브에이전트 4개가 조 본문만 보고 나눠 썼다(후보 찾기 코드·평가 결과·그래프 안 봄). B1/B2는 서로 못 보는 격리 폴더에서 규정 전문만 읽고 라벨(각 4구간). C는 한쪽만 낸 25항목을 원문 기준으로 판정(인정 3, 제외 22, 결정이유는 `labels_final.jsonl`).
- 일치도: B1/B2 합집합 56 중 일치 31(55%), B1만 17, B2만 8. C 후 최종 정답 합계 34.
- 정답 개수 분포(교체 없음): 0개 18건, 1개 14건, 2개 5건, 3개 2건, 4개 1건 (값이 커질수록 같거나 줄어듦). 평균 0.85. 정답 19개 이상인 개정은 없음(번호 이동 2건은 0개, 3개).
- 알려진 한계: C 제외 비율이 높아(22/25) 정답이 보수적이다. 사람 검토에서 특히 B1만 낸 항목의 제외 판단을 확인할 것.
