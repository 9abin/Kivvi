# 개정 영향 후보 LLM 리랭킹 프롬프트

`impact_rerank.txt`는 기존 `scripts/run_domain28_pointwise_luna.py`의 `PROMPT` 문자열을 그대로 추출한 참조 파일이다. 후보마다 독립적으로 판단하는 pointwise 방식이다. 이 폴더의 `run.py`에는 LLM 호출을 추가하지 않았다.

## 입력 조립

프롬프트의 `{input}`에 아래 텍스트를 넣는다. 원본 템플릿은 JSON 중괄호를 이중 중괄호로 저장하므로 Python의 `template.format(input=text)`로 조립할 수 있다.

```text
개정문: {규정명과 개정문}
개정 전 원문: {출발 조 전체 원문}
변경 대상 개정 전: {수정 대상 항·호 원문}
변경 대상 개정 후: {변경을 적용한 대상 원문}
{변경 범위 설명}
관련 정의·적용범위·예외: {관련 원문 또는 추가 근거 없음}

후보 ID: {candidate_id}
후보 조항 원문: {후보 규정명과 원문}
```

기존 실험은 두 규정 각각에서 제목에 정의·용어·적용범위가 있는 앞 두 조를 보조 문맥으로 제공했다. 모든 예외나 간접 인용 사슬이 제공되는 것은 아니다. 정답, 검색 점수·순위, 그래프 경로는 입력에 포함하지 않았다.

## 출력과 정렬

```json
{
  "candidate_id": "후보 조 ID",
  "score": 0,
  "reason": "판단 이유 한 문장",
  "source_evidence": "개정 측 근거 구절",
  "candidate_evidence": "후보 측 근거 구절",
  "needs_text_revision": "판단불가"
}
```

점수는 직접 영향 3, 중간 근거를 통한 간접 영향 2, 근거 부족 1, 영향 없음 0이다. `needs_text_revision`은 `필요`, `불필요`, `판단불가` 중 하나다. 근거가 없으면 evidence는 빈 문자열이다.

기존 실험은 각 검색 방식의 상위 50개 후보를 점수 내림차순으로 재정렬하고, 동점은 원래 순서를 유지했다. 그 밖의 후보는 원래 순서를 유지하므로 후보 집합 밖 정답을 복구하지 못한다. 판단불가 1점이 영향 없음 0점보다 먼저 온다는 정책도 그대로다.

API를 연결할 때는 응답 JSON 형식·필드·점수 범위·후보 ID 일치를 검증해야 한다. 원문 인용 문자열 검사는 별도로 수행해야 하며, 프롬프트 자체가 근거 정확성을 보장하지 않는다.
