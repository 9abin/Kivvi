- 관련: [92 최종 선택](../docs/reports/261110-1552-92-final-selection.md), [93 후보 state 파이프라인](../docs/reports/261111-1500-93-candidate-state-pipeline.md), [94 평가 지표](../docs/reports/261111-2100-94-eval-metrics.md), [97 판단 모델 입력](../docs/reports/261112-2200-97-decide-input-luna-prompt.md), [98 개정 영향 온톨로지](../docs/reports/261112-2330-98-impact-ontology-domain-graph.md)
- 변경 범위: 이 문서만. 실행 스크립트 `eval/relabel_v2/compare_methods.py`(새), 결과 폴더 `out/relabel_v2/compare_bm/`(git 제외)는 실행 때 만든다.
- 상태: **실행 완료(개발 100, seed 0).** 아래 「측정값」에 값을 채웠다. 해석과 계획 대비 바뀐 것은 [리포트 100](261113-1414-100-filter-method-compare-result.md). Gemma 4 12B-it(로컬 LLM) 실행 중이라 해당 행은 비어 있다. 3 · 7번은 규칙 후보 점수를 현재 코드로 다시 채점한 값으로 갱신했다(리포트 100).

## 요약
후보 수집이 낸 후보 풀(개발 100, 문항당 약 60개)을 사람이 읽을 수준으로 줄이는 방법 7가지를 같은 후보 · 같은 정답으로 나란히 비교한다. 지금까지의 비교는 이전 평가셋(val 30 + 최종 98, 정답 40쌍)에서 개발과 시험을 나누지 않은 탐색이었고, 여섯 방법을 한 표에서 비교한 적이 없다. 개발 100(v2 정답)에서 비교하고, 고른 구성 하나만 시험 100에서 한 번 잰다.

## 범위
| 포함 | 제외 |
|---|---|
| 개정문 입력 → 후보 수집 → 거르기 | 근거 문장 생성(답변), 사람 검토 화면 |
| 개발 100 (`eval/relabel_v2/bm`) | 시험 100 (고른 구성 하나로 따로 한 번) |

- 정답: 확신 높음 · 중간만(리포트 94). 개발 100은 정답 91개, 정답 있는 문항 55, 정답 0개 문항 45.
- 후보 풀: `out/relabel_v2/pool_bm.json`(도메인 그래프 경로를 뺀 풀, 리포트 98). 모든 방법에 같은 풀을 넣는다.
- 규칙 후보: 온톨로지 경로 + 개정문 낱말 일치. RAG 후보: 의미 검색 + 키워드(순위 합치기). (리포트 98)

## 비교 방법 7가지
| 번호 | 방법 | 규칙 후보 | RAG 후보 | 로컬 / 외부 |
|---|---|---|---|---|
| 1 | 안 거름 (기준선) | 풀 순서 그대로 | 풀 순서 그대로 | 로컬 |
| 2 | 유사도 리랭커 | bge-reranker-v2-m3 점수순 | 같음 | 로컬 |
| 3 | 판단 모델 단독 | 판단 모델 | 판단 모델 | 로컬 |
| 4 | 로컬 LLM 단독 | Qwen3.5 9B 목록 방식 | 같음 | 로컬 |
| 5 | 외부 LLM 단독 | Luna 목록 방식 | 같음 | 외부 |
| 6 | 출처별 분리, RAG는 로컬 LLM | 판단 모델 | Qwen3.5 9B 목록 방식 | 로컬 |
| 7 | 출처별 분리, RAG는 외부 LLM (현재 구조) | 판단 모델 | Luna 목록 방식 | 외부 |

방법별 설정:
- **판단 모델:** Kanana-2-v-decide-3b. 거르는 문턱 0.7. 확정급 후보는 점수와 관계없이 남긴다. 정의 변경의 용어 사용(USES_TERM) 후보는 판단 모델을 거치지 않는다(리포트 93). 규칙 후보 점수는 기존 `decide_scores.json`을 재사용하고, RAG 후보(3번)는 새로 채점한다.
- **LLM 목록 방식:** 후보 목록을 한 번에 보여 주고 고르기 · 순서 · 근거를 함께 내게 한다(`luna_rerank.py`). 후보 순서를 섞고 id는 별칭(C1…)으로 바꾼다. 입력에 찾은 경로(사실)는 넣고 단계 · 점수는 넣지 않는다. Luna와 Qwen은 같은 프롬프트를 쓴다.
- **리랭커 · 1번의 목록 크기:** 방법마다 최종 목록 크기가 다르므로, 1번과 2번은 7번의 문항별 최종 목록 크기에 맞춰 자른 결과를 함께 낸다.
- **5번 입력:** 후보 풀 순서(등급 → 경로 종류 수 → 점수) 상위 60개. 거르기 입력 평균(약 58개) 수준으로 맞춘 값이며, 결과를 보고 바꾸지 않는다.
- 이전에 쓰던 반반(검색 순위와 판단 모델 순위를 반씩 섞어 순서만 정하는 방법)은 현재 구조의 중간 단계라 비교에서 뺐다.

## 통계와 반복
- 95% 구간은 문항 단위 부트스트랩 5,000번(seed 고정). 1번과 7번을 기준으로 같은 문항끼리 짝지어 차이의 구간을 낸다.
- LLM을 쓰는 방법(4, 5, 6, 7번)은 먼저 후보 순서 seed 0으로 한 번만 돌린다. 방법 간 차이의 95% 구간이 0을 포함하고 순위가 인접한 LLM 방법에 한해 seed 1, 2를 추가한다. 평균과 범위(최소~최대)로 보고한다.
- 판단 모델, 리랭커, 안 거름은 점수 계산이라 한 번만 돌린다.
- 외부 API는 seed를 고정해도 응답이 같다는 보장이 없으므로 응답 원문을 모두 저장하고, 채점은 저장된 응답으로 한다.

## 실행 순서
1. 3문항으로 환경과 속도를 확인한다(판단 모델 환경, bge-reranker, Qwen 9B, Luna API).

3. 2번(리랭커)과 1번(안 거름)을 계산한다.

5. 모든 방법을 `metrics.py`로 채점하고 한 표로 모은다.
6. 구간이 겹치는 LLM 방법에 seed 1, 2를 추가한다.

## 한계와 주의
- **현재 구조(7번)가 유리하다.** 판단 모델 문턱 0.7과 LLM 프롬프트, 후보 개수를 개발 100으로 정했다. 다른 방법은 기본 설정이다. 개발 100 결과는 비교용이고, 최종 점수는 시험 100에서 고른 구성 하나로 한 번만 낸다.
- **정답은 AI 초안이고** 확신 낮음은 평가에서 뺐다. 현업 검수 전 수치다.
- **LLM 흔들림:** 같은 프롬프트도 후보 순서 seed만 바꾸면 전체 재현율이 0.945와 0.967로 달랐다(리포트 97).
- **외부 전송:** Luna(5, 7번)는 규정 원문과 후보 조문이 외부 API로 간다. 팀 작업 규칙(내부망 · 로컬 LLM)과의 관계는 배포 전에 정한다(리포트 93).
- **재현 조건:** 후보 풀, 판단 모델 점수 파일(`decide_scores.json`)은 git에 없다. 판단 모델은 별도 환경에서 돌린다.
- 실행 전에 확인하지 못한 것: 판단 모델(Kanana) 폴더와 환경 위치, bge-reranker 모델 파일, Luna API 키 설정.
