# 팀 실행 안내 (2026.10.14)

검색·답변 추천 구성과, 팀이 같은 결과를 다시 내는 방법. 질문 하나가 처리되는 순서는 `질의_흐름.md`,

## 3. 팀 DB를 이 PC로 받기

팀 DB(`.env`의 `TEAM_*`, 조회 전용 계정)에 접속되면 public 스키마를 이 PC의 Docker DB에 새 DB로 복사한다. 팀 DB는 읽기만 한다.

```powershell
uv run python -m scripts.copy_team_db            # → db-pg 컨테이너의 regulations_team
```

`chunks.section`(장) 칸이 팀 DB에 없어서 사본에만 빈 칸으로 추가한다. 이미 있으면 멈춘다.

## 4. 추천 구성으로 평가하기

PowerShell, 저장소 루트. GPU 8GB 기준이라 GPU를 쓰는 실행(답변 생성, 검색 평가)은 하나씩 돌린다.
두 개를 겹치면 메모리가 거의 다 차서(7.9GB) 둘 다 크게 느려진다. 채점·RAGAS는 GPU를 쓰지 않는다.

```powershell
$env:PYTHONIOENCODING = "utf-8"
$env:PG_DATABASE = "regulations_team"
$env:RETURN_ARTICLE = "1"; $env:HIGHLIGHT_HITS = "1"; $env:LAW_CITES_FROM_HITS = "1"

# 답변 100문항 (첫 글자·답 완성·검사 끝 시간을 문항마다 기록, 같은 --tag로 다시 돌리면 이어서 함)
.\.venv\Scripts\python.exe -m src.eval.run_answer_eval --tag my_run --questions eval/answer_eval_100.jsonl
# LLM 채점 (판정별 개수 출력) / RAGAS (이미 만든 답변에 매김)
.\.venv\Scripts\python.exe -m src.eval.judge_answers my_run --questions eval/answer_eval_100.jsonl
.\.venv\Scripts\python.exe -m src.eval.ragas_from_runs my_run
# 검색 지표 (Hit@k, MRR, Recall@k, 단계별 정답 순위, 리랭크 뒤 10위 밖 문항)
.\.venv\Scripts\python.exe -m src.eval.rank_trace --questions eval/questions_100_retrieval.jsonl --out my_trace.json
```

- 결과: `eval/answer_runs/<tag>/runs.jsonl`(답변·시간), `judged.jsonl`(판정), `judged_q.jsonl`(질문 중심 판정), `ragas.jsonl`, `eval/runs/<out>`(검색).
- 현행 기준 평가셋: `--questions eval/answer_eval_100_current.jsonl`. 질문 중심 채점: `judge_answers <tag> --mode question`. 평가셋 `질문자` 칸을 로그인 정보처럼: `run_answer_eval --asker`.
- 다른 임베딩: `uv run python -m scripts.embed_variant --model Qwen/Qwen3-Embedding-0.6B --target regulations_team_qwen3` 뒤
  `$env:EMBED_MODEL = "Qwen/Qwen3-Embedding-0.6B"; $env:PG_DATABASE = "regulations_team_qwen3"`.
- 근거가 어느 단계에서 빠졌나: `uv run python -m src.eval.loss_breakdown --trace eval/runs/rank_trace_100_team_stages.json --tag <tag> --questions <평가셋>`.
- 끄고 켜며 비교: `USE_REWRITE=0`, `FAST_PIPELINE=0` 환경 변수. `run_answer_eval --plan`/`--no-plan`은 질문 나누기. `rank_trace --no-rewrite`/`--synonyms`/`--no-synonyms`/`--device cpu`.
- 답변 평가셋의 근거를 고치면 검색 정답을 다시 만든다:
  `uv run python -m scripts.build_190_retrieval --src eval/answer_eval_100.jsonl --dst eval/questions_100_retrieval.jsonl`

## 6. 남은 일과 알려진 문제

- **LLM 채점이 흔들린다**: 오답 4개 중 2~3개는 사람이 보면 오답이 아닐 수 있었다(두 규정을 다 적은 것을 틀렸다고 봄, 근거에 있는 문장을 지어냈다고 봄). "빠짐"으로 표시된 요지에는 "다르게 말함"도 섞여 있다. 중요한 판정은 사람이 다시 본다.
- **"부분" 59개**: 답변에 넘어가는 상위 5개 조 안에 필요한 근거를 모두 찾는 비율이 Recall@5 0.62다. 넘기는 조 수(5 → 7)와 RRF 가중치(0.7 : 0.3은 항 단위 시절 값)를 재 볼 것.
- **더 빠르게**: 바꿔쓰기만 gpt-4o-mini로(약 −1.2초, 바꿔쓰기 효과를 잰 검색어가 4o-mini 것), 바꿔쓰기를 기다리는 동안 원래 질문 후보를 먼저 리랭크(약 −0.6~0.9초, 결과 같음), 결론·불릿 모순 확인을 답 뒤로(약 −1~1.5초).
- **검색 누락이 가장 큰 원인**: 비정답 66문항 중 28개. 별표(Q051 직무전결 기준표)는 두 임베딩 모두 못 찾는다. "당일치기 ↔ 당일귀임"처럼 말이 다른 경우도 남아 있다(Q186).
- **Q072 규정 충돌**: 취업규칙 제43조(3회 분할, 2025.06 개정)와 인사규정 제30조(2회 분할)가 다르다. 평가셋 정답은 인사규정만 본다. 정답을 고칠지 팀이 정한다.
- **평가셋 원본 오류**: "예전엔 배우자 출산휴가가 5일…"의 근거에 복무규정 제1조(목적), "인사규정 별표에 직급이 1급부터 5급…"의 근거에 개인정보 지침 "1급 개인정보" 별표가 들어 있다. "팀장 전결…"은 근거가 번호 없는 "별표"라 검색 정답에서 빠졌다.
- **이름 없는 위임 조문 41개**: "출장여비는 별도로 정한 바에 따라 지급한다"처럼 대상 규정 이름이 없어 인용 따라가기가 안 된다. 사람이 대상을 정해 `cites`에 넣으면 해결된다.
- **끊긴 인용 75개**: 약칭을 못 푼 61개, 대상을 못 찾은 14개는 따라가지 않는다.
- **HNSW 상한**: `hnsw.ef_search` 기본 40 < 요청 50. 지금은 DB가 전체 비교라 문제없지만 데이터가 늘면 올린다.
- **화면**: Streamlit 앱은 `ask()`를 그냥 불러 근거 검사를 기다린다. 답을 먼저 보여 주려면 `ask(…, on_token=…, wait_checks=False)`와 `finish()`로 바꾼다.
