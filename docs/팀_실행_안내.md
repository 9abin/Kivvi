# 팀 실행 안내 (2026.10.13)

검색·답변 구조를 아래처럼 확정했다. 팀은 이 설정 그대로 2절을 돌린다.
질문 하나가 처리되는 전체 순서는 `질의_흐름.md`, 단계별 근거는 `검색_설계.md`·`답변_설계.md`.

| 항목 | 값 | 설정 (`config.py`) |

| 리랭크 | 상위 30개, BAAI/bge-reranker-v2-m3, 입력 앞에 `[문서명 장 조항]` | `RERANK_MODEL`, `RERANK_HEADER` |

## 2. 팀이 돌릴 것

PowerShell, 저장소 루트에서. GPU 8GB 기준이고, 아래 실행은 하나씩 돌리는 게 안전하다(두 개까지는 동시에 돌았음, GPU 메모리 7.9GB).

### 2.1 (선택) 동의어 사전 끔이 맞는지 확인 (검색만, 약 10분)

동의어 사전은 끄기로 했지만 효과를 재지는 못했다. 확인하려면 아래 두 줄을 돌린다. 첫 줄은 설정과 상관없이 켜고 재야 하므로, 먼저 `config.USE_SYNONYMS = True`로 바꿔 돌린 뒤 다시 `False`로 돌려놓는다.

```powershell
$env:PYTHONIOENCODING = "utf-8"
.\.venv\Scripts\python.exe -m src.eval.rank_trace --questions eval\questions_100_retrieval.jsonl --out rank_trace_100_syn.json > eval\runs\trace_100_syn.txt
.\.venv\Scripts\python.exe -m src.eval.rank_trace --questions eval\questions_100_retrieval.jsonl --no-synonyms --out rank_trace_100_nosyn.json > eval\runs\trace_100_nosyn.txt
```

- 출력 끝의 "단계별로 정답이 10위 안 / 30위 안 / 못 찾음" 표에서 **리랭크** 줄을 두 파일끼리 비교한다.
- 각 파일 아래쪽 "리랭크 뒤 10위 밖" 목록은 정답이 밀린 질문, 정답과 그 위 조문의 리랭크 점수다. 사전 때문에 생기거나 사라진 실패를 여기서 본다.
- 판단 기준: 리랭크 10위 안 문항 수가 켬 > 끔이면 다시 켜는 것을 검토한다. 그때는 엉뚱하게 붙는 항목("동기", "점심시간" 등)부터 사전에서 지우고 다시 잰다.

### 2.2 항 단위 vs 조 단위 답변 (답변·채점 모두 gpt-5.6-luna, 나누기 끔, 동의어 끔)

이 PC의 DB 두 개를 쓴다. **DB 이름 주의**: 팀 서버의 `regulations`는 항 단위지만, 이 PC의 `regulations`는 2026.10.13에 조 단위로 다시 만들었다. 항 단위 비교본은 `regulations_para`다.

| DB (이 PC, localhost) | 단위 | 색인 청크 |
|---|---|---|
| `regulations_para` | 항 | 4,587 |
| `regulations` | 조 | 2,161 |

```powershell
$env:PYTHONIOENCODING = "utf-8"

$env:PG_DATABASE = "regulations_para"
.\.venv\Scripts\python.exe -m src.eval.run_answer_eval --tag para_luna --no-plan

$env:PG_DATABASE = "regulations"
.\.venv\Scripts\python.exe -m src.eval.run_answer_eval --tag article_luna --no-plan

.\.venv\Scripts\python.exe -m src.eval.judge_answers para_luna article_luna
```

- 환경 변수가 `.env`보다 우선한다(`load_dotenv`는 이미 있는 값을 덮어쓰지 않음).
- 결과: `eval/answer_runs/<tag>/runs.jsonl`(답변), `judged.jsonl`(판정). 채점 출력에 판정별 개수(정답·부분·오답·답못함)가 나온다.
- 중간에 끊겨도 같은 `--tag`로 다시 돌리면 끝난 문항은 건너뛴다.
- 한 문항에 10~20초, 190문항에 40~60분.
- **알려진 제약**: `run_answer_eval`과 `judge_answers`는 지금 `eval/answer_eval.jsonl`(190문항)만 읽는다. 근거가 보강된 100문항 세트(`eval/answer_eval_100.jsonl`)로 돌리려면 두 스크립트에 질문 파일 옵션을 넣어야 한다(아직 안 넣음).

## 3. 평가셋

| 파일 | 문항 | 용도 |
|---|---|---|
| `eval/answer_eval.jsonl` | 190 | 답변 채점 (정답 요지, 금지 내용, 근거 인용) |
| `eval/answer_eval_100.jsonl` | 100 | 위의 부분집합, **36문항 근거 보강판** (2026.10.13 받음) |
| `eval/questions_190_retrieval.jsonl` | 171 | 위 190의 검색 정답 (조 ID, 근거 묶음) |
| `eval/questions_100_retrieval.jsonl` | 93 | 위 100의 검색 정답 |
| `eval/questions_multi.jsonl` | 20 | 두 가지를 묻는 질문 (질문 나누기 측정용) |
| `eval/questions_multi_hard.jsonl` | 19 | 비슷한 주제 / 세 가지 / 한쪽 후보 많음 |
| `eval/questions.jsonl` | 277 | 예전 검색 평가셋 (청크 ID 정답) |

- 검색 정답은 `scripts/build_190_retrieval.py`로 답변 평가셋에서 만든다 (`--src`, `--dst`). 답변 평가셋의 근거를 고치면 이걸 다시 돌린다.
- 근거 하나가 별표 조각 여러 개에 걸치면 "정답묶음" 한 묶음이고, 그중 하나만 찾아도 그 근거는 찾은 것이다.
- **프롬프트 예시는 평가셋에 없는 말로만 쓴다.** 평가 질문을 예시로 넣으면 같은 평가셋 점수가 부풀려진다(질문 나누기 프롬프트에서 실제로 있었음).

## 5. 남은 일과 알려진 문제

- **동의어 사전**: 끔으로 정했지만 효과는 미측정 (2.1).
- **기준값 재조정**: `ANSWER_NONE_BELOW`(0.001), RRF 가중치는 항 단위 시절 값. 2.2 결과의 리랭크 점수로 다시 본다.
- **평가셋 원본 오류**: "예전엔 배우자 출산휴가가 5일이었잖아요…"의 근거에 복무규정 **제1조(목적)**가 적혀 있다. 원본에서 고쳐야 한다. "팀장 전결로 처리할 수 있는 지출이 얼마까지예요?"는 근거가 번호 없는 "별표"라 검색 정답에서 빠졌다.
- **이름 없는 위임 조문 41개**: "출장여비는 별도로 정한 바에 따라 지급한다"(복무규정 제17조 제6항)처럼 대상 규정 이름이 없어 인용 따라가기가 안 된다. 사람이 대상을 정해 `cites`에 넣으면 해결된다.
- **끊긴 인용 75개**: 약칭을 못 푼 61개, 대상을 못 찾은 14개는 따라가지 않는다.
- **HNSW 상한**: `hnsw.ef_search` 기본 40 < 요청 50. 지금은 DB가 인덱스 대신 전체 비교라 문제없지만, 데이터가 늘면 `SET hnsw.ef_search = 100`이 필요하다.
