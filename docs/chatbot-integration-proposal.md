# 챗봇 통합 합의안 (김가빈 ↔ 박형건)

- 작성: 261012 박형건 · 상태: **제안 (합의 전)**
- 근거 리포트: [261012-1500-29-chatbot-integration](reports/261012-1500-29-chatbot-integration.md)
- 확인한 가빈 자료: `kvic-internal-regulations-review` master `5aea0b1` — `rag_pipeline/docs/DB_스키마.md`, `out/chunks.jsonl`, `app/streamlit_app.py`

## 1. 무엇을 하려는가

챗봇 화면 하나에 개정 기능을 권한으로 붙인다.

| 사용자 | 볼 수 있는 것 |
|---|---|
| 일반 직원 | 질의응답 (지금 가빈 화면 그대로) |
| 내규담당부서·준법감시인 (`editor`) | 질의응답 + 답변에 인용된 조항의 **「개정안 작성」** → 개정문·신·구조문대비표·영향 이유·함께 개정안·질의서, 승인·기각 |

**원칙: 개정 초안은 챗봇이 읽는 표(`public.chunks`)에 넣지 않는다.** 넣으면 챗봇이 승인 전 문안으로 답한다. 챗봇 표는 공포된 개정본이 시행일 기준으로 적재될 때만 바뀐다 (내규관리규정 제22~24조).

## 2. DB 구조 제안: 같은 DB, 스키마 분리

```
regulations (PostgreSQL + pgvector)
├─ public  (가빈 담당, 현행 공식본)     documents, chunks
├─ amend   (박형건 담당, 개정 작업)     chunk_detail, edge, finding, changeset, impact, decision_log, article_version
└─ law     (한석희, 나중에 SQLite에서 이전)
```

- 서로의 스키마에는 쓰지 않는다. `amend`는 `public.documents.doc_id`, `public.chunks.chunk_id`를 외래키로 참조만 한다.
- 가빈 표에는 칸을 추가하지 않는다. 필요한 것은 `amend` 쪽에 둔다.

## 5. 개정 흐름과 각 표

```
editor가 개정안 작성 → amend.changeset (초안)
  → 변경안 점검·연쇄 수정 → amend.impact
  → 행·영향마다 승인/기각 → amend.decision_log (덧붙이기만)
  → 이사회 등 의결·공포 (회사 절차, 시스템 밖)
  → loader가 공포본 HWP 파싱 → public.documents/chunks 갱신, 바뀐 청크 재임베딩
  → amend.edge·finding 다시 계산, article_version에 옛 문안 보관
```
