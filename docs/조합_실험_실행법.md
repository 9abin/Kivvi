# 조합 실험 실행법

`rag-combo-experiment.md`(가이드)의 임베딩 · 리랭커 · LLM · 선택 단계 조합을 같은 코드로 돌리는 방법이다. **코드는 고정이고 설정 파일(`configs/combo/`)만 바꿔 끼운다.** 코드를 고치지 않는다.

## 1. 준비 (한 번)

1. 최신 `master`를 받는다. 이 도구는 `src/combo/`, `configs/combo/`에 있다.
2. `.env`의 `PG_*`로 평가에 쓸 DB를 가리킨다(팀 DB 사본). 키와 비밀번호는 문서에 적지 않는다.
3. Ollama 모델을 받는다(담당에 따라).
   ```
   ollama pull qwen3.5:9b                                  # 이민형, 김가빈
   ollama pull qwen3:30b-a3b-instruct-2507-q4_K_M          # 한석희, 박형건 (RAM 약 18GB 이상)
   ollama pull qwen3-embedding:4b-q8_0                     # 박형건 선택 확장
   ```
4. Hugging Face 모델은 처음 실행할 때 자동으로 내려받는다: `BAAI/bge-m3`, `BAAI/bge-reranker-v2-m3`, `Qwen/Qwen3-Embedding-0.6B`, `Qwen/Qwen3-Reranker-4B`(약 8GB, 김가빈 · 박형건).
5. 측정할 때는 다른 프로그램(웹 서버, 다른 Ollama 모델)을 끈다. 시간을 재는 실험이다.

## 2. 공통 기준 실행 (4명 모두, 먼저)

```
python -m src.combo.run configs/combo/baseline.toml
```

기본 구성(E1 · R1 · 선택 끔 · luna 바꿔 쓰기 캐시)이다. 끝나면 `eval/combo/answer_eval_100_tiered/summary.csv`의 마지막 줄을 가이드 값과 맞춰 본다.

| 항목 | 가이드 | 이 코드(개발자 PC) |
|---|---|---|
| 후보 30개 안 필수 근거 | 0.904 (113/125) | 0.905 (114/126) |
| 리랭크 후 필수 Recall@8 | 0.800 | 0.802 |
| 리랭크 후 필수 Recall@16 | 0.896 | 0.905 |
| Hit@1 | 41/98 | 42/99 |
| bge 리랭크 질문당 | 0.3초 | 0.19초 (fp16) |
| 질문 임베딩 bge-m3 | 15ms | 질문 2번(원질문, 바꿔 쓴 질문) 합쳐 약 26ms |

가이드와 이 코드의 질문·근거 수가 하나씩 다르다(98문항 125개 대 99문항 126개). 질문 1개 차이로 보이며, **자기 PC에서 이 정도(±1 근거)로 나오면 같은 것으로 본다.** 크게 다르면 공통 기준 실행 결과 폴더를 가빈에게 보낸다.

## 3. 내 담당 조합 실행

담당별 설정은 `configs/combo/<lee|han|kim|park>/` 에 있다(이민형 `lee`, 한석희 `han`, 김가빈 `kim`, 박형건 `park`).

GPU 메모리 때문에 **단계를 나눠서** 돌린다. 먼저 ① 바꿔 쓰기 → ② 후보 → ③ 리랭크를 모든 설정에 대해 돌려 캐시를 만들고, 그다음 ④ 선택 끔 · ⑤ 선택 켬 지표를 낸다. 단계 사이에 Ollama 모델은 코드가 `ollama stop`으로 내린다.

```
# 1) ① ② ③ (캐시 생성). 설정끼리 같은 단계는 한 번만 계산한다
python -m src.combo.run configs/combo/kim/*.toml --stage rerank

# 2) ④ ⑤ 최종 근거와 지표 (선택 켬 설정은 여기서 LLM 선택을 돌린다)
python -m src.combo.run configs/combo/kim/*.toml
```

- `--stage` 값: `rewrite`, `cands`, `rerank`, `select`, `final`, `answer`, `all`(기본, 최종 근거·지표까지).
- 일부만 돌리기: `--limit 10`(앞 10문항 시험), `--set select.pool=16`처럼 값 덮어쓰기.
- **같은 설정 2회 반복**(변동 크기 측정): `--tag r2`를 붙이면 선택과 결과 파일 이름에 `_r2`가 붙는다. 바꿔 쓰기, 후보, 리랭크는 캐시를 쓴다.
- 캐시를 무시하고 다시 계산: `--force rewrite,cands,rerank`.
- Qwen3 리랭커 4B는 후보 목록당 약 43분이다. 김가빈 · 박형건만 돌린다.

## 4. 결과 파일 (`eval/combo/answer_eval_100_tiered/`)

| 파일 | 내용 |
|---|---|
| `rewrite_<L>.json` | ① 바꿔 쓴 질문, 질문별 시간, 토큰 수, 출력 원문, 오류 |
| `emb_<E>.npy` | ② 모든 색인 청크의 문서 벡터 (크기가 커서 보내지 않는다) |
| `cands_<E>_<L>.json` | ② 후보 30개(순위, RRF 점수), 후보 단계 시간 |
| `rerank_<E>_<L>_<R>.json` | ③ 리랭크 순서와 점수, 시간, 적재 시간, GPU 피크, 오프로드 정보 |
| `select_<조합>.json` | ⑤ LLM이 고른 조문, 출력 이상(파싱 실패, 개수 위반, 후보 밖), 시간, 토큰 |
| `results_<조합>.json` | 질문별 지표(가이드 7절 필드)와 조합 전체 집계(구간 포함) |
| `answers_<조합>_<L>.json` | ⑥ 답변과 판정, 답변 지표 |
| `summary.csv` | 조합별 요약 한 줄(덮어쓰지 않고 줄을 덧붙임) |

결과 파일은 덮어쓰지 않는다(같은 이름이 있으면 `_2`, `_3`). 모든 단계는 질문별 시간(`time.perf_counter`)을 저장하고, 캐시를 쓴 단계는 처음 계산한 시간을 합계에 더한다. 요약에는 코드 커밋, 평가 파일 해시, 설정 해시, 프롬프트 해시, 측정 환경 한 줄이 들어간다.

## 5. 결과 보내기 · 합치기

`eval/combo/answer_eval_100_tiered/` 에서 `emb_*.npy`를 뺀 나머지를 모은다. 합쳐서 요약표 · 요인별 효과 · 단계별 탈락 지점 · 효율-정확도 그림을 만든다.

```
python scripts/combo_report.py <결과 폴더> [<다른 사람 결과 폴더> ...] --out eval/combo/report
```

**평가 파일 해시와 프롬프트 해시가 다른 결과는 합치지 않는다**(보고서에 경고가 나온다).

## 6. ⑥ 답변·채점 (주지표 상위 조합에만)

```
python -m src.combo.run configs/combo/kim/<조합>.toml --stage answer
```

설정의 `[llm.answer]`(없으면 `[llm.default]`)로 답을 쓰고, `[judge]`의 고정 모델로 채점한다. **채점 모델은 후보 LLM이 아닌 모델로 확정해야 한다(미정).** 지금 설정에는 자리표시자로 `gpt-5.6-luna`가 들어 있다(`OPENAI_API_KEY` 필요).

## 7. 문제가 생기면

- `Connection refused`: `ollama serve`가 떠 있는지, 설정의 `base_url`(기본 `http://localhost:11434/v1`)을 확인한다.
- 바꿔 쓰기 · 선택 출력이 깨진다(`parse_fail`이 많음): 사고(thinking) 출력 때문일 수 있다. 설정의 `reasoning_effort = "none"`을 확인한다. `rewrite_<L>.json`의 `raw`에 모델 원문이 있다.
- GPU 메모리 부족: 다른 프로그램을 끄고 `ollama ps`로 올라가 있는 모델을 확인한다(`ollama stop <모델>`). 임베딩 · 리랭커 단계에서는 Ollama 모델이 비어 있어야 한다.
- 문서 벡터 캐시 오류(`다른 설정으로 만들어졌습니다`): 같은 이름의 `emb_<E>.npy`가 다른 모델 · 접두어로 만들어진 것이다. 파일을 지우거나 설정의 `label`을 바꾼다.
- 다시 시작: 단계별 결과가 파일로 남아 있어서 같은 명령을 다시 실행하면 이어서 한다(끝난 단계는 캐시 사용).

## 8. 가이드와 코드의 대응

| 가이드 | 코드 |
|---|---|
| ① 바꿔 쓰기 | `Run.stage_rewrite` (운영 `REWRITE_PROMPT` 그대로) |
| ② 후보 | `Run.stage_cands` (운영 `Searcher`의 RRF · 창 · 용어집 · 조 묶기 그대로, 임베딩만 교체) |
| ③ 리랭크 | `Run.stage_rerank` (R0 없음 / R1 CrossEncoder / R2 Qwen3-Reranker) |
| ④ ⑤ 선택 · 최종 근거 | `Run.stage_select`, `Run.stage_final` (운영 `SELECT_PROMPT`, `_as_articles`, `assemble` 그대로) |
| ⑥ 답변 · 채점 | `src/combo/answer.py` (운영 `Assistant` 그대로, 검색 결과만 저장본 사용) |
| 5.1 지표 | `src/combo/metrics.py`, `Run.aggregate` |
| 5.3 시간 · 자원 | 각 단계 `perf_counter`, `src/combo/env.py` (GPU · RAM 피크, `ollama ps`, 환경 한 줄) |
| 6 · 8 분석 · 산출물 | `scripts/combo_report.py` |
