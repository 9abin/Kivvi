## 목표
30B 내외 로컬 모델 후보를 같은 평가셋으로 비교해, **모델을 키우면 무엇이 얼마나 좋아지는지와 안 좋아지는 이유**를 분리해 밝힌다.

## 배경
- 현재 로컬: 개정문 qwen2.5:7b, 오타·가설·카드 설명 qwen3.5:9b. 외부 luna와 비교하면 자연어 개정 의도 일치가 73% → 86%(120건, 격차 13%p, 신뢰구간이 겹침).
- 격차가 **모델 용량 때문인지, 파이프라인 때문인지** 분리되지 않았다. 말투 D(이름을 대충 쓴 요청)는 luna도 50%였고 모두 규정을 못 찾은 경우라 모델과 무관했다. 가설 카드 bridge 시험에서도 9B와 30B가 같았다(리포트 49).
- 기관 규모(직원 약 160명, 이용 빈도 낮음)와 폐쇄망 가정 때문에 상시 운영 가능한 모델의 상한이 불명확하다. 기관의 GPU 유무를 모른다(확인 필요).

## 비교 설계
**같은 조건**: 같은 120건 자연어 요청(`eval/agent/nl_requests_ext.jsonl`)+원래 8건, 온도 0, 같은 프롬프트·검증 규칙. 모델만 바꾼다.

| 평가 | 입력 | 지표 |
|---|---|---|
| 자연어 → 개정문 | 120+8건 (말투 4 × 개정 3) | 의도 일치, 적용 성공, 첫 시도 성공, 요청 밖 변경 |
| 규정·조 찾기의 바꿔 쓰기 | RAG 팀 평가셋 100문항(`answer_eval_100_tiered.jsonl`) | 규정·조 적중 @1/@3/@5 (rewrite 끔과 켬) |
| 오타 후보 | 새 시드 골든셋 오타 문항 | 재현율, 문제없는 문항의 오경보 |
| 카드 설명 | 카드 30개 표본 | 검증 통과율, 사람이 읽고 틀림·장황함 표시 |
| 속도·자원 | 위 전부 | 건당 지연, 토큰/초, VRAM·RAM, 양자화 |

## 원인 분석 (점수 비교로 끝내지 않는다)
1. **실패 유형 분류**를 모델마다 센다: ① 규정을 못 찾음(호출 전) ② 형식 위반(「개정 문장이 없음」) ③ 요청 밖 수정 ④ 의도 불일치 ⑤ 번호·경계 오류.
2. **같은 문항의 짝지은 비교**(McNemar 검정): 어떤 문항에서 큰 모델이 맞히고 작은 모델이 틀리는가.
3. **공통 실패 vs 모델 고유 실패**: 모든 모델이 틀리는 문항은 파이프라인·정답 쪽 문제로 보고 원인을 따로 본다. 큰 모델만 맞히는 문항이 용량이 필요한 부분이다.
4. **개정 종류별·말투별 교차표**: 격차가 삭제·덧붙이기에 몰려 있는지 확인한다.
5. 자원 대비 효과: 점수 1%p당 지연·메모리 증가.

## 판정 기준 (실험 전에 정한다)
- 큰 모델을 권장하려면: 의도 일치가 작은 모델보다 **10%p 이상 높고**, 짝지은 검정이 유의하며, 대상 환경의 지연 허용선(건당 수십 초 이내)을 만족한다.
- 그렇지 않으면 7B~9B를 유지하고 「모델이 아니라 파이프라인이 병목」이라는 결론을 적는다.
