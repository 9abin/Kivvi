## 목표
한석희가 구축하는 법률 DB를 수정 에이전트가 그대로 질의할 수 있도록 테이블·키·버전 표현을 합의한다.

## 배경
핵심 기능(법령 개정 미반영 탐지)은 변경 법조문과 규정 인용을 SQL로 조인한다.
법조문 ID와 버전 표현이 맞지 않으면 조인이 안 된다. 나중에 바꾸기 비싸서 먼저 정한다.

## 합의할 항목
- [ ] RDB 엔진 (PostgreSQL + pgvector 권장, [02](../02-specs.md))
- [ ] `edge` 테이블 형식 (법조문 도착, 법 이관 유형 포함)
- [ ] 법조문 ID 형식: 조·항·호·목, `제N조의M` 표현
- [ ] 버전 관리: `law_article`의 시행일·종료일, 삭제 조문과 다른 법으로 이관된 조문 표현
- [ ] `law_amendment`의 "변경 조문" 단위 (조 / 항)
- [ ] `sync_log` 기준일 의미 (반입일 vs 법령 기준일)
- [ ] 수집 대상 법령 범위: 규정 인용 법령 목록을 박형건이 넘김
- [ ] 데모용 스냅샷 2개(기준일 전·후) 제공 가능 여부 → 반입 흐름·주입 사례에 필요
- [ ] `reg_law_citation`(규정 ↔ 법조문 연결)은 누가 만드는지

- [ ] 이관 엣지(구법 조문 → 신법 조문) 표현. 그래프는 RDB 엣지 테이블로 표현 ([261006-1152-03](../../../reports/261006-1152-03-rag-cag-tag-graph.md))
