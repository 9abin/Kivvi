조항 수정 에이전트(담당: 박형건) 부분의 작업 규칙. 이 부분을 작업하는 사람과 에이전트는 작업 전에 이 문서부터 읽는다.

- 261013: 저장소 루트의 `AGENTS.md`에서 옮겼다. master에서 `AGENTS.md`·`CLAUDE.md`는 개인용 에이전트 설정으로 git 제외가 됐기 때문이다(가빈 PR #4). **절 번호는 그대로**라서, 옛 리포트·코드 주석의 "AGENTS §3"은 이 문서의 §3이다.
- 범위: `src/regcheck/`, `scripts/`(조항 수정 에이전트 스크립트), `app/review_app.py`, `sql/amend_schema.sql`, `db/`, `docs/00~05`·`docs/reports/`·`docs/todo/`·`docs/learning/`. RAG 챗봇 부분(`src/answer` 등)의 규칙은 가빈 문서(`docs/전처리_규칙.md` 등)를 따른다.

## 2. 작업 흐름

1. 요청의 목표를 한 줄로 정리한다.
2. 읽는다: 이 문서 → `docs/archive/plans/00-status.md` → `docs/01~04` 중 관련 문서 → `docs/archive/plans/todo/00-todo-list.md`
3. 관련 TODO가 있으면 그 문서를 기준으로 진행한다. 없고 작업이 크면 TODO를 먼저 만든다.
   TODO 파일은 바로 다음 1~2개만 상세히 쓴다. 나머지는 목록에만 둔다.
4. 실행한다.
5. 기록한다: 결정·변경이 있으면 `docs/reports/`에 리포트(왜 그렇게 했는지, 버린 대안 포함), 스펙이 바뀌면 `docs/archive/plans/02-specs.md` 갱신.
6. 새 개념이나 설계 결정이 나온 작업은 §6에 따라 학습 문서를 만든다.
7. TODO 상태와 `docs/archive/plans/00-status.md`를 갱신하고, 다음 TODO를 상세화한다.

필요한 문서만 읽는다. 맥락은 대화가 아니라 저장소 문서에 둔다. 팀 회의 결정도 리포트로 옮긴다.

## 3. 원칙 (원본 기획의 결정 사항)

- 오류 후보는 RDB 질의로 찾는다. LLM은 암묵적 관련 비교와 참고 수정안 작성에만 쓴다.
- 법적 판단을 하지 않는다. 결과는 담당자 검토용이다.
- 충돌은 자동 판정하지 않고 양쪽 조문을 표시한다.
- 수정안은 참고 문안으로만 제시한다. 자동 반영하지 않고 담당자가 승인 또는 기각한다.
- 문서만으로 판단할 수 없는 항목(1주차 검토 X1~X7 유형)은 수정안 없이 "담당 부서 확인 필요"로 표시한다.

## 4. 데이터·환경 가정

- 내부망(폐쇄망) 가정. 법률 API는 직접 호출하지 않고, 반입된 법령 스냅샷만 쓴다. 데모는 반입 스냅샷으로 가정한다.
- LLM은 로컬 모델을 쓴다.
- 규정 원문(HWP 등)은 KVIC 저작물이다. 외부 공유 시 원문 대신 ALIO 링크를 제공한다.
- 비밀번호는 git 제외 파일(`.env`, `.env.team`)에만 둔다. 접속 정보는 [connections](../team/connections.md).

## 5. 문서 규칙

- 리포트 파일명: `YYMMDD-HHMM-NN-slug.md` (예: `261006-1430-02-error-rules.md`)
- TODO 파일명: `slug.md`, 목록은 `00-todo-list.md`에 등록
- 형식은 각 폴더의 `_template.md`를 따른다.
- 문서는 짧게 유지한다. 길어지면 쪼갠다.

## 6. 학습 문서 (cognitive-teacher 스킬)

구현한 내용을 팀원(박형건)이 직접 이해하고 설명할 수 있게 학습 문서를 만든다.
- 스킬: `cognitive-teacher` (사용자 PC에 설치. 저장소에는 포함하지 않음)
- 대상: 파서·점검 규칙·DB 설계·평가 설계처럼 이후 판단에 쓰이는 개념, 또는 사용자가 요청한 주제. 단순 설정 작업은 제외
- 저장: `docs/learning/YYMMDD-slug.html`. 상단에 작성일, 대상 코드·문서, 관련 리포트를 적는다
- 예시 데이터: 공개 규정 원문은 써도 된다. 출처(규정명·조문)를 함께 적는다
- 확인: 사용자가 읽고 퀴즈를 푼 결과를 해당 TODO 진행 기록에 한 줄 남긴다
- 학습 문서는 참고용이다. 기준은 `docs/01~05`다
