## 2. 이번에 바꾸는 것

나머지(바꿔 쓰기 방식, 후보 30개, 리랭커, 선택 16→10, 근거 10개, 채점)는 위와 같게 둔다. 바꿔 쓰기와 선택도 생성 LLM이 하므로 LLM을 바꾸면 ①④⑤가 함께 바뀐다.

| 구분 | 모델 | 고른 이유 | 실행 |
|---|---|---|---|
| 임베딩 | **Qwen3-Embedding-8B** (q4) | 1차 최고인 4B의 상위 체급. 1차에서 「체급을 크게 올릴 때만 차이가 난다」는 결과의 연장 | Ollama `qwen3-embedding:8b` (태그 · 크기 확인) |
| 임베딩 | **KURE-v1** | bge-m3를 한국어로 미세조정. 같은 1024차원이라 운영 bge-m3를 그대로 갈아 끼울 수 있음 | sentence-transformers (bge-m3와 같은 방식) |
| 생성 LLM | **EXAONE 4.0 32B** (q4) | 한국어 특화. 밀집형이라 GPU 24GB 이상 권장. 라이선스가 비상업(NC)일 가능성이 있어 운영 채택 전 확인 필요 | 허깅페이스 GGUF (`hf.co/LGAI-EXAONE/...`, 저장소 이름 확인). Ollama 최신 버전 필요. 추론 모드 끔 |
| 생성 LLM | **gpt-oss-20b** | 계열이 다른 MoE(활성 약 3.6B). 「규칙을 어기고 단정한다」는 약점이 모델 계열을 바꾸면 나아지는지 확인 | Ollama `gpt-oss:20b`. 추론 강도 low |

## 4. 실행 조건 (1차에서 문제가 된 것)

- 평가셋: `eval/answer_eval_100_tiered_v2.jsonl`. 1차와 질문 · 근거가 같고 칸 4개(현업확인 등)만 더해졌다
- Ollama 주소는 `localhost`가 아니라 **`http://127.0.0.1:11434`**. 윈도우에서 `localhost`는 호출마다 약 2초가 붙는다
- 생성 LLM은 **컨텍스트 12k 이상, 출력 상한 2048**을 넣은 모델 별칭으로 돌린다. Ollama 기본 컨텍스트(4096)로는 답변 프롬프트(약 9천 토큰)가 잘리고, 상한이 없으면 같은 말을 끝없이 생성하는 문항이 생긴다
  ```
  FROM <모델 태그>
  PARAMETER num_ctx 12288
  PARAMETER num_predict 2048
  ```
- 답변 단계는 끝나야 한꺼번에 저장되므로 **25문항씩 나눠** 돌린다
- 30B급 생성 LLM은 RAM 32GB PC에서 빠듯하다. 다른 큰 프로그램을 닫는다
- 채점은 `gpt-5.6-luna`로 보낸다(평가 질문과 공개 규정 문장). API 키가 필요하다
