# 라벨링 가이드라인: 내부규정 오류 원장

작성 2026-10-07 · 관리 박형건 · 관련: [goldset TODO](todo/goldset.md), [리포트 12](reports/261007-1028-12-goldset-eval.md)

이 문서를 읽고 나면 누가 라벨링하더라도 같은 오류에 같은 기록을 남길 수 있어야 한다. 애매하면 판정하지 말고 `애매`로 두고 9절 절차를 따른다.

## 1. 무엇을 만드는가

**오류 원장**은 한국벤처투자 내부규정 90건의 원문에 있는 문제를 한 건씩 적은 목록이다.

| 쓰는 곳 | 어떻게 |
|---|---|
| 조항 수정 에이전트 (박형건) | 에이전트가 원문만 보고 이 목록의 몇 건을 찾는지 잰다 (정답) |
| 챗봇 RAG (김가빈) | 답변할 때 원문 옆에 정정 안내를 붙인다 |

그래서 원장은 **특정 프로그램의 결과가 아니라 원문 자체에 대한 기록**이어야 한다.

## 2. 지켜야 할 원칙

1. **원문은 고치지 않는다.** 원장에 "어디가 왜 문제인지"만 적는다.
2. **위치는 원문 기준으로 적는다.** 특정 프로그램의 청크 ID에 의존하지 않는다 (4절).
3. **원문의 문제만 적는다.** 프로그램이 원문을 잘못 읽은 것(파싱 실수, 잘못된 인용 해석)은 원장에 넣지 않고 `docs/` 버그 목록으로 보낸다.
4. **추측하지 않는다.** 정답이 확실하지 않으면 `answer`를 비우고 근거만 적는다. 문서만으로 알 수 없으면 `판단 불가`.
5. **판정마다 근거를 남긴다.** 다른 사람이 원문을 열어 같은 결론에 이를 수 있어야 한다.

## 3. 한 건의 단위

- **원문의 문제 1개 = 1행.** 같은 문장에 문제가 두 개면 두 행.
- **같은 원인이 여러 곳에 있으면 곳마다 1행**, 그리고 `group`에 같은 값을 넣는다.
  예: 퇴직금지급규정 제8조①과 제8조의2①의 「제5조」(번호 밀림 하나가 원인) → 2행, `group: "퇴직금지급규정-제5조밀림"`
- **같은 실수가 다른 규정에 반복되면 각각 1행.**
  예: 괴롭힘 예방 지침 제5조④와 직무청렴계약 운영지침 제6조가 둘 다 「임직원행동강령 제35조」를 행동강령책임관 근거로 듦 → 2행
- **범위 인용**(「제19조제2항부터 제21조까지」)은 범위 전체를 1행으로, `quote`에 범위 전체를 적는다.
- **나열 인용 중 일부만 틀리면** 틀린 것만 적는다.

## 4. 위치 적는 법

| 칸 | 적는 것 | 예 |
|---|---|---|
| `reg_id` | 폴더 이름 끝 숫자 (알리오 번호) | `23949` (회계규정) |
| `unit` | `본문` / `부칙` / `별표` / `별지` | `본문` |
| `article` | 원문에 적힌 조 표기 **그대로** | `제72조`, `제9조2`, `제12-1조`, 별표·별지는 `별지 제3호서식` |
| `para` | 항 번호 숫자. 없으면 0 | `1` |
| `para_note` | 원문 항 번호가 겹치거나 이상할 때만 | `②(두 번째)` |
| `quote` | 문제 부분을 **원문에서 그대로 복사**. 그 조·항 안에서 한 곳만 가리킬 만큼 (보통 5~30자) | `제128조의 규정에 의한 결산서` |
| `link` | 알면 적는 연결 ID (없어도 됨) | `{"gabin": "23949_제72조", "ours": "23949:72-0-0-0"}` |

- 부칙은 `article`에 부칙 날짜와 조를 함께: `부칙<2022.07.27> 제2조`
- `quote`는 띄어쓰기·괄호까지 원문 그대로. 오탈자도 고치지 말고 복사한다 (프로그램이 이 문구로 위치를 다시 찾는다).
- 챗봇 DB를 보며 라벨링해도 되지만, **청크 ID의 항 번호가 원문과 다를 수 있다** (노사협의회규정 제9조의 두 번째 ②가 검색용으로 `3항`). `para`는 원문 기준으로 적는다.

## 5. 종류 (`type`)

| 종류 | 뜻 | 실제 예 |
|---|---|---|
| `인용_대상없음` | 인용한 조·항·호·장·별표가 그 문서에 없다 | 회계규정 제72조 「제128조」(제77조까지 있음), 정관 「제42조의2」 |
| `인용_대상불일치` | 인용한 조는 있지만 내용이 문맥과 맞지 않는다 (번호 밀림 포함) | 「임직원행동강령 제35조에 따른 행동강령책임관」(제35조는 교육, 책임관은 제36조), 「인사규정 제6장이 정한 퇴직」(제6장은 휴직) |
| `인용_제목불일치` | 인용에 붙인 조 제목이 실제 제목과 다르다 | 「취업규칙 제6조(채용제한)」(실제 제목 채용결격사유) |
| `규정명_불일치` | 인용한 규정 이름이 공개된 규정의 정식 이름과 다르다 | 「휴직자의 복무관리지침」, 「위임전결 규정」(직무전결규정) |
| `근거소멸` | 의존하던 조문·제도가 삭제됐는데 남아 있다 | 해외근무직원 보수·복지규정 「환율변동차 보전급여」(근거 제7조 2016 삭제) |
| `항번호_중복` | 같은 조 안에서 항 번호가 겹친다 | 노사협의회규정 제9조 ② 두 번 |
| `조번호_이상` | 조 번호가 빠지거나 순서가 어긋난다 | 전산업무지침 제19조 → 제26조 → 제20조 (원문 확인 후) |
| `구명칭_용어` | 바뀐 부서·기관·제도 이름, 문서마다 다른 용어 | 「외무부」(외교부), 「당연해직」(인사규정은 당연면직) |
| `규정간_충돌` | 같은 사항을 두 규정이 다르게 정한다 | 육아휴직 분할: 취업규칙 3회 vs 인사규정 2회 |
| `법령_불일치` | 규정이 인용·반영한 법령 내용이 현행 법령과 다르다 | 퇴직금 중간정산 사유가 2014년 시행령 기준 (법령 대조 후) |
| `표기_오류` | 뜻은 통하지만 형식이 규칙과 다르다 | 「제9조2」(가지번호는 제9조의2), 머리말에 다른 규정 이름(홍보업무지침 머리말 「사옥관리지침」) |
| `오탈자` | 글자·띄어쓰기·조사 오류 | 「정직-갑봉」(감봉), 「금용신용」(금융신용) |

- 하나에 여러 종류가 걸리면 **고치는 행동이 정해지는 쪽**을 고른다. 「제5조」가 밀려서 내용이 틀렸으면 `인용_대상불일치` (번호 밀림은 `basis`에).
- `규정간_충돌`은 한쪽만 적지 말고 **양쪽 위치를 각각 1행**으로 적고 같은 `group`을 준다.
- `오탈자`는 에이전트 평가 범위 밖이지만(결정 전) 챗봇 정정 안내에 쓰므로 똑같이 적는다.

## 6. 처리 분류 (`handling`)

1주차 검토의 F·J·X 분류를 그대로 쓴다.

| 값 | 기준 | 정답(`answer`) |
|---|---|---|
| `고칠 수 있음` | 정답이 하나로 정해진다 (오타, 확실한 번호, 정식 명칭) | **반드시** 적는다: `제71조`, `직무전결규정` |
| `판단 가능` | 두 조문이 다르지만 내규관리규정 판정 규칙으로 우선이 정해진다 | 비우고, `basis`에 적용 규칙을 적는다 (아래) |
| `판단 불가` | 문서만으로 알 수 없다 (제도가 아직 있는지, 실제 운영, 비공개 문서) | 비운다. `basis`에 무엇을 확인해야 하는지 |

**판단 가능**에 쓰는 규칙 (내규관리규정):
- 제7조① 법령·정관에 저촉되면 그 부분은 효력 없음
- 제7조② 규정 > 지침
- 제7조③ 같은 순위면 나중에 제정·개정된 쪽이 우선
- 제8조③ 부서·기관명이 바뀌었으면 개정 전까지 새 이름으로 읽음

예외: 취업규칙 제3조 단서("하위 지침이 취업규칙보다 우선")는 위 규칙과 반대라 판정 근거로 쓰지 않는다.

**판단 불가**의 예: 집행간부 운영규정의 근거 조문이 정관·직제규정에 없음(제도가 폐지됐는지 근거만 빠졌는지 모름), 징계지침 별표4의 「해임」(징계 종류에 없음, 면직으로 볼지는 회사 결정), 공개 90건에 없는 「벤처투자모태조합 출자관리지침」 인용.

### 6-1. 기대 출력 (`expected`)

`answer`는 "고친 값"이라 판단 가능·판단 불가에서는 비어 있다. 하지만 이때도 **에이전트가 무엇을 내놓아야 맞는지**는 정해야 채점할 수 있다 (예: 판단 가능인데 에이전트가 한쪽으로 고쳐 버리면 틀림). 그래서 모든 행에 `expected`를 적는다.

| 처리 | `expected`에 적을 것 | 예 |
|---|---|---|
| 고칠 수 있음 | `{"show": "수정 제안", "fix": 고친 값}` (`answer`와 같음) | `{"show": "수정 제안", "fix": "제71조"}` |
| 판단 가능 | `{"show": "양쪽 표시", "pair": [두 위치], "rule": 적용 조항, "prevails": 우선하는 쪽}` — **수정안을 내면 틀림** | `{"show": "양쪽 표시", "pair": ["취업규칙 제43조②", "인사규정 제30조②"], "rule": "내규관리규정 제7조③", "prevails": "인사규정 제30조② (2026.09 개정)"}` |
| 판단 불가 | `{"show": "판단 불가", "ask": 담당 부서에 물을 질문}` — **수정안이나 우선 판정을 내면 틀림** | `{"show": "판단 불가", "ask": "집행간부 제도가 현재 운영 중인가, 근거 조문은 어디인가"}` |

판단 가능 중 충돌이 아니라 **인용 대상이 없지만 다른 근거로 보충할 수 있는 경우**는 `{"show": "대상 없음 표시 + 보충 안내", "keep": 유효한 부분, "supplement": 보충 근거}`로 적는다. 예: 괴롭힘 예방 지침 제3조 「행동강령 제2조 제6호」(제6호 없음) → 근로기준법 부분은 유효, 취업규칙 제48조①로 보충 (1주차 J5).

채점할 때는 위치가 맞는지(탐지)와 별개로, 에이전트의 표시 방식이 `show`와 같은지를 따로 센다.

## 7. 오류가 아닌 것 (적지 않는다)

| 경우 | 이유 |
|---|---|
| 개정 이력 메모 「[제11조에서 이동, 종전 제13조는 제15조로 이동]」 | 옛 번호의 기록이지 인용이 아님 |
| 부칙의 시행일·경과조치에 남은 옛 번호 (예: 2005년 부칙의 「제7조의2」) | 그 당시 번호가 맞음. 부칙은 이력으로 남는 것이 정상 |
| 부칙의 옛 이름 읽기 조항 (내규관리규정 부칙 제2조 「제규정관리규정」) | 옛 이름을 새 이름으로 읽으라는 정상 조항 |
| 외부 법령·고시 인용 (「국가사이버안전관리규정」, 「○○부 고시」) | 공개 90건에 없다는 이유만으로 오류가 아님. 법령 대조가 필요하면 `법령_불일치` 후보로 따로 |
| 프로그램이 잘못 읽은 결과 | 원문 문제가 아님 → 버그 목록 |

**주의:** 부칙이라도 **현행 본문을 가리키는 적용례**가 틀리면 오류다. 예: 취업규칙 부칙<2022.07.27> 제2조 「제4조 제6호, 제12호 및 제13호의 개정규정은」(채용결격사유는 제6조) → `인용_대상불일치`.

## 8. 기록 칸

| 칸 | 규칙 |
|---|---|
| `id` | 출처별 접두어 + 번호 (1주차 `C1`, 가빈 `K001`, 확인 대기에서 온 것 `R001`, 독립 검토 `I001`) |
| `basis` | 왜 문제인지 한두 문장. 근거 조문을 원문 표기로 (`인사규정 제7장(퇴직)`) |
| `source` | 어디서 나온 건인지 (`1주차 검토`, `김가빈 corrections.json`, `확인 대기`, `독립 검토`) |
| `judge`, `date` | 판정자 이름, 판정 날짜 |
| `expected` | 에이전트가 내놓아야 할 표시 (6-1절). 모든 행에 적는다 |
| `group` | 같은 원인·충돌 짝 묶음 (선택) |

## 9. 작업 방식별 절차

### 9-1. 확인 대기열 판정 (`eval/review_queue.csv`)
시스템이 낸 후보를 원문과 대조해 판정 칸에 하나를 적는다.

| 판정 | 뜻 | 다음 |
|---|---|---|
| `오류` | 원문 문제가 맞다 | 원장에 1행 추가 (5~8절대로) |
| `정상` | 원문은 문제없다 | 시스템 오탐으로 기록 |
| `판단불가` | 문서만으로 모른다 | 원장에 `판단 불가`로 추가 |
| `애매` | 판정자가 확신이 없다 | 두 번째 사람이 본다 |
| `버그` | 시스템이 원문을 잘못 읽었다 | 버그 목록으로 |

### 9-2. 독립 정밀 검토 (재현율 측정용)
- 담당 21건 **밖**에서 무작위로 고른 조문을 처음부터 끝까지 읽고 문제를 **모두** 적는다.
- **시스템 결과, 다른 사람의 라벨, 챗봇 DB의 `본문_검색`·보정된 인용을 보지 않는다.** 원문(HWP나 `본문`)만 본다.
- 문제가 없는 조문도 "확인함"으로 기록한다 (어디까지 봤는지가 재현율 계산의 분모).

### 9-3. 이중 라벨링과 합의
- 확인 대기와 독립 검토의 **20%**는 두 사람이 따로 판정한다.
- 판정이 다르면 둘이 원문을 같이 보고 합의한다. 합의가 안 되면 `판단 불가`로 두고 `basis`에 양쪽 의견을 적는다.
- 일치율(같은 판정 비율)을 기록한다. 낮으면 이 가이드라인의 해당 절을 고친다.

|---|---|
| 챗봇 DB의 `본문_검색`, 보정이 반영된 `cites` | 이미 고쳐진 값이라 원문 문제가 가려짐 |
| `corrections.json` (가빈 판정분 이외의 작업 중) | 이중 라벨링·독립 검토가 오염됨 |
| 시스템 결과 (독립 검토 중) | 시스템이 찾은 것만 보게 되어 재현율을 잴 수 없음 |

## 11. 변경 시나리오 세트 (질문 → 정답)

오류 원장은 "원문 전체를 점검했을 때"의 정답이다. **"이 조항을 이렇게 바꾸면 어떻게 되나"**라는 질문에 대한 정답은 시나리오 세트로 따로 만든다 (PoC 필수 ④ 변경안 점검의 평가 기준). 파일은 `eval/scenarios/S01.json`처럼 시나리오당 1개.

### 11-1. 질문 쪽 (`change`)

| 칸 | 적는 것 |
|---|---|
| `kind` | `값 변경` / `번호 변경` / `삭제` / `신설` / `용어 변경` |
| `target` | 바꾸는 위치 (4절 형식: 규정ID·조·항) |
| `amendment` | 개정문 형식: 「제30조제2항 중 "최대 2회(나누어 사용하게 되는 휴직의 단위는 총 3회)"를 "3회(…최대 4회)"로 한다」 |
| `request` | 같은 내용을 사람이 말하듯이 (자연어 입력 시험용) |

### 11-2. 정답 쪽 (`expected`)

영향을 아래 칸으로 나눠 적는다. 칸마다 항목은 `{위치, 이유, handling}`.

| 칸 | 뜻 | 예 |
|---|---|---|
| `breaks` | 이 변경으로 **깨지는** 인용·근거 (반드시 고쳐야 함) | 제37조 삭제 → 「제37조에 따라 당연면직」 인용 |
| `new_conflicts` | 새로 생기는 충돌 | 값을 바꿨더니 다른 규정과 달라짐 |
| `resolved` | **해소되는** 기존 이슈 (원장 ID로) | J4 |
| `review` | 영향은 있지만 고칠 필요는 없을 수 있음, 사람 확인 | 「인사규정 제30조에 따른 육아휴직」을 인용하는 승진지침 별표2 |
| `law_check` | 법령 대조가 필요한 것 | 남녀고용평등법 육아휴직 분할 기준 |
| `undeterminable` | 판단 불가로 표시해야 할 것 | |
| `not_affected` (선택) | 영향이 **없어야** 하는 것 (오탐 확인용) | 이름만 비슷한 다른 조문 |

### 11-3. 시나리오 라벨링 규칙
- **관련 조항 표를 출발점으로 쓰되 거기서 끝내지 않는다.** 표는 인용으로 연결된 것만 안다. 인용 없이 같은 내용을 정한 조문(J4), 같은 용어를 쓰는 조문(「당연면직」·「당연해직」)은 원문을 검색해서 직접 찾는다. 이 둘이 에이전트가 놓치기 쉬운 부분이라 꼭 넣는다.
- 변경 유형마다 2~4개, 전체 10~15개를 목표로 한다.
- 원장에 있는 기존 이슈가 해소되면 `resolved`에 원장 ID를 적는다.
- 부칙에 옛 번호를 새 번호로 읽으라는 조항이 있는 규정(직제규정, 임직원행동강령)에서 번호가 바뀌면, 다른 규정의 인용은 **효력상 문제는 없지만 표기 정비 대상**이다. `breaks`가 아니라 `review`에 넣고 이유에 그 부칙 조항을 적는다.

## 12. 챗봇 질문-답 세트 (참고, 김가빈 담당)

챗봇 평가는 "질문 → 답 + 근거 조문(청크 ID)" 형식이라 위치를 챗봇 청크 ID로 적는다. 원장에서 질문을 만들 수 있다.
- 원장의 `규정간_충돌` → "육아휴직 몇 번 나눠 쓸 수 있어?" / 기대 답: 두 규정이 다름, 양쪽 조문, 우선 규칙 안내
- 원장의 `판단 불가` → "집행간부는 어떻게 임명해?" / 기대 답: 근거 조문 없음, 담당 부서 확인
- 원장의 `인용_대상없음`(고칠 수 있음) → 정정 안내가 붙는지 확인
