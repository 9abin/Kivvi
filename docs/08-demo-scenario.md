# 08. 시연 시나리오 (10/20 발표)

시연 한 번에 7~8분. 「설치 첫날 → 법령 반입 → 변경 감시 → 개정 요청 → 영향 검토 → 승인 → 공포」를 한 화면(규정 도우미)에서 보인다.
준비물: Docker Desktop(`docker start reg-db`), Ollama(qwen3.5:9b, qwen2.5:7b), `uv run --extra db python app/web_server.py` → http://127.0.0.1:8765, 화면은 개정 담당자 역할로 시작.
**시연 전 확인 (각 1줄)**: 화면 오른쪽 위 연결 표시가 초록(청크 대응 끊김 없음), `/api/status`의 `stale`이 0, 시험으로 만든 개정안(L261014-…, W…)은 「기각」으로 닫아 두거나 남겨 두는 것을 미리 정한다.

## 장면 1. 질문 (1분)  — 일반 직원
- 일반 직원 역할: 「육아휴직은 몇 번까지 나눠 쓸 수 있나요?」 → 답변의 [n]을 눌러 오른쪽에 근거 원문. 답은 근거에 있는 것만, 개정 중이면 「개정 검토 중」 배지.
- 말할 것: 직원은 질의응답만 보인다. 개정 기능은 권한이 있는 사람에게만 보인다.

## 장면 2. 법령 반입과 변경 감시 (2분) — 개정 담당자
- 「변경 감시」: 반입된 법률 DB 두 판이 목록에 있다 (10/07판 232개, 현재 판 284개).
- 10/07판 선택 → 「기준으로만 기록」(설치 첫날). 현재 판 선택 → 「탐색 시작」 → **새로 생김 5건** (1.3초).
- 한 건의 「조문 열기」 → 법령 대조 카드: 바뀐 법령 조문과 우리 내규 문장, 법제처 해석례.
- 말할 것: 법을 새로 반입하면 점검을 다시 돌려 「새로 생긴 문제」만 가려 준다. 법령 개정을 사람이 일일이 찾지 않는다. 판단은 사람(§3).
- 같은 화면 아래 「법령명 일괄 정비」: 옛 법령명 4종·오기 3종 → 6개 규정 개정문. 규정을 골라 개정안 생성(시연 중 1건만).

## 장면 3. 개정 요청 → 개정안 → 영향 검토 (3분) — 개정 담당자
- 인사규정 제30조(육아휴직)에서 개정안 작성: 「분할 횟수를 최대 3회(…총 4회)로 늘려줘」 → 로컬 모델이 개정문 초안, 적용기가 원문과 맞는지 확인.
- 개정안 검토: 신·구조문 대비표, 영향 카드(깨짐 0, 충돌 해소 1: 취업규칙과 값이 같아짐, 법령 대조: 남녀고용평등법 제19조의4 「3회」와 숫자 대조), **오타 의심 카드**(오타를 일부러 넣은 문장으로 한 번 더).
- **개정 절차 안내**: 인사규정은 이사회 의결 대상(이사회규정 제3조제2항제10호), 대표이사 결재, 등록·공지. 근거 조문이 같이 나온다. 취업규칙이면 근로기준법 제94조 근로자 의견 청취 단계가 추가된다.
- 카드를 수락·기각하고 「검토자에게 제출」.

## 장면 4. 승인과 공포 (1분)
- 역할을 **승인권자**로 전환 → 개정안 검토 화면: 카드 결정은 막혀 있고 「승인(최종안 확정)」/「반려」만 있다. 기안한 사람은 자기 개정안을 승인할 수 없다(서버가 거부).
- 승인 → 수락한 카드만 반영한 최종안(최종 개정안 미리보기, 내려받기).
- 개정 담당자로 돌아와 「공포 처리(등록·공지)」. 결정 기록은 덧붙이기만 가능(수정·삭제 불가).

## 장면 5. 한계를 보이며 닫기 (1분)
- 평가 표 한 장(docs/07): 설계한 오류 유형은 거의 다 잡고, 의미가 틀린 인용·법령과 다른 숫자·오타는 일부만 잡는다. 외부 상용 모델(상한)과 로컬 모델 차이도 같이 보여 준다.
- 말할 것: 완벽하게 잡는 것은 불가능하다. 목표는 「사람이 놓치기 쉬운 곳을 근거와 함께 먼저 보여 주고, 판단은 사람이 한다」.

## 막혔을 때
| 증상 | 조치 |
|---|---|
| 화면이 「예시 데이터」 | DB 컨테이너(`docker start reg-db`)와 서버를 확인, 접속은 `127.0.0.1` |
| 채팅이 느리다(20~35초) | 질문을 미리 한 번 해서 모델을 올려 둔다. 시연은 근거 원문이 먼저 보이는 순서로 |
| 연결 표시가 「청크 대응 끊김」 | `uv run --extra db python scripts/amend_load.py` (db-sharing-guide §6) |
| 개정안 작성이 실패 | 요청을 더 구체적으로(조·항·값). 안 되면 미리 만들어 둔 개정안(S01, W261013-162409)을 연다 |
