# 261019-1748 솔라(업스테이지) 비교: Pro 4는 추론 모드를 켜면 luna와 같은 품질, 대신 느리다

- 관련: [57 LLM 인용 검토](261018-2000-57-llm-citation-review.md)(개정 요청 120건 luna 116), [59 RAG 실험 결정](261019-1050-59-rag-experiment-decision.md)(최종 검색 설정), 커밋 6684138(솔라 API 연결)
- 변경 범위: 문서만 (이 리포트). 코드 · 설정 변경 없음. 시연 기본 모델은 그대로 luna

## 요약
KVIC가 업스테이지와 사내 챗봇을 만든다는 기사(2026.09.30 서울경제)를 보고, 우리 두 시스템을 솔라로 바꿔 끼우면 어떤지 쟀다.
**Solar Pro 4를 추론 모드(`reasoning_effort=high`)로 쓰면 RAG(정답 64)와 개정 요청(의도 맞음 116/120) 모두 luna와 같다.** 추론을 끄면 RAG 오답 6 · 답못함 10, 개정 요청 109로 떨어진다.
다만 추론 모드는 질문 하나에 1분 넘게 걸려 시연에는 luna를 유지한다.

## 측정 조건
- **RAG**: 평가셋 v2 100문항(`eval/answer_eval_100_tiered_v2.jsonl`), 검색은 최종 설정(리포트 59: Qwen3-Embedding-4B · bge 리랭커 · 근거 10 · 바꿔 쓰기 끔)으로 **한 번 돌린 결과를 모든 모델이 같이 씀**(`configs/combo/final/final_qwen4b_bge_S0.toml`, `--stage answer`). 답변과 검사(근거 검사 · 충돌 확인)를 같은 모델로 바꿈. **채점은 모두 luna**(고정 채점 모델)
- **개정 요청**: 자연어 개정 요청 120건(`eval/agent/nl_requests_ext.jsonl`, `scripts/nl_eval.py`). 지표는 「의도 맞음 · 요청 밖 변경 없음」
- 솔라 호출: 업스테이지 OpenAI 호환 API(`https://api.upstage.ai/v1`, `.env`의 `UPSTAGE_API_KEY`). 추론 모드는 `SOLAR_REASONING=high`(개정 요청) · `reasoning_effort="high"`(RAG 설정)
- 보내는 것: 질문과 공개 규정(ALIO) 조문뿐 (AGENTS §4 외부 API 원칙)

- 추론 끔의 답못함 10 중 9건은 우리 숫자 검사(`unsupported_numbers`)가 근거에 없는 숫자를 단 답을 보류한 것. 추론을 켜면 5건으로 줄어 luna(4)와 비슷해진다
- 오답(규정에 없는 것을 단정하는 등)은 추론 high · luna 모두 2건. 미리 정한 채택 기준(개정 요청 110건 이상, 오답이 luna보다 많지 않을 것)을 넘는다

## 해석
1. **솔라로 바꿔 끼울 수 있다.** 같은 검색 결과 · 같은 검사 단계에서 추론 모드 Pro 4는 luna와 구분되지 않는다(100문항이라 ±1~2건 차이는 의미 없음). KVIC가 운영 모델로 솔라를 쓰더라도 우리 파이프라인은 모델 이름만 바꾸면 된다(`CHAT_MODEL` · `DRAFT_MODEL`에 `solar-…`)
2. **품질은 추론 모드가 만든다.** 추론을 끄면 숫자를 지어내 보류되거나(답못함 10) 단정해 틀리는(오답 6) 답이 늘고, 개정 요청도 7건 덜 맞힌다
3. **문제는 속도다.** RAG는 질문 하나에 모델을 3번(답변 · 근거 검사 · 충돌 확인) 부르는데 세 번 모두 추론을 해서 질문당 1분 이상. 화면에서 기다리기 어렵다
