# 261106-2100 새 봉인 7차(휴직 20문항) 사전 등록: 우리 키워드 층 대 팀 휴직 DB 층

- 관련: [84 온톨로지 보강과 휴직 DB 비교](261106-1900-84-ontology-reinforcement-and-pr-review.md)
- 이 문서는 **결과를 보기 전에** 쓴다. 이후 코드 · 층 설정 · 판정 기준을 바꾸면 이 평가는 개발용이 된다.

## 무엇을 확인하나
리포트 84 §5의 비교(휴직 시험 28문항)는 우리 층을 쓰던 중에 만든 문항이고 후보 풀에 우리 층 후보가 들어 있어 DB에 불리했다. 새 가상 개정 20건(I101~I120)에서 층의 몫을 다시 잰다.

## 절차
- 작성: 시스템과 DB를 모르는 에이전트가 본문에 「휴직」이 나오는 조 목록에서 난수로 뽑는다(제외목록 149쌍). 종류: 값 변경 10, 삭제 3, 내용 변경 4, 정의 변경 1, 위임·법령 변경 2. 한 규정에서 4건 이하.
- 후보 풀: 파이프라인(RAG 포함) + 밀집 + BM25 + 하이브리드 상위 30 + **주제 층이 내는 후보 전부**(우리 층, DB 위계, DB 같은 개념 전부, DB 확정만). 라벨러 4명이 풀의 모든 조를 읽고 판정한다(AI 초안).
- 동결: `out/freeze/freeze_r7_20261106.json`(src 전체 · 스크립트 · 연결 표 `out/hyujik_links.jsonl` 해시).

## 비교 변형 (후보 수집만, 판단 모델 정렬은 쓰지 않는다)
1. 층 끔 (RAG + 그래프)
2. 우리 키워드 층
3. 팀 DB 층 (같은 개념 · 같은 속성 + 개념 위계)
4. 팀 DB 층, 사람이 확정한 연결만 (+ 위계)
5. 우리 + 팀 DB(위계)
6. 우리 + 팀 DB(확정만, 위계)

## 사전 등록 지표와 판정 (RAG 포함이 기본 조건, RAG 없이는 보조)
- 주지표: **층이 더한 정답 수**(층을 껐을 때 후보에 없던 정답이 후보에 오름), 더한 후보 수, 더한 후보당 정답.
- P1 (기본 조건, RAG 포함): 변형 5가 변형 1보다 정답을 하나 이상 더하면 「층이 더한다」, 아니면 「더하지 못한다」. 더한 후보 수를 함께 적는다.
- P2 (RAG 없이): 변형 5가 변형 2(우리 층 단독)보다 정답을 더하면 「합치면 이득」.
- P3 (RAG 없이): 더한 후보당 정답이 변형 3이 변형 2보다 높으면 「DB가 더 정확」.
- 정답이 적어(예상 20~40건) 통계 구간으로 우열을 말하지 않고 방향과 개수만 보고한다. 표본이 작아 1~2건 차이는 우연으로 읽는다.

## 알려진 한계 (미리 적는다)
- 정답은 AI 라벨이고 현업 확인이 없다. 팀 DB 연결의 119/151은 「초안」 표시다.
- 문항이 휴직 한 주제이고 20건이며, 일부 문항은 DB가 다루지 않는 조(별표 등)를 뽑을 수 있다.
- 우리 키워드 층과 팀 DB 모두 휴직 시험 28문항을 본 뒤의 구성이다. 7차 문항에는 맞춘 적이 없다.
