- 관련: [50 에이전트 전체 점검](261015-2300-50-agent-audit.md), [38 변경안 골든셋](261014-1225-38-change-goldset.md)
- 변경 범위: `src/regcheck/change_gold.py`(정답 생성기 결함 3개, `--scale`), `src/regcheck/nl.py`(덧붙이기 IndexError, 외부 모델 경로), `src/regcheck/change_check.py`(연쇄 2단계, 구조 밖 체크리스트), `src/regcheck/explain.py`(카드 설명), `scripts/gen_nl_requests.py`, `scripts/nl_eval.py`, 화면 설명 버튼

## 요약
평가가 우리가 만든 문항에 치우쳐 있다는 약점(리포트 50)을 줄이려고 ① 설계에 쓰지 않은 새 시드로 골든셋을 482문항씩 3벌 만들고, ② 외부 모델(gpt-5.4-mini)이 다양한 말투로 쓴 자연어 개정 요청 120건을 만들어 로컬 7B와 외부 luna로 채점했다. 기계적 정합성은 높게 유지됐고, 자연어 입력은 더 낮게 나와 약점이 드러났다. 평가 중에 **실제 버그 1개**(문장 덧붙이기 IndexError)와 **정답 생성기 결함 3개**를 찾아 고쳤다.

## 1. 새 시드 골든셋 (시드 2·3·4, 각 482문항, 규칙은 시드 1만 보고 다듬음)
| 유형 | 시드 2+3 합산(오타 켠 상태), 95% 구간 | 시드 4(오타 끈 상태) |
|---|---|---|
| 깨짐 | 517/519 = 99.6% [98.6, 99.9] (생성기 수정 전 집합) | 276/276 |
| 법령명 | 153/153 [97.6, 100] | 77/77 |
| 새 충돌 | 60/60 [94.0, 100] | 30/30 |
| 다른 규정 확인 | 86/86 [95.7, 100] | 39/39 |
| 법령 수치 | 8/8 [67.6, 100] (표본 작음) | 4/4 |
| **오타(로컬 qwen3.5:9b)** | **256/374 = 68.4% [63.6, 73.0]** | — |
| 문제없는 문항 높은 우선순위 경보 | 182개 중 9건 | 91개 중 0건 |
- 시드 2·3은 정답 생성기를 고치기 **전**과 **후** 집합이 달라(재생성으로 문항이 바뀜) 1:1 비교는 아니다. 위 합산은 고친 뒤 재생성한 집합이다(깨짐 274/274, 243/245 등).
- 점수가 높은 이유: 이 유형은 글자 단위로 확인되는 기계적 정합성이고, 정답도 우리 생성기가 원문 검색으로 만든다. **실제 개정에서의 연동 탐지력을 뜻하지 않는다.**

### 오경보 9건의 판정 (시드 2·3)
- 정답 쪽 한계 2건: 자기 규정 이름을 「…」로 감싸 인용한 곳을 생성기가 놓침(G047), 번호가 밀리는 조 안의 같은 규정 인용(G310). 시스템이 맞았다.
- 시스템 오경보 4건: 「규정 제5조」 같은 막연한 상위 규정 인용을 같은 문서 인용으로 읽음 2건(G058, G301), 오타 검사가 「하여야→해야」를 오타로 봄 2건(G219, G230).
- 3건은 원인 분석 미완.

### 정답 생성기 결함 (모두 시스템이 맞았음)
1. 규정명이 더 긴 이름의 일부일 때(「국가사이버안전관리규정」 속 「안전관리규정」) 일치로 셈
2. 부칙의 「[종전 … 조문번호 변경]」 이력 표시를 인용으로 셈
3. 「취업규칙 제46조 및 인사규정 제31조」처럼 중간에 다른 규정명이 끼어도 일치로 셈
- 시드 1의 법령 수치 G090(인용하지 않은 항의 숫자)을 포함하면 정답 생성기 오류는 모두 시스템이 맞은 사례였다.
- 한계: 규정명을 조금 틀리게 쓰면(「전화 녹음관리 및 운영지침」→「전화 녹음 및 운영지침」) 비슷한 이름으로 연결돼 깨짐으로 안 잡힌다(첫 집합 5건, 재생성 집합 2건). **고치지 않은 시스템 한계.**

## 2. 자연어 개정 요청 (외부 모델이 쓴 120건, 정답은 코드가 정함)
말투 4종(A 격식, B 구어, C 규정명 없음·조를 연 상태, D 짧고 거침·조 안 연 상태) × 개정 3종(숫자 변경, 삭제, 문장 덧붙이기). 비용 약 50원.
| 구분 | 로컬 qwen2.5:7b | luna (외부) |
|---|---|---|
| **전체 의도 일치** | 88/120 = 73% [65, 80] | 103/120 = 86% [78, 91] |
| A 격식 | 77% | 100% |
| B 구어 | 80% | 97% |
| C 규정명 없음 | 93% | 97% |
| D 짧고 거침 | 43% | 50% |
| 숫자 / 삭제 / 덧붙이기 | 88% / 64% / 64% | 92% / 83% / 81% |
- D는 **두 모델 모두 절반**이다. luna의 D 실패 14건은 모두 모델이 호출되기 전에 규정을 못 찾은 것(이름을 대충 쓴 경우)이라 모델이 아니라 우리 규정명 인식의 한계다.
- 첫 채점(56%)은 두 가지 때문에 낮았다: 덧붙이기에서 `IndexError`(8건, 고침), 평가가 화면과 달리 조 라벨을 붙이지 않음(고침). **고치기 전 수치는 버린다.**
- 이 평가는 정답이 코드로 정해지는 3가지 개정만 다룬다. 복합 개정(여러 조·여러 항)은 아직 없다.

## 2-2. 규정·조 찾기 (RAG 팀의 독립 라벨 평가셋, 질문 90개·필수 근거 122개)
`target.find_targets`로 규정 이름이 없는 질문의 정답 필수 근거(규정, 조)가 상위 후보에 드는지 측정(`scripts/eval_target_rag.py`, CPU).
| 지표 | rewrite 끔 | rewrite 켬(qwen2.5:7b) |
|---|---|---|
| 규정 @1 / @3 / @5 | 58% / **83% [74, 90]** / 89% | 57% / 83% / 90% |
| 조 @1 / @3 / @5 | 41% / **62% [52, 72]** / 71% | 38% / 60% / 73% |
- 이름 매칭이 실패했을 때의 대체 경로로는 쓸 만하다(규정 @3 83%). 조까지는 약하다(@3 62%). 1위는 자동 선택에 쓸 수 없어 「후보를 보이고 사람이 고른다」가 맞다.
- **rewrite는 효과가 없다.** 후보가 바뀐 질문 59개 중 조 @3 좋아짐 5·나빠짐 7, 규정 @3 3·3. 「확신 없음」 표시는 70 → 52개로 줄었지만 적중률이 안 올랐으므로 점수 상승은 정확도가 아니다.
- 한계: 질문 문장으로 측정했고(개정 요청 아님), 100문항 중 10문항은 필수 근거가 (규정, 조)로 매핑되지 않아 제외(이유 미확인).

## 3. 추가한 기능
- **연쇄(2단계)**: 삭제로 근거가 사라진 조를 다시 인용하는 조를 낮은 우선순위로 최대 8장. 삭제 가능한 조 2,029개 중 67개에서 카드 생성. 번호만 밀리는 경우는 제외. 회귀 없음.
- **구조 밖 체크리스트**: 고친 부분에 결재·권한, 신분·징계, 금액·비율, 원칙·예외, 요건 범위 낱말이 있으면 「담당 부서 확인 필요」 카드(조당 최대 3). 「영향이 있다」가 아니라 「이 유형은 시스템이 확인하지 못한다」는 안내.
- **카드 설명(요약, 판정 아님)**: 카드마다 버튼으로 로컬 모델이 2~3문장으로 풀어 씀. 입력에 없는 조 번호·숫자·단정 표현은 검증에서 버림. 일부 문장이 어색하고 근거 종류를 되풀이함(프롬프트 개선 남음).

## 4. 복잡한 관계에 대한 분석 (우리 데이터)
- 인용 관계가 있는 조는 24%(491/2,028). 76%는 명시된 연결이 없다. 2단계까지 번지는 조 53개(평균 1.5곳, 최대 7). 다단계 인용 연쇄는 드물고, 어려움의 본체는 **명시되지 않은 의존**.
- 조문 유형 분포(의존이 아니라 가능성의 상한): 기관·직위 38%, 절차 28%, 숫자 20%, 단서 17%, 정의 9%, 법령 7%, 위임 4%.
- 암묵 연동의 실제 규모는 **측정하지 못했다**. 같은 날 여러 규정이 함께 개정된 이력으로 추정하려 했으나 원문의 조 단위 개정 표시가 31건뿐이라 표본이 안 나왔다. 현업의 과거 개정 사례가 필요하다.
- 치명적일 수 있는 미해결 유형(제 판단, 도메인 전문가 확인 전): 요건 변경이 다른 규정의 전제를 흔드는 경우, 권한·결재선 변경, 원칙-예외 어긋남, 법령 개정의 간접 영향, 경과조치. 가장 위험한 실패 방식은 「결과 없음」을 「영향 없음」으로 읽는 안심이며, 확인한 범위·구조 밖 체크리스트가 이를 줄인다.
- 문헌 확인(가벼운 검색, 본문 미확인): 법률·규제 분야에서 전문가가 관리하는 온톨로지·지식 그래프가 쓰이고, 그래프 구축 품질이 병목이며 하이브리드가 낫다는 연구가 있다. 「실무에서 흔하다」는 빈도는 확인하지 못했다.
