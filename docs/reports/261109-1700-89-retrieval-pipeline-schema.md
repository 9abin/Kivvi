# 261109-1700 검색 파이프라인 정리: 스키마 · 온톨로지 (한석희 DB 포함)

- 범위: 영향 후보를 찾는 검색 단계만. 판정(값 비교·충돌)과 순서 정렬은 경계만 적는다.
- 근거 코드: `src/regcheck/kg.py`(온톨로지), `collect.py`(후보 수집), `review_list.py`(노출), `linked_layer.py`(연결 표 층), `vectors.py`. 한석희 DB는 `domain_ontology.reviewed.db`를 열어 확인했다(규정 원문 `item.text`가 들어 있어 저장소에 넣지 않는다).
- 숫자는 모두 개발 수준이다(리포트 88, 같은 세션의 측정). 라벨은 AI 초안이고 현업 확인이 없다.

## 1. 한눈에

```
규정 원문(90건, 파싱) ──► 조항 관계 그래프(KG)  ──┐
        │                 (규칙으로 만든 구조 관계) │
        │                                           ├─► 후보 수집(collect) ─► 단계 분류 ─► 노출(split_view) ─► 사람
        ├─► 의미 색인(청크 임베딩 + BM25) ──────────┤        ▲
        │                                           │        │
        └─► (선택) 주제 연결 층 ◄── 한석희 도메인 DB ┘   변경 분석(수정 종류·시작 조)
                    (조·개념·속성 연결)
```

- 시작점은 수정 전 조항이다. 개정문을 읽어 수정 종류(값 변경 · 삭제 · 번호 이동 · 정의 변경 · 위임·법령 변경 · 내용 변경 · 표현 수정)를 정하고, 종류별로 따라갈 경로를 고른다.
- 후보를 지우지 않고 근거 경로와 단계만 붙인다. 결과는 확인 후보이고 충돌 판정이 아니다.

## 2. 우리 쪽: 조항 관계 그래프(KG) 스키마

### 2.1 노드 (클래스 11개, 상위 클래스 Unit 1개)

| 클래스 | 뜻 | 실제 수 |
|---|---|---|
| Regulation | 규정 문서 1건 | 90 |
| Article | 본문 조 | 2,051 |
| Supplement | 부칙의 조 | 540 |
| Annex | 별표 | 103 |
| Form | 별지 서식 | 316 |
| Term | 정의 조에서 정의된 용어(규정별) | 314 |
| Body | 위원회 이름 | 21 |
| Org | 직제규정의 조직 이름 | 6 |
| Law | 인용된 법령 | 95 |
| LawArticle | 조 번호까지 인용한 법령의 조 | 128 |
| Alias | 「이하 "B"라 한다」 약칭 | 34 |

상위 클래스 `Unit` = Article · Supplement · Annex · Form(조항 단위). 규정에는 위계(법령 > 정관 > 규정 > 지침)가 있다. 노드 합계 3,698.

### 2.2 관계 (21개, 엣지 13,511)

| 묶음 | 관계 | 만드는 방법 |
|---|---|---|
| 구조 | PART_OF, ARTICLE_OF | 파싱 |
| 인용 | CITES(인용·준용·예외), CITES_REG, CITES_LAW, CITES_LAW_ART | 인용 표(`amend.edge`) · 본문 법령 조 인용 |
| 정의·용어 | DEFINES, USES_TERM, ALIAS_OF | 정의 조 패턴, 용어 글자 일치(등장 60단위 이하), 약칭 정의 |
| 언급 | MENTIONS_TITLE, MENTIONS_STEM, MENTIONS_FORM, MENTIONS_BODY, MENTIONS_ORG | 제목·줄기·서식 이름·위원회·조직이 본문에 글자 그대로 나옴 |
| 같은 사항 | SAME_TITLE, SAME_VALUE, SHARED_ATTACH, SUPPLEMENTS | 제목 일치, 같은 대상어 + 같은 값, 같은 부속 공유, 규정–지침 짝 |
| 의심(규칙) | VALUE_DIFF, DEF_DIFF, STALE_CITE | 규칙 레지스트리(기한·정의 불일치, 이동 후 미반영) |

엣지 수가 많은 순서: USES_TERM 3,407 · MENTIONS_TITLE 3,311 · PART_OF 3,013 · CITES 960 · MENTIONS_STEM 633.

### 2.3 수정 종류별 따라갈 경로 (`change_paths`)

관계, 방향(in = 이 단위를 가리키는 쪽, out = 이 단위가 가리키는 쪽), 가중치로 정해져 있다. 예: 값 변경은 SAME_TITLE · CITES in · VALUE_DIFF · MENTIONS_TITLE in · SAME_VALUE · MENTIONS_FORM out · SHARED_ATTACH …, 삭제는 CITES in · STALE_CITE · MENTIONS_TITLE in …, 정의 변경은 USES_TERM(바뀐 용어만) · CITES in · DEF_DIFF …. 표현 수정은 그래프를 쓰지 않는다.

- 오늘 시험한 확장: 값 변경에 `CITES out` · `MENTIONS_TITLE out`을 더하면 한석희 120문항 후보 재현율 202→215/215(개발 수준), 후보 +3개/항목. 아직 기본값에 넣지 않았다(참고 단계로 들어갈 예정).

## 3. 한석희 쪽: 도메인 온톨로지 DB 스키마 (`domain_ontology.reviewed.db`)

| 테이블 | 행 수 | 역할 |
|---|---|---|
| document · article · item | 90 · 3,244 · 3,133 | 규정 문서 · 조 · 항(원문 `item.text` 포함) |
| concept | 44 | 개념(종류, 부모, 부모와의 관계) |
| concept_attr · concept_primary | 428 · 68 | 개념의 속성 · 개념의 대표 조 |
| edge_item_concept | 1,997 | 항 ↔ 개념 연결. rel = 정의 · 근거 · 언급, changed_from/to, decided_by |
| edge_attr | 2,533 | 연결이 다루는 속성(예: 기간 · 보수) |
| edge_head | 516 | 항의 상하위(자식 항 → 머리 항) |
| edge_rule_fact | 2,466 | 사실표: 연결(edge)마다 속성(attr) · 값(value) · 범위(scope) · 근거 항 · 인용 |
| review_evidence | 1,846 | 연결의 근거 인용 · 사유 · 검토 상태 · 모델 |
| source_binding | 3,133 | 항 ↔ 우리 코퍼스의 논리 항 id(logical_item_id · logical_article_id) · 원문 해시 |
| change_log | 1,892 | 연결 변경 이력 |

한석희 쪽 원칙: 「불일치는 간선 속성이 아니다. 같은 속성의 근거 항을 모아 비교한다」. 연결과 사실표는 사람이 만든 것이고, 이 DB의 가치는 조·개념·속성 연결과 값 사실이다.

## 4. 두 쪽을 잇는 방법

| 항목 | 우리 KG | 한석희 DB |
|---|---|---|
| 단위 | 조 · 부칙 조 · 별표 · 서식 (id `규정번호:조`) | 항(item) 단위, source_binding으로 우리 id에 연결 |
| 관계의 성격 | 구조·글자 기반 21종, 규칙으로 생성 | 개념·속성 기반, 사람 검토(decided_by) |
| 값 사실 | 없음(SAME_VALUE는 같은 값 일치만) | edge_rule_fact에 속성별 값 |
| 연결 방식 | — | `LinkLayer`(`linked_layer.py`)가 JSONL 연결 표를 읽어 `collect(leave=...)`에 꽂는다. 경로 이름 `<머리말>_ATTR`(같은 개념·같은 속성, 확인 권장) · `_UP`(개념 위계, 참고) · `_KIND`(기본 꺼짐) |

- 연결 표 형식: `{"item", "article", "concept", "rel", "attrs", "decided_by"}`와 첫 줄 meta(개념 위계). 규정 원문은 넣지 않는다(`scripts/extract_hyujik_links.py`).
- 후보 수집에서는 이 층의 이득이 작았다(오늘 DB 병합, 팀 보고서 모두). 쓸모는 판정 쪽 값 비교(`edge_rule_fact`)에서 확인됐다. 판정은 이 문서의 범위 밖이다.

## 5. 후보 수집 순서 (`collect`)

1. 변경 분석: 수정 종류, 시작 조(수정 전), 바뀐 말(old / new), 바뀐 용어.
2. 그래프 경로(`kg.impact`): 종류별 경로, 1홉. 번호 이동은 전이 규칙(2단계 조합)과 이동 범위 안 인용도 본다.
3. 문구 검색: 새 말 · 바뀌기 전 말(`OLD_PHRASE`) · 용어 핵심어(`TERM_CORE`) · 삭제된 조의 희귀 핵심어 · 약칭(`ALIAS`). 흔한 말은 문서 빈도 상한으로 거른다.
4. 주제 연결 층(선택): `LinkLayer` 등.
5. 의미 검색: 종류별 질의(제목 + 현행·개정 본문 등)를 BGE-m3 임베딩 + BM25(RRF 합산)로 찾아 상위 30. 점수는 낮게 둔다(0.2 이하).
6. 후보마다 근거 경로를 남기고 단계를 붙인다.

의미 색인은 청크 4,500개 + 부록·서식 959개(`out/kg/ext_emb.npy`). Qwen3-Embedding-4B 색인도 만들어 두었다(`RAG_EMB=q4b`, `IMPACT_EMB=q4b`). 시험에서 현재 구성(BGE-m3 + BM25) 대비 이득이 없어 기본값은 그대로다.

## 6. 단계와 노출

| 단계 | 경로 | 경로별 정밀도 |
|---|---|---|
| 확정급 | 번호·이름으로 직접 인용(CITES in, STALE_CITE, CITES_internal, CITES_REG:제목어, CITES_LAW_ART) | 인용받음 97% (개발 12문항) |
| 확인 권장 | 용어 사용, 같은 제목, 값 차이, 문구 검색, `_ATTR` | 용어 사용 88%, 제목 언급 39% |
| 참고 | 그 밖(HOP, 규정 인용 등) | 제목 줄기 14%, 조직 이름 3% |

- 노출(`split_view`): 기본 화면 = 의미 검색 상위 30 + 그래프 상위 20(소음 경로 제외). 새로 `tier_open`: 확정급 전부와 쓸모 있는 경로의 확인 권장 전부를 상한 없이 펼친다. 나머지는 접고 개수를 표시한다. 후보를 버리지 않는다.
- 정렬: 단계 먼저, 같은 단계에서는 근거 경로 계열 수, 점수.

## 7. 역할 경계와 열린 문제

| 역할 | 맡는 쪽 |
|---|---|
| 구조 관계(인용·정의·언급·이동·법령), 후보 수집, 단계 | 우리 파이프라인 |
| 조·개념·속성 연결, 항별 값 사실 | 한석희 DB (합의 후 사용) |
| 서식·표 한 줄·다른 서술의 값 추출 | 양쪽 모두 비어 있음 |
| 순서 정렬 | 판단 모델(우리), 가빈 PR #13(개발 집합 기준) |
| 판정, 최종 결정 | 사람 |

열린 문제
- 작성자 합의: DB는 원문이 들어 있어 그대로 저장소에 못 넣는다. 연결 표와 사실표만 따로 뽑아 합의한다.
- 서식·표 단위는 문맥이 없어 의미 검색이 못 닿는다. 소속 규정명 + 제목을 붙여 색인하는 보강이 후보.
- 소음 경로 목록은 잠정이다(한석희 세트에서는 CITES_REG가 정답 18쌍의 유일한 경로).
- 단계별 정밀도는 정답 밖 후보를 사람이 판정해야 처음 잴 수 있다.
- 합친 뒤 상한 · 가중치 · 리랭커 적용 범위는 새 문항(동결)으로 한 번에 정한다.
