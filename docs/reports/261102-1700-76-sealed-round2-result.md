## 원인 진단 (코드는 고치지 않고 본 것)

1. 값 변경 · 삭제 문항(I25~I28)은 RAG만으로도 정답이 모두 걸려 비겼다. 그래프가 이긴 곳은 정의 변경 I32(3 대 1)뿐.
2. **번호 이동 정답 4건을 모두 놓쳤다.** 정답이 이동 범위 *안*의 조(옮겨지며 내부 인용 번호가 바뀌는 조)인데, 후보 수집이 시작점(이동 범위)을 후보에서 제외한다. 설계 공백.
3. **확정급 정밀도 90%는 일반화되지 않았다.** 확정급 24개 중 18개가 정의 변경 I32의 용어 사용(`USES_TERM`)이고, 같은 지침 안의 조들이 용어를 쓰지만 라벨러는 영향 없음으로 봤다. 1차의 88%는 다른 규정에서 쓰는 경우가 대부분이었다. 인용받음(`CITES_in`)은 3개 중 2개 정답.
4. 수정 종류 자동 분류가 10건 중 2건 틀렸다(정의 변경 → 값 변경, 위임·법령 변경 → 내용 변경).
5. 법령 개정(I34 근로기준법 제2조, 정답 2건)은 시작 노드가 없어 평가에서 빠졌다. 1차 I22와 같은 구조적 공백. 포함하면 24/34(71%).
6. LLM 판단 P3는 개발 문항에서 유리하게 나왔을 가능성이 크다(예시가 개발 유형과 겹침). 정렬에 쓰면 오히려 정답을 잃는다 → 표시 · 근거 설명용으로만 쓰고 후보는 지우지 않는다.

## 결론 (말할 수 있는 것 / 없는 것)

- 말할 수 있다: 새 문항에서도 RAG보다 낮지 않았다(+6%p, 구간 0 이상). 영향 없음 문항에서 확정급 오경보는 없었다. 근거 문장 인용은 원문과 99% 일치.
- 말할 수 없다: "그래프가 RAG보다 크게 낫다"(1차 +33%p는 재현되지 않음), "확정급 정밀도 90%", "누락 없이". 문항 수가 적어 격차는 +6%p~+33%p 사이로 불확실하다.
- 이 문항들을 본 뒤 규칙을 고치면 2차는 **개발용으로 바뀐다.** 고친 효과를 말하려면 3차 새 문항이 필요하다 → [77](261102-1730-77-round3-prereg.md).
