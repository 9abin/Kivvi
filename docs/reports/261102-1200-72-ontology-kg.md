# 261102-1200 영향 점검용 온톨로지와 지식 그래프 (규칙 기반 1판)

- 관련: [67 마무리 범위](261030-1700-67-impact-check-scope.md), [68 평가셋 설계](261030-1800-68-impact-evalset-design.md), [71 평가셋 표](261102-1000-71-impact-evalset-table.md)
- 변경 범위: `src/regcheck/kg.py`, `scripts/build_kg.py`, `scripts/eval_kg_dev.py`, `tests/test_kg.py` 새로 만듦(미커밋). 출력은 `out/kg/`(git 제외 대상)

## 요약

규정 원문과 인용 표(`amend.edge`)에서 **규칙만으로** 노드 8종, 관계 9종의 지식 그래프를 만들었다(LLM 없음). 수정 종류(값 변경, 삭제, 번호 이동, 정의 변경, 위임·법령 변경, 표현 수정)마다 영향이 번지는 경로를 정해, 그 경로만 따라 확인 후보를 모은다. 개발 분할 5문항에서 정답 영향 68건 중 **46건(68%)이 후보에 들었고** 인용받음만 쓸 때(34%)의 두 배다. 다만 관계를 개발 문항을 보면서 골랐으므로 **낙관적 수치**이고, 봉인 분할은 열지 않았다. 충돌 판정이 아니라 확인 후보다.

선마다 만든 규칙(`method`)과 근거(`evidence`, 구조 검사에서 걸린 인용은 `suspect`)를 기록한다.

### 수정 종류별 영향 경로 (일반 틀)

| 수정 종류 | 따라가는 관계 |
|---|---|
| 값 변경 | `SAME_TITLE`, `CITES` 인용받음, `SUPPLEMENTS`, `CITES_REG`(낮은 우선) |
| 삭제 | `CITES` 인용받음, `CITES_REG`(낮은 우선) |
| 번호 이동 | `CITES` 인용받음. 시작 조는 개정문의 「제N조부터 제K조까지」로 정한 이동 범위 전체 |
| 정의 변경 | `USES_TERM`(개정문이 바꾸는 용어), `CITES` 인용받음 |
| 위임 · 법령 변경 | `CITES` 인용받음 · 인용함, `CITES_REG`, `SUPPLEMENTS`, `CITES_LAW` |
| 표현 수정 · 고립 수정 | 번지지 않음(후보 없음) |

수정 종류는 입력이다. 평가에서는 개정문 작성자가 붙인 값을 썼다.

## 4. 해석과 한계

- **개발 문항을 보고 관계를 골랐다.** `USES_TERM`은 I04, 이동 범위 확장은 I03을 본 뒤에 넣었다. 일반적인 규칙이지만 이 5문항에는 맞춰져 있다. **68%는 상한에 가까운 낙관 수치**이고, 일반화는 봉인 분할에서 확인해야 한다.
- **봉인 분할 16문항은 열지 않았다.** 규칙을 확정한 뒤 `scripts/eval_kg_dev.py --split 봉인 --yes-open-sealed`로 한 번만 연다.
- **정답이 사람 검토 전 초안이다.** 특히 I04의 24건은 모두 같은 이유(용어를 쓴다)로 붙어 있어서, 용어 사용만으로 영향이라고 볼 수 있는지 기준을 먼저 정해야 한다.
- 못 찾은 유형:
  - 용어로만 의존(「인사규정상 당연해직 사유」)하는 조와 열거 · 포괄 위임 → 같은 사항(개념, 면) 묶음이 필요하다. 규정문 파일(검색 팀 PR #10)을 받은 뒤 시험한다.
  - 같은 규정 안의 연관 조 · 별표 · 서식(I05).
  - 별표 · 서식이 규정 이름만으로 연결된 경우.
- `USES_TERM`은 같은 글자가 다른 뜻으로 쓰인 조도 후보로 올린다(오경보 가능). 후보가 문항당 최대 25개로 많은 점도 정밀도 쪽 약점이다.
- `SUPPLEMENTS`는 이름 줄기가 같은 4쌍뿐이다(인사규정 ↔ 직원채용지침처럼 이름이 다른 짝은 못 잡음).
- 이 결과는 충돌 탐지 성능이 아니다. 전문가 확인(UAT)은 향후 과제다.
