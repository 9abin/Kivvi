## 1. 실험 구성

| | LLM 9B (`qwen3.5:9b`) | LLM 30B (`qwen3:30b-a3b-instruct-2507-q4_K_M`) |
|---|---|---|
| **임베딩 bge-m3** | 이민형 | 박형건 |
| **임베딩 Qwen3-Embedding-0.6B** | 김가빈 | 한석희 |

- 각자 리랭커(없음 · `bge-reranker-v2-m3`) × 선택(끔 · 켬)을 돌렸다. `Qwen3-Reranker-4B`는 김가빈 · 박형건만.
- 박형건 확장: `Qwen3-Embedding-4B`(Ollama `4b-q8_0`, 2,560차원) + 30B, 리랭커 없음 · 선택 끔.
- LLM은 바꿔 쓰기와 선택에 쓰인다. **선택 끔** = 리랭크(또는 RRF) 순서 상위 k개를 그대로, **선택 켬** = 상위 16개 중 LLM이 k개를 고름.
- 주지표: 최종 근거 필수 Recall@10 (조 10개 + 인용 복구 후).
- 장비: 4명 모두 RTX 4070 Laptop 8GB, RAM 약 34GB.

- **임베딩 4B + bge + 30B 선택 켬이 지금까지 최고**(@10 0.889, @8 0.881, 전부 확보 87/99)다. bge-m3 대비 이득은 리랭커를 거쳐도 유지된다(유의). Qwen3-0.6B 대비 이득은 작고 유의하지 않다.
- 임베딩이 4B면 **리랭커와 선택의 추가 이득이 작다**(+0.8, +2.4%p). 후보 단계 상한(0.929)이 높아 뒤 단계가 더할 것이 적다.
- **시간(재측정)**: 처음 결과의 검색 합계(선택 끔 6.2초, 켬 11.0초)는 측정 오류였다. 원인은 Ollama 임베딩 호출 주소가 `http://localhost:11434`라서 윈도우가 IPv6(`::1`)를 먼저 시도했다가 IPv4로 넘어가며 **호출마다 약 2초**가 붙은 것이다(`localhost` 2.07~2.30초 대 `127.0.0.1` 0.06~0.10초, 같은 모델 같은 GPU). 임베딩 호출은 요청마다 새 연결을 열어 매번 지연된다. 주소를 `127.0.0.1`로 바꿔 다시 재면 질문 임베딩 0.11초, **검색 합계 p50 선택 끔 1.69초(p95 2.35), 켬 6.57초(p95 7.80)** 이다. 재현율은 같다(0.865 / 0.889). 확장 설정(임베딩 4B · 리랭커 없음)의 5.8초도 같은 원인이라 실제는 약 1.4초로 추정한다(재측정 안 함). LLM 호출(바꿔 쓰기 · 선택)은 연결을 재사용해 영향이 없는 것으로 보인다(9B 선택 호출 1.4초가 근거).

## 4. 결론

**두 칸 이상에서 재현된 것**
1. **리랭커가 없으면 LLM 크기가 결정적이다.** 9B → 30B가 +7.1%p(bge-m3), +10.3%p(Qwen3-0.6B)로 둘 다 유의하다. 30B의 바꿔 쓰기가 후보를 넓히기 때문이다(바꿔 쓰기 이득 30B +3~4%p, 9B 0~1%p).
2. **bge 리랭커가 있고 선택을 끄면 LLM 크기는 상관없다.** 두 임베딩 모두 +0.8%p. 리랭커가 약한 바꿔 쓰기를 만회한다.
3. **Qwen3 리랭커 4B는 1위 정확도를 올리고 재현율은 거의 그대로다.** Hit@1 +10~12, @10 +0~1.6%p, 검색 시간 32~45초.
4. **9B는 선택 단계 지시(k개 고르기)를 지키지 못한다.** 개수 위반 63~71% 대 30B 3~7%.
5. **Qwen3-Embedding-4B가 가장 큰 단일 개선이다.** 리랭커 없는 같은 조건에서 bge-m3 대비 +7.9%p, Qwen3-0.6B 대비 +7.1%p로 유의하고, **리랭커 · 선택 없이도** 한석희 최고 조합과 차이가 없다. 후보 30개 안 상한이 0.929로 가장 높다.

**조건부인 것**
6. Qwen3-Embedding-0.6B의 효과는 작고 일관되지 않다(유의한 칸은 30B · bge · 선택 켬 하나, 같은 조건 9B에서는 +0.8%p).
7. 선택(켬)의 이득은 구성마다 -0.8~+5%p로 다르다.

## 6. 한계
- 개발용 99문항 하나로 20개 이상의 효과를 비교했다. 상위 조합은 시험용(holdout)으로 1회 확인해야 한다.
- 검색 단계 지표다. 답변 정답률(LLM 채점, RAGAS)은 보지 않았다.
- 같은 PC에서 반복하면 값이 완전히 같다(김가빈 `--fresh` 반복으로 확인). 불확실성은 질문 표본에서만 온다.
- 한석희 결과만 평가 파일 해시가 다르다(`a49ba295`, 나머지 `3d50e5a4`). 줄바꿈 차이로 추정되며 내용은 같다(질문 · 근거 수와 기준선 값 동일). 조합 보고 도구로는 아직 합쳐지지 않아, 위 수치는 결과 파일의 질문별 값으로 직접 계산했다.
- 코드 커밋이 사람마다 조금 다르다(`c11c97b`, `1610882+수정`, `1ec0737`, `2ab8564`). 재현율 계산에는 영향이 없지만 바꿔 쓰기 점검(`invented`) 정의가 바뀌어 그 값은 사람 간 비교하지 않는다.
- Qwen3-Embedding-4B는 Ollama 8비트 양자화본이고 2,560차원이라 운영 DB(1,024차원 고정)에 그대로 넣을 수 없다. GPU 메모리 6.2GB를 차지한다.
- Qwen3 리랭커 4B는 8GB GPU에서 일부 층을 CPU에 두어 느리다(질문당 24~34초).
