## 요약
합의안대로 가빈 DB(로컬 사본 reg-db)에 `amend` 스키마를 만들고 우리 산출물을 적재했다. 항·호·목 7,388 (가빈 청크 대응 7,324), 조문 사본 2,051, 관계 1,848, 점검 결과 271 (가빈 청크 연결 256), 개정안 3·영향 47.
역할 4개로 권한을 실제로 걸고 시험했다: 파이프라인·편집자는 가빈 표에 못 쓰고, 결정 기록은 관리자도 고치거나 지울 수 없다. 합의 전이라 이 PC 사본에만 쓴다(스크립트가 localhost 외에는 거부).

## 주요 결정
| 결정 | 이유 | 대안 |
|---|---|---|
| public 참조를 **외래키로 걸지 않음** (`chunk_id` 칸 + 확인 뷰 `v_chunk_unmatched`) | 가빈이 덤프를 `--clean`으로 다시 적재하면 `public.chunks`가 지워졌다 생긴다. 외래키가 있으면 그 적재가 막히거나 우리 표가 같이 지워짐 | 외래키(합의안 초안): 담당 경계를 넘어 서로의 적재를 막음 |
| 역할 4개: `chatbot_ro`·`editor`·`amend_builder`·`loader` | 합의안의 3개에 파이프라인용 `amend_builder`를 분리. 편집자는 관련 조항 표·점검 결과(기계 산출물)를 못 고치고, 파이프라인은 개정안 상태를 못 바꾸게 하는 편이 분명 | `editor` 하나로 적재까지: 화면에서 파생 데이터를 고칠 수 있게 됨 |
| 적재는 `SET ROLE amend_builder`로 | 코드 실수로 public에 쓰려 해도 DB가 거부 (시험으로 확인) | 코드 규칙만: 보장 안 됨 |
| `decision_log` 덧붙이기만: 권한(INSERT만) + 트리거(UPDATE·DELETE·TRUNCATE 거부) | 사람 결정은 다시 만들 수 없다. 관리자 계정 실수도 막음 | 권한만: 소유자는 지울 수 있음 |
| 항 키에 `occ`(출현 순번) | 원문 항 번호 중복(⑤⑤)·같은 조 번호 두 번(경영공시 관리지침 제12조)이 있어 ID만으로는 겹침. 원문을 바꾸지 않고 담음 | ID에 접미어: 관련 조항 표·점검 결과의 ID와 어긋남 |
| 부칙·별표·별지 → 가빈 청크 규칙 (`unit_chunk`): 부칙·별지는 규정별 한 덩어리, 별표는 번호별 첫 조각 | 가빈 청크 구조 그대로. 점검 결과 271 중 256이 가빈 청크와 이어짐 (남은 15: 가빈 쪽 내규관리규정 누락 13, 원문 중복 조 1, 가빈에 별지 없음 1) | 본문만 연결: 별표·별지 점검 결과가 챗봇 화면에 못 붙음 |
| 인용 조회 뷰는 인용 1건 = 1행, 대상 청크는 배열 | 인용은 대개 조 단위라 항 청크마다 복제하면 13건이 65행이 됨 (처음 버전에서 발생) | 항마다 1행: 건수 왜곡 |
| 뷰는 지우고 다시 만듦 | `CREATE OR REPLACE VIEW`는 칸 이름이 바뀌면 실패. 스키마 파일을 다시 실행해도 되게 | 마이그레이션 도구: PoC에 과함 |

## 변경 사항
- 표: `chunk_detail`(항·호·목 + 가빈 `chunk_id`·대응 방식), `article_version`(공포 시점별 사본, 지금은 현행본 1벌), `edge`, `finding`(`review_key` = 사람 결정 고정 키), `changeset`(상태 초안·검토·승인·공포·기각, `origin_chunk`), `impact`, `decision_log`
- 뷰: `v_decision_state`(키별 현재 상태), `v_inbound`(이 조를 인용하는 곳 — 예: 직제규정 제7조 13건·7개 규정), `v_chunk_open_change`(챗봇 "개정 검토 중" 배지, 지금 S01~S03 43개 청크), `v_chunk_unmatched`(가빈 청크 대응 확인, 지금 36 = 가빈 내규관리규정 누락분)
- 권한 시험 (실제 실행): 파이프라인·편집자의 가빈 표 쓰기 거부, 편집자의 관련 조항 표 쓰기 거부, 편집자의 결정 고치기 거부, 챗봇의 점검 결과 읽기 거부(배지 뷰만 허용), 관리자의 결정 지우기 트리거로 거부
- 파서: 표 칸 「40.0%」를 40호로 읽던 문제(근무평정시행지침 5개 조), 개정 표시의 연도 「2019.09.26.]」를 2019호로 읽던 문제(정보보안관리지침 4개 조) 수정 — 호 번호 마침표 바로 뒤가 숫자면 호로 보지 않음. 채점 43/46·점검 결과 271 그대로, 벡터 재생성(4,496 청크)
- 테스트: `test_amend_db.py` (대응 규칙·단위 청크·날짜·중복 순번, DB 권한은 `REGCHECK_DB_TESTS=1`일 때). 전체 78 + DB 5 통과
