## 요약
에이전트는 챗봇이 아니라 **사건 기반 점검 파이프라인 + 검토 화면**이다. 내규관리규정의 개정 절차(제20~25조)에 끼워 넣는다.
수정은 에이전트가 **초안 사본에 신·구조문대비표**로 만들고 사람이 변경 단위로 수락·거절한다. 원문은 개정 절차로만 바뀐다.
PoC는 "설치 첫날" 시나리오 하나를 끝까지 동작시키는 것으로 줄인다.

## 벤치마킹 (실제 확인된 사례)
외부 제안 자료의 사례 4건(국방부·방사청 그래프 검증, 가스공사+BHSN Graph RAG, Ironclad·Loomšta, 금감원·은행)은 근거를 찾지 못해 쓰지 않는다. 가스공사 '업무 Mate'는 실재하나 규정 질의응답 도구다.

| 사례 | 확인 내용 | 가져온 것 |
|---|---|---|
| 강남구 자치법규 스마트 정비시스템 (2026.2) | 법제처 API 매일 수집 → 구 자치법규 비교 → '검토 필요' 표시, 부서 검토 의견·변경 이력, AI는 반복 입안 오류 패턴으로 입안점검표 | 검토 의견 이력, 입안점검표 |
| 강동구 자치법규 변경 알리미 (2026.3) | 법제처 개정 정보 ↔ 자치법규 매칭·영향도, 담당 부서·입법 총괄부서 역할별 화면, 검토 완료일·담당자 표출 | 역할별 화면, 현행화 현황판 |

## 주요 결정
| 결정 | 이유 | 대안 |
|---|---|---|
| 주 화면은 검토 화면, 챗봇 아님 | 출력이 수십~수백 건 목록이고 건별 처리·이력이 필요. 평가에 재현성 필요. 챗봇은 김가빈 담당 | 대화형 에이전트 |
| 대화 기능은 "왜 걸렸나" 설명, 변경안 자연어 입력 두 곳만 | 근거 범위 안의 보조 기능 | 전면 대화형 |
| 4개 계기: 법령 반입 / 내규안 입안 / 개정 시행 / 정기 정비 | 제20~25조 절차에 맞춤. 가장 가치가 큰 지점은 제21조 조정 협의 자료 | 별도 절차 신설 |
| 우선순위 3단계 (높음: 법령 미반영·근거 소멸 / 중간: 충돌·용어·오인용 / 낮음: 명칭·오타) | 제7조① 효력 상실 위험, 제8조③·제20조③3호로 낮은 건은 직권 일괄 정비 가능 | 단일 등급 |
| finding 상태: 신규·배분·검토 중·승인·기각·오탐·판단 불가·해소 + 이력 | 벤치마킹, 기준선 재발 방지 | 원본 기획 3상태 |
| finding에 원인 묶음ID | 번호 밀림 하나가 여러 오인용을 만듦. 초기 도입 부담을 원인 단위로 줄임 | 건 단위 처리 |
| 수정은 초안 사본에 신·구조문대비표로, 변경 단위 수락·거절 | 내규안(제20조) 작성 자료로 바로 쓰임. 원문 불변이라 자동 반영 금지 원칙과 충돌 없음 | 사람이 직접 작성 / 원문 자동 수정 |
| 유형별 수정 범위 차등 (아래 표) | 기계적 수정만 문안, 판단이 필요한 건 선택지만 | 모든 유형 문안 생성 |
| 초기 도입 4단계: 보정 → 묶음 정리 → 단계적 배분 → 기준선 고정 | 오탐투성이 첫 목록은 현업 신뢰를 잃음. 1주차 21건 검토가 수작업 시범 운영에 해당 | 전수 결과 즉시 배분 |
| PoC는 "설치 첫날" 시나리오 하나로 축소 | 코드 없음, 남은 기간 약 2주, 법률 DB 의존 | 운영안 전체 구현 |

## 유형별 수정 범위
| 유형 | 에이전트 | 사람 |
|---|---|---|
| 오타, 구 명칭, 규정 명칭 불일치, 대상이 확실한 번호 오인용 | 변경 표시 문안 | 근거 보고 수락·거절, 같은 유형 묶음 처리 |
| 법령 개정 미반영 (번호만 바뀜) | 새 법조문 번호로 문안 | 확인 후 수락 |
| 법령 개정 미반영 (내용 바뀜), 법령 불일치 | 법조문 신구와 규정 조문 나란히 표시, 문안 없음 | 직접 작성 |
| 충돌, 용어 정의 불일치 | 양쪽 조문 + 선택지별 문안(A안·B안), 선택 안 함 | 선택 또는 작성 |
| 판단 불가 | 수정 없음, 확인 질의서 | 소관 부서 답변 |

자동 수락 습관 방지: 체크 미리 켜지 않음, 기계적 수정 외에는 근거 화면 연 뒤에만 수락, 일괄 수락 건 표본 재확인.
