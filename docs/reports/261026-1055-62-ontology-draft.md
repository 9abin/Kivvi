## 요약
지금의 규정 그래프(`amend.edge` 인용 1,863줄 + `chunk_detail` + 법률 DB)를 「온톨로지」로 정리한 초안이다. **현재 구현된 것**과 **전문가와 정해야 하는 것**을 나눠 적었다.
관계 종류 4가지(인용 · 별표·별지 인용 · 문서 인용·위임 · 법령 인용)는 이미 있고, 충돌 · 보완 · 예외 · 용어 대응 · 조건은 아직 없다. 의미 관계는 자동 판정하지 않고 **자동 후보 → 의심 → 확인됨**으로 전문가가 확정한다.
이 초안은 도메인 전문가 검수 전이며, 효과를 측정한 것이 아니다.

## 1. 원칙
- **범위**: 위계가 분명한 규정 · 별표에만 그래프를 쓴다 (규정 90건). 줄글 · 일반 문서는 벡터 검색에 둔다.
- **자동 추출은 규칙으로, 의미 판단은 사람이**: 인용은 규칙으로 뽑고, 충돌 · 보완 같은 관계는 전문가가 정의하고 확정한다 (법적 판단은 하지 않는다 — [05 작업 규칙 §3](../archive/plans/05-working-agreement.md)).
- **온톨로지 = 설계도, 그래프 = 그 설계도로 채운 실제 데이터**. 설계도는 천천히 바뀌고(전문가 합의), 데이터는 개정마다 늘어난다.
- **검색 우선순위**: Recall이 먼저. 관계를 늘려 후보를 넓히고, 비용은 그다음에 본다.

## 3. 관계 (엣지)

### 3.1 현재 구현 — `amend.edge` (1,863줄, 확실 1,723 · 후보 140)

| 관계 (`kind`) | 방향 (출발 → 대상) | 건수 | 비고 |
|---|---|---|---|
| 법령 인용 | 항 → 법령 | 651 | 법률 DB와 대조, 최근 개정 표시(조문변경여부) |
| 인용 | 항 → 조 | 561 | 같은 규정 · 다른 규정 모두 |
| 별표 · 별지 인용 | 항 → 별표 · 별지 | 441 | 별표 안 인용도 출발점(별표 116 · 별지 182) |
| 문서 인용 · 위임 | 항 → 규정 | 210 | 「인사규정에 따른다」 같은 규정 단위 인용 · 위임 (**둘이 아직 한 종류로 묶임**) |

구조 관계(포함 · 소속)는 키 규칙으로 이미 표현된다: 규정 ⊃ 조 ⊃ 항, 조 ↔ 개정본.

점검 상태 (`check_status`, 어휘는 이미 있음): `ok` 1,107 · `law_pending` 599 · `external_rule` 52 · `unknown_regulation` 23 · `missing_article` 23 · `addendum_history` 23 · `title_mismatch` 10 · `missing_appendix` 9 · `missing_item` 8 · `missing_chapter` 4.

### 3.2 제안 — 전문가와 정의할 관계

| 관계 | 뜻 | 예 (설계 예시) | 판정 |
|---|---|---|---|
| `delegates_to` 위임 | 상위가 세부를 하위에 맡김 (현재 「문서 인용 · 위임」에서 분리) | 취업규칙 제43조 ③ → 인사규정 | 규칙 + 확인 |
| `equivalent_term` 용어 대응 | 말이 달라도 같은 업무 | 영수증 분실 ≈ 카드매출전표 → 법인카드 사용지침 제12조 ① | 전문가 |
| `same_topic` 같은 주제 | 같은 업무를 다룸 | 출장 정산: 복무규정 · 여비규정 | 유사도 후보 + 확인 |
| `value_differs` 값 불일치 | 같은 주제인데 값이 다름 | 육아휴직 분할: 취업규칙 제43조 3회 ≠ 인사규정 제30조 2회 | 규칙(값 비교) |
| `conflicts_with` 충돌 의심 | 표현이 달라 의미로 이어야 충돌로 보임 | 복무규정 「14일 이내」 ⇄ 여비규정 「지체 없이」 · 제14조 「정액」 ⇄ 별표 1 「실비」 | **전문가가 확정** (자동 판정 안 함) |
| `exception_of` 예외 | 단서 · 예외 조항 | 「다만 …」 조항 → 본칙 | 규칙 + 확인 |
| `supersedes` 대체 | 번호 이동 · 개정으로 바뀐 조 | 급여규정 제21조 → 제22조 (성과급) | 규칙(개정 이력) |
| `basis_law` 법령 근거 | 조문이 근거로 삼는 법령 조 | 규정 → 법령 조 (현재 「법령 인용」을 근거 / 단순 언급으로 구분) | 규칙 + 확인 |

## 6. 거버넌스 (지속 유지보수는 그래프와 별개의 문제)
- **정의**: 클래스 · 관계 어휘는 도메인 담당자와 개발자가 함께 정하고, 바꾸면 버전을 올린다 (v0 → v1).
- **확정**: 제안 관계는 `자동 후보 → 의심 → 확인됨`으로만 올라가고, 결정은 지우거나 고치지 않고 **덧붙이기**만 한다.
- **개정 시**: 규정이 바뀌면 영향 점검을 다시 돌려 후보를 갱신하고, 법률 DB가 새 판이 되면 변경 감시를 돌린다.
- **범위 관리**: 줄글 · 일반 문서는 그래프에 넣지 않는다. 쪼개는 단위는 조 · 항 · 별표까지.

## 7. 단계

| 단계 | 내용 | 비고 |
|---|---|---|
| v0 (지금) | 인용 4종 + 점검 상태 + 개정본 시점 | 구현됨 |
| v1 | 「문서 인용 · 위임」을 위임과 문서 인용으로 분리, `exception_of` · `supersedes` 규칙 추출, 법령 인용의 근거 / 언급 구분 | 규칙 기반, 전문가 확인 소량 |
| v2 | 용어 사전(`equivalent_term`)과 주제 연결(`same_topic`)을 전문가와 시작 (평가에서 놓친 질문부터) | 검색 후보 확장에 연결 |
| v3 | 조건 · 값 노드(대상 · 횟수 · 금액)와 `conflicts_with` 확정 | 충돌 판정은 사람 |
| 평가 | Recall 우선. 관계를 넣기 전후로 **필수 근거 Recall**과 **오류 탐지 Recall**을 비교 | 현재 기준: 검색 Recall@10 0.87~0.905, 오류 탐지 43/46 |

## 8. 한계 · 주의
- 전문가 검수 전의 초안이다. 3.2의 관계는 **설계 예시**이고 효과를 측정하지 않았다.
- 자동 그래프화는 어렵다 (한국어 조사 · 표현 차이). 의미 관계는 규칙만으로 만들지 않는다.
- 인용 관계만으로 질문 답변 검색을 넓힌 효과는 작았다 (리포트 39: 전체 Recall +2~4%p 상한). 그래프의 주된 가치는 **오류 탐지**에 있다.
- 값 · 건수는 `out/relations/relations.jsonl`(1,863줄) 기준이다. DB는 1,884줄이어서 21줄 차이가 있다.
