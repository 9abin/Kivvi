## 요약

마무리 범위를 「인용·위임·법령 구조 + 휴직·휴가 개념 층」으로 줄이고, 기존 RAG와 같은 입력 예산에서 비교한다. 방식은 결정적 파이프라인(코드가 열거, LLM은 설명·초안만, 사람이 확정)이고 에이전트는 넣지 않는다. 충돌 탐지 성능은 주장하지 않는다(전문가 확인 0건).

## 1. 이름과 주장

- 이름: 「규정 인용·개념 그래프 기반 영향 점검 시스템(LLM 보조)」. 「AI 에이전트」「그래프 RAG」는 쓰지 않는다.
- 쓸 수 있는 말: 영향 후보를 자동으로 모은다. 선이 있는 곳은 빠짐없이 나열한다. 휴가·휴직 범위에서 정답 조 recall이 기존 대비 X.
- 쓸 수 없는 말: 충돌을 탐지한다/판정한다. 정밀도. 「누락 없이」.
- 이유: 규칙 · 코드가 핵심이라 「AI 시스템」으로 부르면 과장이고, 같은 입력에 같은 결과가 나오고 설명되고 평가된다는 점이 법무·규정 점검의 장점이다.

## 3. 워크플로 (에이전트 아님)

1. 개정안을 받아 바뀐 조항을 찾는다 (코드)
2. 역방향 영향 범위, (종류, attr) 묶음, 규칙 후보를 모은다 (코드, 전체 열거)
3. 후보마다 설명 · 확인할 것을 쓴다 (LLM, 근거 문장은 원문 부분 문자열로 검증)
4. 영향받는 조항의 참고 수정 문안을 쓴다 (LLM)
5. 담당자가 확인한다 (결정 기록)

LLM은 3, 4단계에서 한 번씩만 부른다. 경로를 고르지 않으므로 도구 호출 루프 · 재시도 · 상태 관리가 필요 없다. 에이전트형 탐색은 확장 과제이며, 하게 되면 호출 기록과 미호출 도구 표시를 넣는다.

## 4. 관련 연구 (확인한 것만)

LLM과 알고리즘 결합 | 본문 확인(261030). 3단계: ① LLM이 요구사항을 의무·허용·금지 + 전제조건 + 유효기간으로 형식화 ② 코드가 두 버전의 원자 변경 연산(L1~L4)을 계산 ③ LLM이 프로세스 모델에 대한 영향(비준수/과준수)과 이유를 판정. 평가는 3개 데이터셋(요구사항 36, 변경 연산 26, 편차 25), 정답은 저자 1인 작성 + 외부 전문가 2인 대조, 5회 반복. 단계별 F1 0.80~1.00 이지만 표본이 작다. 대상은 업무 프로세스 모델이지 다른 규정이 아니고, 변경된 요구사항 쌍은 이미 안다고 가정한다. 규칙·알고리즘과 LLM의 역할 분리 방향과 단계별 평가 방식을 참고 |
| Abualhaija 외, AI-enabled Regulatory Change Analysis of Legal Requirements, IEEE RE 2024, 5–17 (10.1109/RE59067.2024.00012) | 금융 규제 4건에서 변경 분류 F1 90.5%(텍스트), 90.8%·83.7%(의미 · 해석) | 변경 분류 성능이고 영향받는 다른 규정을 찾는 recall이 아니다 |
| de Martim, SAT-Graph RAG, arXiv 2505.00039 (「A Structural, Temporal, and Deterministic Approach」) | 조항 버전 · 유효 시점 모델링, 시점별 조회 · 계층 영향 분석, 브라질 헌법 사례 연구. 후속(arXiv 2510.06002)은 확률적 탐색과 결정적 조회를 분리하는 Action API | 시점 모델링과 결정적 조회 분리를 참고. 충돌 탐지 성능 입증은 아님. 용어가 「그래프 RAG」라 우리 표현 정책과는 따로 취급 |

Robaldo 외, Compliance checking on first-order knowledge with conflicting and compensatory norms, *AI and Law* 32 (2024) 505–555 (본문 확인 261030): 가상의 라이선스 계약 8개 규범(금지 3, 허용 3, 의무 2)을 SHACL · ASP · DLV · PROLEG · Arg2P · SPINdle에 형식화해 같은 상태가 준수인지 판정하는 속도와 설명 가능성을 비교한다. 여기서 「충돌」은 일반 규범과 예외 규범의 우선 관계(overrides)로 해소되는 설계된 충돌이고, 규정 간 모순 탐지나 개정 영향 분석이 아니다. 규범 추출도 범위 밖으로 가정한다. 참고할 점: 일반 규범 ↔ 예외 규범을 우선 관계로 두는 모델, 우선 관계가 본문에 명시되지 않는 경우가 있어 저자가 직접 보태야 했다는 관찰(Article 4b), 속도가 빠른 선언형(ASP)은 설명이 어렵고 설명 가능한 것(PROLEG, Arg2P)은 느리다는 비교.

미확인(원문 확인 뒤 사용): AI Act 의무 추출 지식 그래프 논문(2026)의 수치, CUBE · LexisNexis · Thomson Reuters 제품 설명, 국가법령정보센터 기능. 외부 글에서 가져온 링크는 추적 파라미터(`utm_source`)를 지우고 DOI · 논문 주소로 쓴다.

관련 연구가 있다는 것은 문제 설정과 역할 분리가 같은 방향이라는 근거이지, 우리 방법이 검증됐다는 근거가 아니다.

## 5. 평가

기존 RAG 대비 비교. 정답 근거는 구조화 배정과 분리한다(배정이 정답이 되면 누수).

| 항목 | 방법 |
|---|---|
| 층 | 정답 조 후보 recall / LLM 입력 포함 / 역방향 영향 범위(변경안 시나리오 대비) |
| 통계 | 작업 단위 부트스트랩 95% 구간 + 이긴 · 진 작업 수 (`metrics.paired_diff_cluster`, `scripts/compare_runs.py`) |
| 공정성 | 같은 입력 예산의 구조 그래프 대조군. 입력 글자 수 열 함께 보고 (확정 조합은 기준 대비 약 2.6배) |
| 범위 | 개념 층이 있는 휴가 · 휴직 질문과 없는 질문을 나눠 보고 |
| 사례 | 육아휴직 분할 쌍(인사규정 제30조 제2항 ↔ 취업규칙 제43조 제2항): 기존 RAG는 한 입력에 올리는지, 개념 층은 올리는지. 통계가 아니라 사례 |
| 비용 | 휴가 구조화에서 모델 초안 수정률 · 걸린 시간(전문가 필요 비용) |
| 주의 | 이 평가는 탐지 정밀도가 아니다. 전문가 확인(UAT)은 향후 과제 |

현재 알려진 수치: r3 기존 → 확정 16k +0.085 [0.009, 0.189], v4 +0.105 [0.044, 0.162]. 후보@50 단계에서는 확정 조합이 −4(작업 3개 열세)로 원인 미확인.
