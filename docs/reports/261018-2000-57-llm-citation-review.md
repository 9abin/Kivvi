# 261018-2000 엉뚱한 조 인용을 LLM이 잡는가 — 규칙 대 로컬 7B · 30B 대 API, 그리고 KVIC 전체 검토

- 관련: [36 오류 주입](261014-1121-36-agent-eval-set.md) 후속 2(「다른 조로 잘못 인용」 규칙 약 18%), [45 옮겨 간 곳 찾기](261015-1700-45-relocate.md), [51](261016-0100-51-independent-eval.md)
- 변경 범위: `scripts/eval_inject_llm.py`(새로, 짝 시험 · 판정형/선택형), `scripts/llm_cite_review.py`(새로, 전체 검토). 에이전트 본체는 아직 바꾸지 않음
- 외부 전송: API(gpt-5.6-luna)에 공개 규정(ALIO) 문장만 보냄. 평가 목적

## 요약
규칙(설명구 + 리랭커)은 「있는 조인데 엉뚱한 조를 가리키는 인용」을 10~15%만 잡는다(설명구가 없는 인용은 검사도 못 함). **LLM에게 대상 규정의 조 목록을 주고 「[인용] 자리에 가장 알맞은 조」를 고르게 하면(선택형), API는 주입한 오류를 98~100% 잡고 맞는 인용의 20%를 다르게 고른다.** 로컬 30B는 95~100% / 32~35%, 로컬 7B는 구분 능력이 없다. KVIC 본문 조 인용 376개 전체에 API 선택형을 돌리면 후보 79개(21%), **정답 원장의 실제 오류 15건 중 13건(87%)** 을 잡고, 원장에 없던 실제 오류로 보이는 것도 12~15건 나온다.

## 1. 오류 주입 짝 시험 (같은 인용: 원래 조 / 같은 규정의 먼 조로 바꿈, 60쌍, 표본은 설명구 유무와 관계없이 조 인용 전체)
| 방식 | 시드 1 (개발) 잡음 / 오탐 | 시드 2 (시험) 잡음 / 오탐 |
|---|---|---|
| 규칙 (설명구 + 리랭커) | 15% / 8% (검사 못 함 92/120) | 10% / 0% (검사 못 함 106/120) |
| 로컬 qwen2.5:7b, 판정형 v1 | 93% / 72% | - |
| 로컬 30B, 판정형 v1 | 68% / 32% | - |
| API luna, 판정형 v1 | 95% / 30% | - |
| 로컬 30B, 판정형 v2 | 73% / 17% | 82% / 28% |
| API luna, 판정형 v2 | 45% / 3% | 53% / 10% |
| **로컬 30B, 선택형** | **100% / 32%** | **95% / 35%** |
| **API luna, 선택형** | **100% / 20%** | **98% / 20%** |

- 판정형: 「이 후보 조가 [인용] 자리에 맞나」를 하나씩 묻는다. v1은 「인용한 조가 문장 내용을 직접 정해야 맞음」으로 읽어 오탐이 많았고(「[인용]에 따라 인수한 기록물」 → 이관 절차 조를 「배치를 정하지 않는다」며 틀림), v2는 「그 조에 나오는 대상 · 절차를 가리키면 맞음」으로 넓혔더니 오탐은 줄고 놓침이 늘었다. 같은 규정의 조들은 서로 비슷해 하나씩 보면 흔들린다
- 선택형: 문장과 대상 규정의 조 목록(제목 + 앞부분 90자)을 함께 주고 가장 알맞은 조(와 둘째 후보)를 고르게 한다. 고른 조가 인용한 조와 다르면 후보. 비교 대상을 다 보여 주므로 구분이 낫고, 짝 하나에 호출 한 번이라 비용도 절반
- 시간: 선택형 호출 한 번 API 3.1초, 로컬 30B 7.0초(이 PC)
- **선택형의 「오탐」 24건(API, 두 시드)을 읽으니 약 10건은 원래 인용이 실제로 틀린 것**이었다(예: 성과급지급지침 「급여규정 제21조(자녀수당)에 의하여 … 성과급」 → 고른 조 제22조(성과급). 정답 원장 G01, 과거 재현 시연의 그 사례). 진짜 오탐은 약 10%

## 2. KVIC 본문 조 인용 전체 (376개, API 선택형, 4개 동시 호출 291초)
- 후보 79개(21%), 같은 문장 중복을 빼면 76개 → `out/llm_cite_review/candidates_api.csv`(판정 칸 비워 둠, git 제외)
- **정답 원장 「인용_대상불일치」(본문) 15건 중 13건 잡음(87%).** 놓친 2건: T066-4(감사지침 제17조 → 제4조), C003(제26조 → 제19조제2항)
- 원장 밖 후보 66건을 읽은 1차 분류(박형건 측 Claude, 확정 아님)

| 분류 | 개수 | 예 |
|---|---|---|
| 실제 오류일 가능성 큼 | 약 12~15 | 직무청렴계약 운영지침 「임직원행동강령 제35조(교육)에 따른 행동강령책임관」(→ 제36조, 원장 C2와 같은 밀림이 다른 지침에도 남음), 문서관리규정 「제16조(문서에 대한 표시)에 따라 문서의 평가 및 폐기를 심의」(→ 제10조), 사옥관리지침 「제2조(관리책임)의 폐문시까지」(→ 제3조 출입문 개폐), 연봉제운영지침 「직제규정 제3조(대표이사)에 의한 직원」(→ 제14조 직원), 성과급지급지침 「인사규정 제34조(직위해제)에 의하여 징계로 출근하지 않은 기간」(→ 징계 조) |
| 애매함 (원래 인용도 말이 됨) | 약 20 | 범위 인용(「제11조부터 제16조까지 준용」), 「제26조(휴직의 종류)의 휴직 기간」 |
| 모델 실수 · 점검기 해석 오류 | 약 30 | 「징계지침 제5조(징계사유)에 의거 징계처분을 받은 자」, 외부 법령(정보공개법 제9조)을 자기 규정 조로 잘못 연결한 인용 |

- 즉 후보의 약 3분의 1이 실제 오류(원장 13 + 새로 12~15)로 보인다. 담당자가 76건을 훑는 데 30분 남짓

## 3. 덧붙임: 자연어 개정 요청 120건 재측정 (모델 체급별)
| 모델 | 의도 맞음 (요청 밖 변경 없음) | 비고 |
|---|---|---|
| 로컬 qwen2.5:7b | 93/120 | 낮에 잰 100은 아래 안전장치 전이라 부풀려진 값 |
| 로컬 30B (qwen3-30b-a3b) | 108/120 | |
| API luna | 116/120 | 리포트 56 수정 전 103 |

이번에 고친 것 (`src/regcheck/nl.py`)
- `_same_reg`: 「민원처리지침 제4조」처럼 규정 이름을 대충 쓰면 그 조를 「다른 규정의 조」로 빼서 모델이 원문을 못 받았다 → 조 번호 바로 앞 이름이 이 규정과 같은지 느슨하게 본다(「급여규정 제21조」 같은 다른 규정 인용은 계속 뺌)
- `intent_issues`: 조 전체를 원문과 거의 겹치지 않는 문장으로 바꾼 초안을 막는다(글자쌍 겹침 30% 미만, 「전부 개정」 요청 제외). 원문을 달라는 문장, 다른 조 내용, 항 하나만 남기고 나머지를 지운 초안이 기대 문구만 들어 있으면 「맞음」으로 세어지던 채점 허점도 함께 드러났다

## 주요 결정
| 결정 | 이유 | 대안 |
|---|---|---|
| 선택형 채택 (판정형 버림) | 두 시드 모두 잡음 95% 이상, 오탐 20 ~ 35%. 판정형은 엄격하면 오탐, 너그러우면 놓침 | 판정형 v2 (오탐 3 ~ 10%지만 절반을 놓침) |

| 폐쇄망 기본은 로컬 30B, API는 상한선으로 표시 | 운영은 외부 전송 불가. 30B도 잡음은 95% 이상이고 오탐만 더 많다 | API 기본 |
| 7B 제외 | 거의 모든 인용을 「틀림」이라 구분 능력 없음(오탐 72%) | - |

## 발표에 쓸 문장
「규칙이 못 잡는 『있는 조인데 엉뚱한 조를 가리키는 인용』은 LLM이 대상 규정의 조 목록을 보고 고르게 하면 잡힌다. 오류 주입 시험에서 규칙 10 ~ 15%, 로컬 30B 95 ~ 100%, API 98 ~ 100%를 잡았고, 맞는 인용을 다르게 고르는 비율은 30B 32 ~ 35%, API 20%로 체급이 오를수록 줄었다. KVIC 전체에 돌리면 알려진 실제 오류 15건 중 13건을 잡는다.」

## 한계
- 주입 오류는 「같은 규정의 먼 조」라 쉬운 편이다. 바로 옆 조로 밀린 오류(실제 오류에 많은 유형)는 더 어렵다. 다만 원장의 실제 오류 87%는 대부분 이런 밀림이다
- 원장 밖 후보 분류는 한 사람(Claude) 판단이고 현업 확인 전이다
- 로컬 30B 전체 검토(376개, 약 45분)는 아직 안 했다
