# 100. 개정 영향 온톨로지의 검증 방법 · 아키텍처 정리

작성 261113. 관련: [리포트 98](261112-2330-98-impact-ontology-domain-graph.md)(온톨로지 정의), [99](261113-1700-99-web-run-pipeline.md). 외부 자료 두 가지(온톨로지 추론 검증 방법 일반론, 아키텍처 검토 의견)를 우리 시스템에 맞춰 점검한 기록이다.

## A. 온톨로지 검증 방법 중 무엇을 쓸까
우리 온톨로지는 형식 논리(OWL)가 아니라 스키마 + 지식 그래프 + 수정 종류별 추론 규칙이다. 방법을 그대로 가져오지 않고 취지를 빌린다.

| 방법 | 맞나 | 이미 한 것 | 해 볼 것 |
|---|---|---|---|
| 추론기(HermiT · Pellet 등) 일관성 · 충족가능성 | 직접은 아님(OWL · 형식 추론 없음) | 관계 출발 · 도착 종류 위반 131 → 0, 끊어진 연결 0 (리포트 83) | OWL 변환은 하지 않음 |
| 추론 결과 설명(Justification) | 맞음 | 후보마다 찾은 경로 · 원문 인용 · 참고 수정안 | 2단계 연결(전이 규칙) 후보는 중간 조까지 표시 |
| SHACL식 데이터 제약 검증 | 취지가 맞음 | 위 스키마 점검 | 그래프를 만들 때마다 도는 제약 검사(조는 규정 하나에 속함, 인용 대상 존재, 조 번호 형식). 「확정된 개정 반영」 과제와 이어짐 |
| 규칙 기반 추론 검증(기대 · 금지 결과) | 맞음 | 단위 테스트 494개 | 수정 종류별 규칙마다 나와야 할 · 나오면 안 될 후보를 회귀 테스트로 |
| **역량 질문(Competency Questions)** | **가장 잘 맞음** | 없음 | 아래 |
| 단위 테스트 · CI | 맞음 | pytest | 위 두 테스트를 자동 실행에 포함 |
| 전문가 검토 · 정답 데이터 비교 | 맞음 | 정답 데이터셋 비교(재현율 · 정밀도, AI 라벨) | 전문가 검토 = 현업 검수(향후) |

### 역량 질문
「이 온톨로지가 답해야 하는 질문」을 정하고 답하는지 테스트한다. 구조로 답이 정해지므로 정답 라벨 · 현업 검수 없이 코드로 사례를 만들 수 있다.

| 역량 질문 | 지금 |
|---|---|
| 제N조를 삭제하면 그 조를 번호로 인용하는 조는? | 답함 (`CITES_in`) |
| 정의가 바뀌면 그 용어를 쓰는 조는? | 답함 (`USES_TERM`) |
| 조 번호가 밀리면 옛 번호를 인용하는 조는? | 답함 |
| 바뀌기 전 문구가 그대로 남은 조는? | 답함 (개정문 낱말 일치) |
| 인용 번호를 바꾸면 새로 가리키게 되는 조는? | **못 답함** (시험 T058 · T098) |
| 조직 · 지침 이름이 바뀌면 별표 주석에 남은 옛 이름은? | **못 답함** (시험 T087) |

놓친 사례 → 역량 질문 → 답하도록 고침 → 테스트로 고정. 「새 관계 유형 확장」 향후 과제를 이 절차로 운영한다.

## B. 아키텍처 정리 (외부 검토 의견 반영)
### 구조
모든 충돌 관계를 미리 정의하지 않고, **검증 가능한 관계만 미리 구축하고 개정이 들어올 때 필요한 부분만 추론**한다. 작은 온톨로지와 동적 검증의 결합이다(온톨로지를 포기한 것이 아님).

```
사전 구축: 개정 영향 온톨로지 (조항 · 인용 · 위계 · 정의 · 언급 등 의존 관계)
개정 발생: 온톨로지 경로 + 개정문 낱말 일치 + 의미 검색으로 후보
거르기:   판단 모델(규칙 후보) · luna(의미 검색 후보)
근거:     원문 인용 · 참고 수정안은 코드가 조회, AI는 설명만(원문 대조 통과분)
판단:     담당자 (수락 · 기각 · 수정, 결정 기록)
```

### 세 단계를 구분한다
| 단계 | 누가 |
|---|---|
| 관계 발견: A조와 B조가 이어져 있거나 관련될 수 있다 | 시스템(온톨로지 · 의미 검색) |
| 충돌 후보 탐지: 값 · 조건 · 참조 상태가 다르다 | 시스템(규칙 · 판단 모델 · LLM) |
| 법적 충돌 확정: 그 차이가 실제로 고쳐야 할 문제다 | **담당자 · 현업** |

AI가 쓴 근거도 검증 대상이다. 조항 id · 원문 · 인용 문구는 시스템이 조회하고, AI 설명과 분리해 보인다(현재: 원문 인용은 글자 대조 통과분만, 답변 충실도는 원문 기준으로 다시 판정 중).

### 규칙만 vs 동적 탐색을 더했을 때 (검토 의견: 반드시 비교할 것)
| 시험 · 개발 (정답 50 · 91) | 문항당 | 개발 | 시험 |
|---|---|---|---|
| 규칙만(온톨로지 경로 + 낱말 일치) 검색 | 약 8개 | 0.571 | 0.620 |
| 규칙만 + 판단 모델 | 3.0 · 3.5개 | 0.571 | 0.600 |
| **+ 의미 검색 · luna (지금 시스템)** | 5.3 · 5.9개 | **0.934** | **0.900** |
| (참고) 검색 전체 | 약 63개 | 0.978 | 0.940 |

같은 후보 수로 맞추면(의미 검색 순서대로 luna와 같은 개수): 개발 0.769 · 시험 0.780(5.3 · 5.8개). 의미 검색의 기여 +0.18~0.20, luna 선택의 기여 +0.12~0.17이고, luna 5~6개가 의미 검색 순서 10개(0.868 · 0.840)보다 높다. 재현율은 AI 라벨(인용 · 준용 · 같은 사항 · 정의 용어 · 전제 관계가 원문에서 확인되는 조) 기준이며 현업이 확인한 영향 · 충돌 관계가 아니다.

동적 탐색(의미 검색 + luna)을 더하면 목록은 문항당 2~3개 늘고 재현율은 +0.30 안팎 오른다. 의미 검색만 찾은 정답이 개발 28 · 시험 10개다. 복잡도를 더한 이유를 이 숫자로 설명한다.

### 한계 (그대로 남는 것)
- 연결되지 않았고 검색으로도 못 찾은 조는 놓친다(검색 상한 개발 0.978 · 시험 0.940).
- LLM을 더한다고 누락 · 잘못된 연결이 사라지지 않는다(luna는 실행마다 흔들림).
- 동적 분석은 호출 비용 · 시간이 든다(웹 한 건 약 66초).
- **사람이 최종 판단해도 후보 탐색의 재현율 문제는 해결되지 않는다.** 시스템이 놓친 후보는 사람도 못 본다. 재현율이 가장 중요한 평가 지점이다.

### 이름
「충돌 자동 판정」이 아니라 **규정 개정 영향 검토 에이전트**(On-demand Regulatory Change Impact Review Agent).
> 규정이 개정되면 미리 구축한 개정 영향 온톨로지와 관련 문서를 탐색하고, 변경 전후를 비교해 정합성 검토가 필요한 조항을 근거와 함께 제시하며, 최종 판단은 규정 담당자가 수행하도록 지원한다.

기존 규칙(`VALUE_DIFF` = DL-01, `DEF_DIFF` = DEF-01, `STALE_CITE` = MOVE-01 등)은 유지한다. 동적 추론은 규칙을 대체하지 않고, 규칙이 못 잡는 사례에서 근거를 찾고 범위를 넓힌다.
