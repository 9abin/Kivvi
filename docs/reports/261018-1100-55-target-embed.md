# 261018-1100 개정 위치 찾기: Qwen3-Embedding-4B 색인 + 리랭커 800자, 로컬 LLM 주소 지연 수정

- 관련: [51 독립 평가](261016-0100-51-independent-eval.md) §2-2(규정·조 찾기 조 @3 62%), [53 RAG 조합 실험](261016-1800-53-rag-combo-results.md)(임베딩 교체 효과, `localhost` 지연)
- 변경 범위: `src/regcheck/target.py`(리랭커 글자 수, 규정 이름 옵션), `app/web_agent.py`(개정 위치 찾기 전용 색인 · bge 대체), `src/regcheck/nl.py` · `scripts/llm_check.py` · `scripts/llm_compare.py`(Ollama 주소), `scripts/build_vectors_ollama.py`(새로), `scripts/eval_target_rag.py`(옵션), `out/vector/qwen3-embedding-4b-q8_0/`(새 색인, git 제외)

## 요약
규정·조를 모르는 개정 요청에서 후보를 찾는 기능의 **조 @3이 62% → 69%** (짝지은 차이 +6.7%p, 95% 구간 [+1.1, +13.3], 좋아짐 7 · 나빠짐 1). RAG 실험과 같은 패턴으로, 임베딩 교체는 후보 안 천장(87% → 93%)을 올리고 리랭커에 조문을 더 길게(800자) 넘기면 그 정답이 위로 올라온다. 둘 중 하나만으로는 +2%p. 함께 에이전트의 로컬 LLM 호출이 `localhost` 때문에 **호출마다 약 2초** 늦던 것을 고쳤다(2.2초 → 0.13초).

## 측정 (RAG 팀 독립 라벨 평가셋 v2, 질문 90개 · 필수 근거 122개, 질문 단위)
| 설정 | 조 @1 | 조 @3 | 조 @5 | 후보 전체 안 | 규정 @3 |
|---|---|---|---|---|---|
| bge-m3, 후보 25, 400자 (이전) | 41% | 62% | 71% | 87% | 83% |
| bge-m3, 후보 50 | 41% | 63% | 73% | 93% | 84% |
| bge-m3, 800자 | 40% | 64% | 72% | 87% | - |
| Qwen3-4B, 후보 25, 400자 | 42% | 64% | 76% | 93% | 84% |
| Qwen3-4B, 후보 50 | 41% | 64% | 72% | 97% | 84% |
| Qwen3-4B, 규정 이름 붙임 | 43% | 68% | 73% | 93% | 87% |
| **Qwen3-4B, 800자 (채택)** | 42% | **69%** | **77%** | 93% | **88%** |
| Qwen3-4B, 규정 이름 + 800자 | 41% | 70% | 77% | 93% | 89% |

- 짝지은 비교(이전 설정 대비, 조 @3): 4B만 +2.2 [−2.2, +6.7], 규정 이름 +5.6 [−1.1, +13.3], **800자 +6.7 [+1.1, +13.3]**, 규정 이름 + 800자 +7.8 [0.0, +15.6]
- 시간: 요청당 0.19초(400자) → 0.28초(800자), GPU fp16, 모델 적재 뒤. 첫 호출은 모델 · 규정 적재로 약 29초
- 「확실함」 기준(점수 0.3)은 그대로 맞다: 확실함 21건 중 조 @3 20건(이전 20건 중 19건)
- 색인 만들기: 청크 4,500개(기존 bge 색인과 같은 청크), Ollama `qwen3-embedding:4b-q8_0`, 552초

## 주요 결정
| 결정 | 이유 | 대안 |
|---|---|---|
| 개정 위치 찾기만 4B 색인으로 | 평가한 것은 이 기능뿐. 의미 이웃 · 옮겨 간 곳 찾기 · 변경안 점검은 bge 색인으로 정답 대조를 해 왔다 | 모든 기능의 색인 교체 (각 기능 재평가 필요, 후속) |
| 리랭커 800자 채택, 규정 이름은 보류 | 800자만 구간이 0을 넘는다. 규정 이름은 방향은 같지만 유의하지 않다 | 둘 다 (+7.8, 구간 하한 0) |
| 후보 수 25 유지 | 50으로 늘리면 천장은 오르지만(93 → 97%) 상위 3 · 5는 오르지 않는다 | 50 |
| Ollama 임베딩 실패 시 bge로 자동 대체 | 화면이 멈추지 않게. 결과에 `index`로 어느 색인을 썼는지 남긴다 | 실패 표시만 |
| 로컬 LLM 주소 `127.0.0.1` | 윈도우에서 `localhost`는 IPv6를 먼저 시도해 호출마다 약 2초. urllib은 연결을 재사용하지 않아 매번 늦다 | - |

## 한계
- 평가 입력은 직원 질문이지 개정 요청이 아니다(리포트 51과 같은 한계). 개정 요청 4개를 눈으로 본 결과는 그럴듯했다(「경조휴가에 반려동물 사망 추가」 → 복무규정 제26조 경조휴가 1위)
- 「출장비 기준을 올리고 싶어」는 해외 파견 지침의 출장 경비가 1 · 2위, 여비규정이 3위다. 요청이 모호하면 여러 규정이 섞이고, 그래서 후보를 사람이 고르는 설계가 맞다
- 질문 90개라 구간이 넓다(±10%p 안팎)

## 변경 사항
- `target.TEXT_CHARS` 400 → 800, `target.RERANK_REG_NAME`(기본 끔) 추가
- `web_agent.targets`: `TARGET_INDEX`(기본 `qwen3-embedding-4b-q8_0`, 환경 변수로 `BAAI__bge-m3` 되돌림) 색인을 Ollama 임베딩으로 쓰고, 실패하면 bge 색인
- `scripts/build_vectors_ollama.py`: 기존 청크를 Ollama 임베딩 모델로 다시 임베딩 (`--model`)
- `scripts/eval_target_rag.py`: `--index`, `--search-k`, `--device`, `--text-chars`, `--rerank-reg`, `--tag`, 후보 전체 안 비율
- Ollama 주소 `localhost` → `127.0.0.1`: `src/regcheck/nl.py`, `scripts/llm_check.py`, `scripts/llm_compare.py`
