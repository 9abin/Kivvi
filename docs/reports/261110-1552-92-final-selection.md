# 261110-1552 최종 선택: 후보를 사람에게 보일 만큼 줄이기 (규칙은 판단 모델로 거르기, RAG는 순서 섞기)

- 관련: [90 고정 평가셋 기준값](261110-1000-90-gabin-benchmark-baseline.md), [91 표현 수정 RAG](261110-1700-91-expression-edit-rag.md)
- 변경 범위: `src/regcheck/final_view.py`(새), `scripts/decide_score_pairs.py`(새, 판단 모델 환경), `scripts/eval_final_view.py`(새), `tests/test_final_view.py`(새). 검색기는 가빈 파이프라인(리포트 91의 두 옵션 기본 켬)
- 평가셋: 값 선택 = val 30 + 4도메인 30. 최종 100건은 파서 수정과 실험 3에 쓰였으므로 **개발 세트**다(아래 4의 「시험」 표기는 정정, 6 참고). **시험 = 가빈 4도메인 39문항 수정본**(`full-testset`, 기존 세트와 개정문 1문항만 겹침). 정답은 AI 초안. 판단 모델은 Kanana-2-v-decide-3b(3.67B)

## 요약
검색 후보(최종 100건 문항당 62.5개)를 18.0개로 줄이고 정답 83%를 지킨다(전부 보이면 95%). 규칙 후보는 판단 모델 점수로 걸러 문항당 3.3개로 규칙 정답 90%를 지켰다. 같은 개수를 기존 순서로 자르는 것(81%)보다 +2쌍이지만 구간이 0을 포함한다(시험). 정답 대부분이 RAG만 찾은 후보라서 남은 여지는 RAG 쪽 순서다.

## 주요 결정
| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 규칙 후보는 판단 모델로 **거른다**(순서는 그대로) | 점수 0인 확인 권장 · 참고 후보는 정답률 0~0.8%, 점수 2는 14~22%. 순서를 바꾸면 시험에서 이득이 없다(아래 2) | 판단 모델로 순서 정렬(시험 −2쌍), 판단 모델 확률(시험 −10쌍), 거르지 않기 |
| 확정급은 점수와 관계없이 보인다 | 점수 0인 확정급도 시험에서 57%가 정답 | 확정급도 거르기 |
| RAG만 찾은 후보는 검색 순위 반 + 판단 모델 순위 반, 상위 15 | 섞으면 판단 모델 · 9B · GPT-4o-mini · luna 모두 상위 3에서 +6~9쌍(구간 > 0). 모델 간 차이 없음, 판단 모델이 가장 싸다 | 리랭커(유사도 기반, 한국어판은 −8~−10쌍), 모델 점수 단독 |
| 점수가 없는 후보는 숨기지 않는다 | 판단 모델이 못 돌 때 후보를 잃지 않게 | 숨기기 |
| 근거: 규칙은 원인(경로 · 전후 문구)과 결과(대상 조문)를 LLM이 풀어 쓰고, RAG는 코드가 뽑은 인용 + LLM 이유 한 문장 (예정) | LLM이 쓴 인용은 33~50%가 원문과 글자가 달랐다 | LLM이 인용까지 쓰기 |

## 1. 실험 순서와 방식
모든 비교는 문항을 다시 뽑는 부트스트랩(2,000회) 95% 구간으로 본다. 2 · 4는 개발에서 미리 정한 규칙으로 값을 고르고 시험은 한 번만 쟀다. 3은 val + 최종 100건을 합쳐 본 탐색이다.

| 실험 | 대상 | 비교한 것 |
|---|---|---|
| 1. 전체 후보 순서 바꾸기 | 후보 풀 전체 | 여러 재정렬 전략 vs 풀 순서 |
| 2. 규칙 후보 판단 모델 | 규칙 후보 3,186쌍 | 순서 4가지, 거르기 임계값 |
| 3. RAG만 찾은 후보 순서 | 문항당 상위 20, 2,164쌍(val 30 + 최종 98) | 판단 모델, 9B(qwen3.5, 예시 유무), GPT-4o-mini, gpt-5.6-luna, 리랭커 3종 |
| 4. 최종 화면 | 세 세트 160문항, 판단 모델 입력 10,175개 | 거르기 + 섞기 vs 같은 개수 자르기 |

판단 모델 입력: `[개정 종류] [개정 내용](개정문 + 시작 조 원문) [확인 대상 조문]`. 질문은 수정 종류별 예/아니오(`p`)와 「얼마나 닿는가」 4단계 기댓값(`lv`, 0~3). 문구는 `final_view.INSTR` · `LEVELS`. 경로 정보는 주지 않았다.

## 2. 실험 1 · 2: 규칙 후보
- 실험 1: 어떤 재정렬도 풀 순서(단계 먼저 · 점수순)를 이기지 못했다.
- 실험 2, 순서(상위 5 정답 수, 풀 순서 대비): 판단 모델 4단계 개발 +2 [−3, +7] / 시험 −2 [−11, +6], 확률 −3 / **−10 [−21, 0]**, 반반 +4 / +2, 확정급 먼저 + 판단 모델 +3 / +0. 순서는 바꾸지 않는다.
- 단계 × 점수(반올림) 정밀도:

| 단계 | 점수 0 | 점수 1 | 점수 2 |
|---|---|---|---|
| 확인 권장 (개발 / 시험) | 0.1% / 0.8% (679 / 617개) | 1.9% / 4.3% | 18% / 22% |
| 참고 | 0% / 0.2% (445 / 475개) | 1.2% / 8.4% | 18% / 14% |
| 확정급 | 25% / 57% | 50% / 33% | 38% / 50% |

- 거르기 임계값(미리 정한 규칙: 개발 규칙 정답 유지 90% 이상인 가장 높은 값, 후보 0.5 · 1.0 · 1.5): 개발 ≥0.5 97% · ≥1.0 89% · ≥1.5 83% → **0.5**. 시험 한 번: 규칙 후보 문항당 16.5 → 5.4개, 규칙 정답 62/68(91%). (실험 2의 후보 풀은 한석희 연결 표를 포함한 이전 풀)

## 3. 실험 3: RAG만 찾은 후보 순서 (정답 40쌍, 34문항, 탐색)
| 순서 | 상위 3 | 상위 5 | 상위 3 차이 [구간] |
|---|---|---|---|
| RAG 순서 | 20 | 27 | — |
| 판단 모델 4단계 | 26 | 33 | +6 [−1, +13] |
| RAG 반 + 판단 모델 확률 반 | 26 | 32 | +6 [+2, +11] |
| RAG 반 + 9B 반 | 27 | 30 | +7 [+3, +12] |
| RAG 반 + GPT-4o-mini 반 | 29 | 32 | +9 [+3, +16] |
| RAG 반 + luna 반 | 27 | 30 | +7 [+3, +12] |
| 리랭커 bge-reranker-v2-m3 | 18 | 30 | −2 [−7, +4] |
| 리랭커 bge-reranker-v2-m3-ko | 12 | 17 | **−8 [−15, −1]** |
| 리랭커 Qwen3-Reranker-0.6B | 25 | 29 | +5 [−2, +12] |

9B 예시 넣기(예시 A · B 두 묶음)는 묶음에 따라 결과가 갈렸다(+7 / +4). 모델 간 차이는 구간 안에 있다. 판단 모델을 고른 이유는 가장 싸고 로컬이기 때문이다.

## 4. 실험 4: 최종 화면 (가빈 파이프라인 후보 풀, 한석희 연결 표 없음)
미리 정한 규칙: 규칙 임계값은 2와 같은 기준, RAG 개수(5 · 10 · 15 · 20)는 개발 전체 유지율이 20개 때보다 3%p 넘게 떨어지지 않는 가장 작은 값 → **0.5, 15개**.

| | 문항당 후보 | 정답 유지 | 같은 개수 풀 순서 자르기 | 차이 [구간] |
|---|---|---|---|---|
| 개발 (값 고른 세트) | 59.6 → 18.5 | 65/86 (76%) | 58 (67%) | +7 [+1, +14] |
| 시험 (한 번) | 62.5 → 18.0 | 89/107 (83%) | 87 (81%) | +2 [−9, +12] |

- 보이는 후보는 규칙 3.3개 + RAG 14.7개(시험). 문항당 0~48개(중앙 17), 확정급이 많은 문항이 길다.
- 시험 정답 107쌍 중 규칙 후보에 든 것 61쌍, 나머지는 RAG만 찾았다. 규칙 쪽은 61 → 55를 지켰고 놓친 정답 대부분은 RAG 15개 밖이다.
- 판단 모델 계산: 6,293개에 2,278초(8GB GPU). 개정 1건(약 60개)에 약 15초. 점수 3,882개는 이전 실험 것을 재사용했다(같은 형식, 글자 대조 안 함).

## 6. 새 39문항(시험)과 추가 비교 (261110)
값은 그대로(규칙 ≥0.5, RAG 15개) 한 번만 쟀다. 정답 44쌍(조 단위).

| | 문항당 후보 | 정답 유지 | 같은 개수 기존 순서 | 차이 [구간] |
|---|---|---|---|---|
| 검색만 | 60.6 | 36/44 (82%) | — | — |
| 최종 화면 | 16.9 | 34/44 (77%) | 29 (66%) | +5 [+1, +10] |

- 개정문 분석 실패 3건(E021 「각 호 외의 부분에 단서 신설」, E022 「각 호 외의 부분 중」, E029 「후단 신설」). 이 문형은 새 39를 보지 않고 법제 문형 기준으로 넣어야 한다.
- 상위 50 다시 정렬, 상위 10: 기존 50% / 판단 모델 68% (+8 [0, +15]) / bge-reranker-v2-m3 59% / Qwen3-Reranker-0.6B 59% / bge-reranker-v2-m3-ko 43%. 일반 리랭커는 쓰지 않는다.
- 최종 100건(개발)에서 gpt-5.6-luna(가빈 프롬프트, 외부 API 실험 예외) 상위 50 판정 4,420건: 순서로 쓰면 상위 10 79%(기존 74%, 판단 모델 72%). 2점 이상으로 거르면 문항당 2.8개, 정답 56%(정답 쌍의 35%가 0점). 거르기에는 쓰지 않고 순서 · 근거에 쓴다.
- 항 단위: 조를 찾으면 정답 항도 대부분 같이 들어온다(같은 칸 수에서 조 기준과 0~4%p 차이). 찾기는 조, 화면 · 근거는 항.
- 한석희 scoped 그래프를 우리 그래프에 합치면 후보가 문항당 24~57개 늘고 고유 정답은 1~6쌍(새 39: 1쌍). 기본에 넣지 않는다.
- 감사(서브에이전트): 정답 유출 · 문항별 규칙 없음. 평가 설정이 앱 설정보다 강함(값 변경 바깥 방향 간선, 하이브리드 RAG)은 남은 문제.

## 한계
- 정답은 AI 초안, 시험 세트는 봉인이 아니다. 정답 한 쌍이 약 1%라 몇 %p 차이는 구분하기 어렵다.
- 실험 3은 개발 · 시험을 나누지 않은 탐색이다.
- 판단 모델 점수는 「닿는다」는 확신이 아니다. 거르기와 순서에만 쓰고 판정은 사람이 한다.
