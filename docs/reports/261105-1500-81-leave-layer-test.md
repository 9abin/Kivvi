# 261105-1500 휴직 개념 층 시험 (개발 12개 · 봉인 8개)과 삭제 개정 분류 수정

- 관련: [80 4차 봉인 결과](261102-2030-80-sealed-round4-result.md), [74 전체 구조](261102-1530-74-impact-pipeline-overview.md)
- 변경 범위: `src/regcheck/leave_layer.py`(신규), `collect.py`(`leave` 옵션), `impact_view.py`(`run(..., leave=)`), `change_query.py`(삭제 분류), `scripts/build_leave_layer.py` · `exp_leave_items.py`(신규), `eval/leave_items/`(시험 항목 20개)
- 상태: 정답 라벨은 모두 Claude 서브에이전트가 만든 **AI 초안(사람 확인 전)**. 비교는 RAG 없이 그래프 · 문구 경로만. 결과는 탐색용이다.

## 요약

- 방향 전환(범위를 휴직 관계, 기존 RAG, 기본 규칙 기반 온톨로지로 좁힘)에 따라 휴직 개념 층을 만들어 후보 수집에 옵션으로 붙였다. 층은 후보를 **더하기만** 하고 빼거나 판정하지 않는다.
- 개발 항목 12개에서는 정답 9건 중 층 끔 6건, 켬 9건이었다. 그러나 3건 중 1건은 결과를 본 뒤 고친 규칙으로 얻었다. 봉인 항목 8개에서는 정답 6건 중 끔 1, 켬 1로 **이득이 재현되지 않았고**, 후보만 59개에서 149개로 늘었다.
- 시험 중 분석기의 구멍 두 가지가 드러났다. 삭제 개정이 표현 수정으로 분류되던 것(수정함, 기존 평가 4묶음 수치 동일)과 이름 · 용어 교체가 표현 수정으로 분류되어 후보가 0개인 것(**미수정**, 봉인 정답 5건 놓침).

## 층의 설계

클래스 = 휴직 종류(육아 · 질병(인병) · 가족돌봄 · 청원 · 직권 + 공통), 프로퍼티 = 속성(기간 · 분할 · 보수 · 승진 · 절차 · 대상 · 복직), 인스턴스 = 조 · 별표. 키워드 규칙으로 자동 배정한 초안이다(휴직 관련 49개 조, 17개 규정). 추론은 계층 닫힘(공통 ⊃ 각 종류)과 규칙표뿐이다.

| 경로 | 조건 | 단계 |
|---|---|---|
| LEAVE_ATTR | 같은 종류, 같은 속성 | 확인 권장 |
| LEAVE_COMMON | 공통 조가 그 속성을 정함 | 참고 |
| LEAVE_KIND | 같은 종류, 다른 속성 | 참고 |

개정문이 따옴표로 지목한 항에서만 속성을 뽑고, "휴직"이 본문에 두 번 이상 나오는 조만 휴직 조로 본다(첫 실행은 항목당 19~45개를 확인 권장으로 더해 과다였다).

## 한계

- 라벨이 AI 초안이다. 에이전트 하나가 근거 인용 일부를 요약해 적었다고 밝혔으므로 인용문은 원문 대조가 필요하다.
- 항목은 모두 직접 만든 가상 개정이다. 정답이 있는 항목이 적다(개발 6개, 봉인 1개 항목에만 정답).
- 비교에 RAG를 쓰지 않았다. 실제 기본 화면에서는 RAG 30개가 함께 나가므로, 층이 더 찾는 몫은 더 작을 수 있다.
- 층의 규칙은 키워드 기반 자동 초안이다. 팀의 사람이 검수한 휴직 온톨로지로 바꾸면 결과가 달라질 수 있다(자료 미확보).

## 추가 기록 6 (261105): 평가가 규칙 쪽에 치우쳤는지 점검 (풀 보강 + RAG 포함 재측정)

- **풀 보강**: 36개 항목에 밀집 검색 · BM25 · 하이브리드 RAG 상위 30개를 모아 이전 풀에 없던 후보 1,016개를 따로 라벨(`out/pool_extra`, 항목당 평균 28개). 라벨 파일 36개는 풀 단위와 일치함을 직접 확인했다(처음 보고에서 L19~L28 파일이 없었고 L05 보고가 파일과 달라 재라벨했다).

| 방법 | 정답 |
|---|---|

- 한계: 새 풀도 RAG · BM25 상위로 모았으므로 RAG에 유리한 쪽으로 기울 수 있다(그래서 새 정답 3건 중 2건을 RAG+그래프+층이 찾았다). 항목은 직접 만들었고 라벨은 AI 초안(아니오 사유는 공통 문구)이다. 사람 검수와 현업 검수가 남아 있다.
