## 2. 세 가지 연결을 구분한다
| | 인용 그래프 (지금) | 키워드 탐색 (외부 도구) | 벡터 · BM25 검색 (RAG) |
|---|---|---|---|
| 연결 근거 | 조문에 **적힌 인용** | 같은 **말이 나옴**(문자열) + 사람이 만든 분류 | 뜻이 비슷함 / 낱말 일치 |
| 노드 | 규정 · 조 · 항 · 별표 · 법령 · 개정본 | 키워드 561개 + 조문 | 조각(chunk) |
| 알 수 있는 것 | 이 조를 쓰는 곳, 깨진 인용, 법령 개정 미반영, 개정 영향 | 같은 주제의 다른 규정 조문 | 질문과 가까운 조문 |
| 못 하는 것 | 인용 없는 같은 주제 | 방향 · 시점 · 법령 | 조건 · 시점 · 충돌 판단 |
| 용도 | **오류 탐지 · 개정 점검** | 탐색 · 후보 확장 | 질문 답변의 후보 검색 |

세 가지는 **경쟁이 아니라 역할이 다르다.** 오류 탐지는 인용 그래프, 말이 다른 같은 주제는 용어 · 주제 노드, 질문 답변의 후보는 검색기들의 합집합이 맡는다.

## 3. 온톨로지 (요약, 상세는 리포트 62)
- **지금 구현**: 클래스(규정 · 장 · 조 · 항 · 별표 · 부칙 · 개정본 · 법령 · 개정안 · 영향 · 결정), 관계 4종(법령 인용 651, 인용 561, 별표 · 별지 인용 441, 문서 인용 · 위임 210 — 관계 파일 1,863줄), 점검 상태 어휘, 개정본 시점(`valid_from` / `valid_to`).
- **제안**: 용어 · 주제 · 조건 · 값 노드, 관계 8종(위임, 용어 대응, 같은 주제, 값 불일치, 충돌 의심, 예외, 대체, 법령 근거).
- **원칙**: 자동 추출은 규칙으로, 의미 관계는 전문가가 확정한다(자동 후보 → 의심 → 확인됨, 결정은 덧붙이기만). 법적 판단은 하지 않는다.

## 4. 키워드 탐색 도구를 붙여 본 효과 (측정 결과)
- 대상: 외부 공개 「키워드 탐색」 페이지(우리 규정 90건 대상, 키워드 561개 · 조 1,149개 · 규정 87건). 평가 질문 수와 예시 질문이 붙어 있어 **평가 질문을 본 흔적이 있음**(결과가 낙관적일 수 있음).
- 방법: 질문에 키워드(묶인 말 포함)가 들어 있으면 그 키워드의 조문을 후보에 더함. 우리 최종 설정(필수 조 126개, 99문항)과 **조 단위**로 비교.

| 방식 | 필수 조 Recall | 질문 전부 확보 | 추가 조(평균) |
|---|---|---|---|
| 기준: 최종 10개 | 110/126 = 0.873 | 86/99 | 0 |
| 최종 10 + 키워드 전체 | 114/126 = 0.905 | 89/99 | 20.2 |
| 최종 10 + 구체적 키워드(조문 20개 이하) | 111/126 = 0.881 | 86/99 | 4.1 |
| **리랭크 상위 16으로 넓힘** | **115/126 = 0.913** | 90/99 | 0.1 |
| 상위 16 + 키워드 전체 | 117/126 = 0.929 | 92/99 | 20.3 |

- 해석: 키워드를 그대로 붙이면 Recall은 오르지만 후보가 질문당 약 20개 늘어 **효율이 낮고, 단순히 상위 16으로 넓히는 것이 더 낫다.** 복구된 것은 모두 「출장」처럼 큰 키워드(조문 80개)에 걸린 여비규정이었다.
- 놓친 13문항 중 **7문항은 키워드가 아예 안 걸림**(법카 영수증 · 공문 결재 · 이해충돌 · 회사 메일 · 업무 PC 카톡 · 챗GPT 등). 말이 달라서 놓친 문제는 키워드 일치로 풀리지 않는다.
- 활용: 키워드 계층은 그대로 검색에 붙이기보다 **주제 · 용어 노드의 시드**로 쓰고, 리랭커를 거치게 하는 편이 낫다(미측정). 가장 싼 개선은 **리랭크 상위 N을 16으로 넓히는 것**(0.873 → 0.913).

## 6. 객관적으로 증명하는 방법
**정밀도 (연결이 정말 관련 있나)**
1. 연결 종류마다 「맞다」의 정의를 따로 정한다(인용: 원문대로 해석 / 법령: 법률 DB와 일치 / 영향: 같이 확인해야 함 / 주제: 그 질문의 답이 되는가 — 필수 · 보조 · 무관).
2. 종류별 **층화 표본**(약 40개 × 5종)을 사람이 판정하고 **95% 신뢰구간**과 함께 보고한다.
3. **두 사람이 독립 판정**(한 명은 도메인 담당자)하고 일치도(Cohen's κ)를 본다. LLM 라벨은 사전 선별까지만 쓴다.
4. **무작위 쌍**을 섞어 오탐 기준선을 본다.

**재현율 (안 놓쳤나) — 증명이 아니라 추정**
1. 연결을 만들 때 쓰지 않은 **독립 정답**으로 잰다: 오류 원장 46건, **과거 실제 개정 재현**(함께 고쳐진 조문), 오류 주입 골든셋 182문항.
2. **풀링**: 여러 검색기(벡터 · BM25 · 키워드 · 그래프 · 인용)의 결과를 합쳐 사람이 판정하고 각 방식이 합집합의 몇 %를 담는지 비교한다.
3. 독립인 두 방식의 겹침으로 **놓친 양을 추정**한다(N ≈ N1 × N2 / 겹침, 근사).
4. 문제없는 문항에서 경보가 0인지 반대 시험도 한다(33문항 중 0).

**절차**: 평가 전에 방식 고정, 개발 · 시험 분리, 키워드처럼 평가 질문을 본 자료는 별도 표시, 수치마다 표본 수 · 신뢰구간 · 짝지은 검정(McNemar), 마지막은 **현업 검수(UAT)**.

| 현재 상태 | |
|---|---|
| 인용 정밀도 | 표본 75개(1차 57% → 고친 뒤 80%), **라벨은 Claude, 사람 확인 전** |
| 오류 재현율 | 46건 중 43건 (정답 원장은 우리가 만들었고 일부는 규칙 조정에 사용) |
| 키워드 연결 정밀도 | 측정 없음 |

## 7. 발표 · 보고서 문구 제안
- 「오류 탐지는 RAG가 아니라 **규정 그래프와 규칙**으로 한다. RAG는 직원 질문 답변을 맡는다.」
- 「오류 탐지는 실시간이 아니라 배치로 쌓아 둔 후보 DB를 담당자가 검토한다.」
- 「검색은 **Recall을 먼저** 올린다. 현재 0.87~0.905, 현업 기준은 0.9 이상이 필요하다.」
- 「지금의 인용 그래프에 **관계 종류와 용어 사전을 전문가와 함께 더해 확장**한다. 유사도는 후보를 찾는 데만 쓰고 판정은 사람이 한다.」
- 한계: 유사도는 「비슷함」만 알려 줄 뿐 충돌 여부는 의미로 판단해야 한다(출장 정산 기한 · 국내 출장 숙박비 · 비밀번호 변경 주기 같은 충돌 의심 사례).

## 8. 한계 · 주의
- 키워드 효과 수치는 **평가 질문과 겹쳐 만든 도구**로 쟀고 표본이 작아(필수 조 126개) 상한에 가깝다. 신뢰구간은 구하지 않았다.
- 문형 출현 횟수는 관계의 개수나 정확도가 아니다. 구현하면 샘플을 사람이 확인해야 한다.
- 외부 레퍼런스의 수치는 다른 과제의 값이다. 우리 성능처럼 말하지 않는다.
- 온톨로지 · 관계는 **전문가 검수 전 초안**이다. 의미 관계의 효과는 측정하지 않았다.
- 상태: 인용 관계 수는 관계 파일(1,863줄) 기준이고 DB는 1,884줄이다(21줄 차이).
