## 주요 결정
| 결정 | 이유 | 대안 |
|---|---|---|
| 실행 기록은 실행마다 파일 하나(코드 커밋·미커밋 여부·입력/출력 해시·모델·설정), 결과 행에는 실행 ID만 | 결과를 사람이 수락·거절하기 전에 재현·원인 추적 수단이 있어야 함. 행마다 반복하면 파일이 커지고 불일치 위험 | 행마다 전부 기록 (버림) |
| 채점 기록은 `eval/runs/`(git 포함), 생성물 기록은 `out/runs/`(git 제외) | 점수 변화는 남겨야 하고, 생성물은 다시 만들 수 있음 | 둘 다 out/ (점수 이력 유실) |
| 채점 기록에 원장 분포(위계·단위·종류·규정 수) 포함 | 정답셋 대표성 점검(QMR-001)을 지금은 분포 출력만. 설계서는 가빈 155건 후 | 지금 설계서 작성 (채울 데이터 없음) |
| 판독 위험 목록은 발표 준비 때 | 파싱 결과에 정보가 이미 있음, PoC 필수 아님 | 지금 작성 |
| 목표 수치: 원장 50건 이상에서 탐지 재현율 90%, 정답 밖 결과는 사람 판정 정밀도로 따로 | RFP 기준(문항 50개, 정답률 90%)과 같은 형식. 우리는 질의응답이 아니라 탐지라 재현율로 바꿈 | 정답률 하나로 보고 (정답 밖 결과를 오탐으로 셈) |
| 결과 페이지는 로컬 HTML 한 장(`out/`) | 규정 문구·미확정 오류 후보가 들어감. 폐쇄망 가정, 외부 게시 안 함 | Streamlit (검토 화면 단계에서) |
| 채택 안 함: RBAC·SSO 검색, 사용자 맞춤 답변, GPU 인프라, MCP·A2A | PoC 범위 밖 | — |
