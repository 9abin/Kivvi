# 101. 적용 범위 · 한계 · 향후 과제

작성 261113. 관련: [94](261111-2100-94-eval-metrics.md) · [96](261112-2000-96-codex-cross-review.md) · [98](261112-2330-98-impact-ontology-domain-graph.md) · [99](261113-1700-99-web-run-pipeline.md) · [100](261113-1900-100-ontology-validation-architecture.md). 외부 검토 의견(「기능을 더하기보다 적용 범위 · 효과 · 탐지하지 못하는 유형 · 향후 과제를 명확히」)에 따라 정리했다.

## 1. 이 시스템이 하는 일
**규정 개정 영향 검토 에이전트.** 규정이 개정되면 미리 구축한 개정 영향 온톨로지(의존 관계 그래프)와 관련 문서를 탐색하고, 정합성 검토가 필요한 조항을 근거와 함께 제시한다. 영향 · 충돌 여부, 수정 문안, 경과조치, 협의 · 승인은 담당자가 판단한다.

## 2. 구현 · 검증한 범위
| 범위 | 내용 |
|---|---|
| 명시적 관계 탐색 | 조 번호 인용 · 장 · 절 인용 · 규정 이름 인용 · 위임 · 준용, 정의 용어 사용, 조 제목 언급, 같은 제목 · 같은 값, 서식 · 별표 언급 (온톨로지 관계 18종) |
| 변경 유형별 선택적 추적 | 수정 종류(값 변경 · 삭제 · 번호 이동 · 정의 변경 · 위임 · 법령 변경 · 내용 변경 등)마다 따라갈 관계 · 방향 · 가중치(`change_paths`) |
| 개정문 낱말 일치 | 바뀌기 전 문구 · 지워진 낱말 · 새 문구가 그대로 남은 조 (조 전체 교체 개정문은 옛 문구를 되살림) |
| 의미 검색 보완 | 명시적 관계가 없는 조를 의미 검색 + luna 선택으로 보완 |
| 근거 제시 | 원문 인용은 코드가 조회(글자 대조 통과분만), 참고 수정안(번호 · 명칭), AI 설명은 따로 |
| 거르기 · 화면 | 판단 모델(규칙 후보) · luna(의미 검색 후보), 첫 화면 10개 + 더 보기, 웹 편집 화면 · 리뷰 앱이 같은 파이프라인 |
| 후속 조치 일부 | 깨진 인용의 연쇄 수정 루프, 함께 개정안 · 부칙 초안, 판단 필요 질의서, 수락 · 기각 · 제출 · 승인 기록 |

## 3. 확인된 효과 (AI 초안 라벨 기준)
| 구성 | 개발 재현율 (문항당) | 시험 재현율 (문항당) |
|---|---|---|
| 규칙(온톨로지 경로 + 낱말 일치) | 0.571 (8.2) | 0.620 (8.3) |
| 규칙 + 판단 모델 | 0.571 (3.0) | 0.600 (3.5) |
| + 의미 검색, luna와 같은 수를 검색 순서로 | 0.769 (5.3) | 0.780 (5.8) |
| **+ 의미 검색 · luna (지금)** | **0.934 (5.3)** | **0.900 (5.9)** |

- 재현율의 뜻: AI 라벨러 두 명이 만든 「함께 살펴볼 조」(인용 · 준용 · 위임 · 같은 사항 · 정의 용어 · 전제 관계가 원문에서 확인되는 조, 확신 높음 · 중간) 중 최종 목록에 든 비율. **현업이 확인한 영향 · 충돌 관계의 재현율이 아니다**(현업 정답 0건).
- 시험 0.900은 시험 실패를 보고 고친 뒤 값이다(처음 고정 실행 0.860). id 없는 정답(별지 · 별표) 6개를 넣으면 0.804. 검색 상한 0.940.
- 같은 후보 수에서도 의미 검색(+0.18~0.20)과 luna 선택(+0.12~0.17)이 각각 재현율을 올렸다.

### 답변(근거 설명) 품질
| 시험 답변 | Faithfulness (95% 구간) |
|---|---|
| luna 답변 | 0.89 (0.81~0.95) |
| 규칙 답변 | 0.97 (0.92~1.00) |
| **전체** | **0.93 (0.89~0.97)** |
| 전체, 근거 확인 못 한 luna 답변 → 「확인 필요」 | **0.96 (0.91~0.99)** |

Faithfulness = 답변 문장이 모두 확인 대상 조 · 개정 원문으로 뒷받침되는(또는 사실 주장 없는 확인 권고인) 답변의 비율. 시험 답변 531개(luna 235 · 규칙 296)에서 50개를 뽑아(경로 × Solar 판정 층화) 원문과 직접 대조하고, 경로 × Solar 판정 × 원문 인용 유무 층의 크기로 가중했다(인용 없는 luna 답변은 전체의 8%인데 표본에는 12/25로 많이 뽑혔다). 판정은 Claude(사람 확인 전, `test/faith_check_50.csv`), 구간은 층별 부트스트랩. 판정 모델(Solar)은 「문제 있음」 28개 중 18개가 오판이라 쓰지 않았다. (261113 정정: 처음 적은 「틀린 사실 약 0.03」은 층 가중을 잘못 적용한 값이다. 원문 인용 유무까지 층으로 나눠 가중한 값이 위 표다.) luna 답변의 틀린 사실은 luna가 한 번에 본 다른 후보의 내용이 이유에 섞여 옮겨진 경우가 많았다.

**근거를 확인 못 한 luna 답변은 「확인 필요」로(261113, 결정)**: luna가 고른 후보 중 후보 조문에서 근거 구절을 확인하지 못한 것(시험 18/235 · 개발 8/234)은 luna가 쓴 이유 대신 「원문에서 근거 문장을 확인하지 못했습니다. 조문을 직접 보고 관련 여부를 확인해 주세요(담당자 확인 필요).」를 보인다(`impact_pipeline.UNVERIFIED_REASON`, 원래 이유는 `evidence.luna_reason`). 후보 · 순서는 그대로라 검색 · 거르기 · 정렬 지표는 바뀌지 않는다. 같은 표본으로 다시 재면 **시험 Faithfulness 0.96(0.91~0.99), luna 0.94(0.88~1.00)**. 남는 오류는 인용이 있는데도 개정 내용을 잘못 읽은 경우(표본 13개 중 2개)다. 저장된 실행 결과(`runs/pipe.jsonl`)는 고치기 전 답변이다. 버린 대안: luna 답변을 후보마다 원문을 넣어 다시 쓰기(호출 470건 추가 비용), 판정 모델로 전체 재판정(gpt-5.5는 비싸고 Solar는 오판이 많음).

## 4. 탐지하지 못하는 유형 (현재 범위 밖)
| 유형 | 예 | 이유 |
|---|---|---|
| 개정안이 새로 만드는 관계 | 인용 번호를 바꿔 새로 가리키게 되는 조(시험 T058 · T098), 신설 조가 인용하는 조 | 그래프는 현행 규정만 담고, 개정안의 신설 · 변경 관계를 그래프에 넣지 않는다 |
| 같은 업무 · 같은 속성인데 표현이 다른 조 | 다른 규정의 같은 보관 의무(T060), 다른 인력군의 같은 사직 기한(B096) | 같은 값(`SAME_VALUE`)만 잇고, 「같은 속성 · 다른 값」 색인이 없다 |
| 이름 변경 이력 · 별표 주석 | 두 번 바뀐 부처 이름(B025), 별표 주석의 옛 지침 이름(T087) | 이름 변경 이력(별칭) · 별표 주석 검색이 없다 |
| 해석이 필요한 영향 | 정의 조 · 전제 · 같은 사항(놓친 정답은 모두 「확신 중간」) | 영향 여부가 규정 운영 방침에 달려 있다(현업 판단) |
| 웹 편집기의 조 삭제 | 조 전체 삭제 개정 | 웹 편집기는 조문 편집만 다룬다(리뷰 앱은 처리) |

따라서 「개정안 전체에 대한 영향 분석」이라고 쓰지 않는다. **현행 규정의 관계와 개정문의 바뀐 문구 · 의미 검색으로 찾을 수 있는 범위**에서 결과를 제시한다.

## 5. 향후 과제
| 구분 | 과제 | 성격 |
|---|---|---|
| 탐색 확장 | 개정안의 신설 · 변경 관계를 임시 그래프로 만들어 추론(현행 그래프와 분리) | 구현(적용기 · 추출기 재사용) |
| | 업무 · 행위 · 속성(기한 · 횟수 · 금액) 역색인, 「같은 속성 · 다른 값」 후보 | 구현 · 검증 |
| | 이름 변경 이력 · 별표 주석 검색 범위 | 구현 |
| 품질 | luna 답변: luna 이유 대신 후보 원문 인용 안에서만 쓰게 | 구현 |
| | 역량 질문 기반 테스트(수정 종류별로 반드시 찾을 조) · 그래프 제약 검사 | 구현 |
| 운영 | 확정된 개정을 파싱 · 그래프 · 색인에 반영, 후속 조치 처리 추적 | 구현 |
| 검증 | 현업 검수로 영향 · 충돌 정답 확보 → 실제 업무 기준 재현율 · 정밀도, 애매한 유형의 판단 기준 | **현업 필요** |
| | 새 관계 유형 발견: 놓친 사례 → 역량 질문 → 추가 · 검증을 반복 | 지속 운영 |
| | 독립 평가셋(시험 100은 개발용이 됨) | 데이터 |

온톨로지와 지식 그래프를 계속 고쳐 나가야 하는 것은 변하는 도메인을 다루는 시스템에 공통된 운영 과제다. 이번 프로젝트의 성과는 온톨로지를 완성한 것이 아니라, **미리 정의한 관계만으로 놓치는 영향 조항을 의미 검색으로 보완하고 그 효과를 제한된 평가셋에서 정량적으로 확인한 것**이다.

## 보고서용 문단
> 본 시스템은 규정 간 명시적 참조 관계와 수정 종류별 추론 규칙을 갖춘 개정 영향 온톨로지로 영향 후보를 탐색하고, 의미 검색으로 사전에 정의되지 않은 관계를 보완한다. AI 초안 라벨 기준으로 규칙만 쓸 때 시험 재현율 0.620이 의미 검색 · LLM 선택을 더해 0.900(문항당 약 6개)이 되었다. 다만 개정안이 새로 만드는 관계, 표현이 다른 같은 업무의 조항, 이름 변경 이력은 현재 범위 밖이며, 영향 여부의 최종 판단은 담당자가 한다. 실제 규정 개정에서는 새로운 참조 · 업무 의존 · 용어 변경이 계속 생기므로 이를 초기 온톨로지에 완전히 반영하는 것은 현실적으로 어렵고, 이는 변화하는 도메인을 다루는 온톨로지 · 지식 그래프 운영의 공통 과제다. 향후 개정안의 신규 관계를 임시 그래프로 반영하고, 업무 · 속성 기반 탐색을 확장하며, 현업 검토 결과를 온톨로지와 검증 규칙 개선에 반영하는 체계가 필요하다. 현재 평가는 현업 검증 이전의 라벨을 기준으로 하므로, 전문가 확인 데이터로 실제 업무 관점의 재현율과 충돌 후보의 타당성을 다시 평가해야 한다.
