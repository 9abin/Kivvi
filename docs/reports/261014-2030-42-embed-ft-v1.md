## 한 줄 요약
**LoRA 임베딩 튜닝은 성공 기준(후보 30 안 +5%p)을 못 넘었다.** 합성 질문 검증에서는 MRR 0.807 → 0.910으로 크게 좋아졌지만, 실제 평가 질문에서는 **차이가 없거나 약간 나쁘다.** 학습 없이 합성 질문을 색인에 붙이는 doc2query도 뚜렷한 이득이 없다. 90%로 가는 길은 튜닝이 아니라 **후보 풀 확대, 정의 항 용어 색인, 리랭커·k 조합**이다.

## 아침에 할 일 (순서대로)
1. 이 리포트의 「결과」와 「해석」을 읽고 튜닝을 접을지 정한다. (제 의견은 접기)
2. `docs/reports/261014-1700-40-embed-stage0.md`의 다음 단계 제안 중 **후보 풀 30 → 50~100**과 **용어 → 정의 항 색인**을 가빈에게 넘길 메모로 쓸지 정한다. (제가 메모를 써 드릴 수 있음)
3. 판정표 4개가 비어 있다 (아래 「사람이 남긴 일」). 정밀도 표본 30건이 가장 중요하다.
4. 커밋 여부 (맨 아래 「커밋 안 한 파일」 참고). 아직 아무것도 커밋하지 않았다.

## 결과
### 학습
- 데이터: 합성 질문 5,316개(GPT-5.4 mini, 간접 2,805 · 구어 1,519 · 검색어 1,486 중 자동 검사 통과분), 학습 4,900 + 검증 416(규정 9개를 통째로 분리). 질문마다 어려운 오답 4개(기본 모델 상위 30 중 같은 조 제외, reranker로 false negative 방지).
- LoRA(r=16, 학습 파라미터 710만, 전체의 1.2%), 2에폭, 배치 24, 학습률 1e-4, 31분 (RTX 4070 노트북 8GB, 최대 6.9GB).
- 검증(합성 질문, 검증 규정 청크 풀): 조 단위 MRR **0.807 → 0.910(1에폭) → 0.905(2에폭)**, Recall@10 0.990 → 1.000.

### 평가: 하이브리드 후보 단계 (가빈 4목록 RRF), 후보 N개 안 정답 근거 재현율 (색인에 있는 근거 기준)
| 세트 | 모델 | @10 | @30 | @50 | @100 |
|---|---|---|---|---|---|
| **개발용** 94문항·근거 126곳 (설정을 고르며 본 세트, 가빈이 라벨 보강) | 기준선 bge-m3 | 0.659 | 0.841 | 0.881 | 0.937 |
| | LoRA 효과 1.0 | 0.659 | 0.817 | 0.889 | 0.921 |
| | LoRA 효과 0.5 | 0.675 | 0.841 | 0.897 | 0.913 |
| **시험용** 81문항·근거 110곳 (안 본 세트, 원본 라벨) | 기준선 bge-m3 | 0.818 | **0.964** | 0.973 | 0.973 |
| | LoRA 효과 1.0 | 0.800 | 0.918 | 0.964 | 0.982 |
| | LoRA 효과 0.5 | 0.845 | 0.945 | 0.973 | 0.982 |
- 성공 기준 **미달**: @30에서 개발용 +0.0%p(0.5)·−2.4%p(1.0), 시험용 −1.9%p(0.5)·−4.6%p(1.0). 근거 126곳에서 1곳이 0.8%p, 110곳에서 0.9%p라 ±1~3곳 차이는 잡음 범위.
- LoRA 효과 0.5(기본 모델과의 보간)가 1.0보다 낫다: 튜닝이 기본 모델의 일반 능력을 조금 해친다는 뜻.
- 시험용의 기준선이 이미 @30에서 0.964라 올릴 여지가 거의 없다. 시험용 라벨은 가빈이 교차 검증한 개발용보다 느슨하다. 두 세트의 절대 점수는 직접 비교하지 않는다.
- 벡터 단독(원질문) 숫자와 BM25까지 포함한 전체 표는 `data/embedding/eval_ft_dev.txt`, `eval_ft_holdout.txt`.

### doc2query: 합성 질문을 색인에 붙임 (학습 없음)
조 996개분(색인 조·별표의 약 47%)에만 질문이 있다. 질문이 붙은 조의 근거와 안 붙은 조의 근거를 나눠 보면 대조군 효과를 알 수 있다.
| 세트 | 방식 | @10 | @30 | @50 | @100 | 질문 붙은 조 근거 @30 | 안 붙은 조(대조군) @30 |
|---|---|---|---|---|---|---|---|
| 개발용 | 기준선 | 0.659 | 0.841 | 0.881 | 0.937 | 0.803 | 0.877 |
| | 벡터에 질문 붙임 | 0.619 | 0.794 | 0.810 | 0.849 | 0.852 | **0.738** |
| | **BM25에만 붙임** | **0.706** | 0.849 | 0.889 | 0.937 | 0.820 | 0.877 |
| 시험용 | 기준선 | 0.818 | 0.964 | 0.973 | 0.973 | 0.962 | 0.965 |
| | 벡터에 질문 붙임 | 0.727 | 0.873 | 0.900 | 0.973 | 0.943 | 0.807 |
| | BM25에만 붙임 | 0.818 | 0.964 | 0.973 | 0.973 | 0.962 | 0.965 |
- **벡터에 붙이면 반쪽 커버리지 편향이 생긴다.** 질문이 붙은 조는 점수를 받을 기회가 많아져 붙지 않은 조를 밀어낸다(대조군 0.877 → 0.738). 이 비교는 전체 조에 질문을 만들어야(약 2,300원 추가) 공정하다. 지금 숫자로는 판단하지 않는다.
- **BM25에만 붙이는 것은 안전하고 약간 도움**(개발용 @10 +4.7%p, @30 +0.8%p, 시험용 변화 없음). 효과는 작다.

## 해석
1. **왜 튜닝이 안 통했나.** 합성 질문은 GPT가 조문을 보고 그 조를 겨냥해 쓴 질문이라 기본 모델이 이미 63%를 3위 안에 찾는다(리포트 41). 모델은 이 쉬운 과제를 더 잘하게 됐지만(검증 MRR 0.81 → 0.91), 실제 평가에서 놓치는 질문은 「여러 조 중 비약된 하나」(유튜브 수익 → 겸직 금지, 챗GPT 요약 → 기밀 반출, 정의·적용 조항)라서 전이되지 않는다.
2. **어려운 오답으로도 부족했다.** 오답은 기본 모델의 상위 후보를 썼는데, 실제 오답 후보와 합성 질문이 만드는 구분이 평가에서 틀리는 구분과 다르다.
3. 이번 시험으로 **다음 시도의 조건**이 분명해졌다. 다시 한다면 (a) 실제 놓치는 유형을 닮은 질문(정의 조항, 적용·시행 조항, 간접 사례)을 조당 수 개씩 만들고, (b) 두 번째 근거까지 정답으로 묶는 다중 정답 학습, (c) 전체 조 커버(약 2,300원 추가)가 필요하다. 하지만 기대 효과가 작고 시간이 든다.

## 90% 목표에 대한 판단
후보 단계 재현율의 가장 큰 개선은 이미 확인된 것들이다 (리포트 40):
| 방법 | 개발용 후보 재현율 | 비용 |
|---|---|---|
| 지금 (후보 30) | 0.841 | |
| 후보 풀 50 | 0.881 (+4.0%p) | 리랭커 시간 |
| 후보 풀 100 | 0.937 (+9.6%p) | 리랭커 시간 |
| 용어 → 정의 항 색인 | 정의·적용 조항 3~4곳 (+3%p) | 규칙 기반, LLM 불필요 |
튜닝은 이 위에 얹어도 기대가 작다. 최종 근거 Recall은 리랭커와 k까지 거쳐 따로 재야 한다 (가빈 표: k=16이면 0.808).
