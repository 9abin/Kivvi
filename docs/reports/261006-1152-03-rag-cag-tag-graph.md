## 요약
로민 블로그(RAG·CAG·TAG 가이드, 벤더 자료)와 그래프 DB를 조항 오류 점검에 대입했다.
점검의 중심은 **TAG식 구조화 + SQL**이고, RAG는 의미 검사, CAG는 수정안 생성과 비교 기준선에 쓴다.
그래프는 **모델링 방식으로 채택하되 저장은 RDB**로 하자고 제안한다. 규모가 작고, 법률 DB가 RDB라서다.

## 1주차 사례로 본 핵심 사실
조문 번호 오인용 F1~F6 중 **인용한 조문이 아예 없는 경우는 F3 하나뿐**이다 (회계규정 「제128조」, 문서는 77조까지).
나머지(F1·F2·F4·F5·F6)는 인용 대상 조문이 **존재하지만 내용이 다르다** (예: F1 인사규정 제6장은 존재하지만 퇴직이 아니라 휴직).
→ 구조 검사(SQL이든 그래프든)로는 F3만 잡힌다. 나머지는 인용 문맥과 대상 조문 제목·본문을 비교하는 **의미 검사**가 있어야 한다.

## 기법별 적용
| 기법 | 블로그 정의 | 에이전트에서의 자리 | 판단 |
|---|---|---|---|
| TAG | 구조 보존 + SQL로 계산·다단계 추론 | 법령 개정 미반영, 없는 조문 인용, 규정 간 인용, 구 명칭 → 전부 테이블 질의. 수치 충돌도 "LLM이 (주제, 조건, 값) 추출 → SQL 비교"로 바꾸면 재현 가능 | **중심** |
| RAG | 검색 결과를 LLM 입력에 결합 | ① 의미 검사: 인용 문맥 ↔ 대상 조문 불일치 (F1·F2·F4~F6) ② 암묵적 관련: 같은 주제의 법조문·규정 조문 후보 쌍 찾기 | 보조 (후보 생성) |
| CAG | 문서를 컨텍스트에 미리 올리고 KV 캐시 | 규정 1건 전문은 컨텍스트에 들어감 (최대 4.2만 자). 전체 83만 자는 불가. ① 비교 실험의 "LLM 단독" 기준선이 사실상 CAG ② 수정안 생성 시 **내규관리규정 제9~18조(조문 형식, 개정 시 가지번호·삭제 표시)를 고정 컨텍스트**로 두면 수정안이 회사 작성 형식을 따름 | 수정안·기준선 |
| Agentic 라우팅 | 질문 유형별 동적 선택 | 에이전트는 질문이 아니라 오류 유형별로 고정 파이프라인이 정해져 있음. LLM 라우터를 넣으면 평가 재현성만 떨어짐 | **도입 안 함** (챗봇 쪽 주제) |

## 그래프 DB
데이터 자체는 그래프다.
- 노드: 규정, 조문(버전), 법령, 법조문(버전), 용어
- 엣지: 인용(조문→조문, 조문→법조문), 위임(지침→규정), 대체(새 버전→옛 버전, 부칙 번호 리다이렉트), 이관(구법 조문→벤처투자법 조문), 명칭 변경

| 그래프가 유리한 곳 | 설명 |
|---|---|
| 다단계 영향 | 법 개정 → 그 법을 인용한 규정 조문 → 그 조문을 인용한 지침 조문. 원본 기획은 1단계 조인만 다룸 |
| 이관 경로 | 구 법률 → 벤처투자법 같은 연쇄 추적 |
| 구조 이상 | 끊긴 인용, 순환 참조, 아무도 인용하지 않는 조문 |
| 시각화 | 검토 화면과 발표에서 영향 범위를 그림으로 보여주기 |

| 그래프 DB(Neo4j 등)를 지금 안 쓰는 이유 | |
|---|---|
| 규모 | 노드 약 2.5천, 엣지 약 1.7천(근사). RDB 재귀 질의(`WITH RECURSIVE`)로 충분 |
| 법률 DB와의 조인 | 한석희 법률 DB는 RDB. 저장소가 둘이면 규정↔법령 조인이 어려움 |
| 폐쇄망·일정 | 시스템 하나 추가, 남은 기간 2주 |
| 의미 검사 문제 | 위 F 사례처럼 핵심 난제는 구조가 아니라 의미 불일치. 그래프로 해결되지 않음 |

GraphRAG(문서 묶음 요약 방식)는 질의응답용이라 오류 탐지와 맞지 않는다.

## 주요 결정 (제안)
| 결정 | 이유 | 대안 |
|---|---|---|
| 그래프로 모델링, RDB에 저장 (인용·위임·대체·이관을 엣지 테이블로) | 규모 작음, 법률 DB와 같은 저장소 | Neo4j 별도 구축 |
| 다단계 영향은 `WITH RECURSIVE`, 분석·시각화는 NetworkX로 메모리 적재 | 추가 시스템 없음 | 그래프 DB 질의 |
| PostgreSQL 선택 시 Apache AGE(같은 DB에 Cypher)를 예비안으로 둠 | 다단계 질의가 복잡해지면 저장소 이동 없이 전환 | — |
| 내부 참조 오류를 "없는 조문"(규칙)과 "대상 불일치"(의미 검사)로 분리 | 1주차 사례 6건 중 5건이 후자 | 하나로 처리 |
| 비교 실험에 "1단계 vs 다단계 영향 분석" 추가 검토 | 그래프 모델링의 효과를 수치로 보여줌 | — |
