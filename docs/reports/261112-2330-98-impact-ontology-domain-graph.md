# 98. 개정 영향 온톨로지의 정의 · 도메인 그래프 제외

작성 261112. 관련: [리포트 93](261111-1500-93-candidate-state-pipeline.md), [97](261112-2200-97-decide-input-luna-prompt.md). 코드: `src/regcheck/kg.py` `ONTOLOGY`, `collect.py`, `eval/relabel_v2/run_eval.py`.

## 개정 영향 온톨로지
스키마와 추론 규칙을 갖춘 의존 관계 지식 그래프(경량 온톨로지). 세 층이다.

| 층 | 내용 | 언제 |
|---|---|---|
| 스키마 | 노드 9종(규정 · 조 · 부칙 · 별표 · 서식 · 용어 등), 관계 18종(인용 · 정의 · 용어 사용 · 제목 언급 · 같은 제목 · 같은 값 · 위임 등), 상하위 · 규정 위계 제약 | 설계 |
| 지식 그래프 | 스키마에 따라 규정에서 뽑은 연결(노드 약 3,500 · 연결 약 13,000, `out/kg`) | 미리 구축 |
| 추론 규칙 | 수정 종류별로 따라갈 관계 · 방향 · 가중치(`change_paths`). 예: 삭제면 그 조를 인용하는 조 | 개정이 들어올 때 |

- 일반적인 지식 그래프가 미리 정의한 **사실**로 질문에 답한다면, 이 온톨로지는 규정 사이의 **의존 관계**를 미리 연결해 두고 개정이 들어오면 **영향이 갈 수 있는 후보**를 추론한다. 변경의 경우의 수는 미리 만들 수 없으므로 그래프는 결과가 아니라 추론의 재료를 담는다. 소프트웨어 변경 영향 분석(의존성 그래프 + 리뷰)과 같은 구조다. 온톨로지는 놓치지 않는 것(재현율), 판단 모델 · LLM은 거르기와 근거, 담당자는 최종 판단을 맡는다.
- 형식 언어(OWL)나 자동 추론기는 쓰지 않는다. 「온톨로지가 영향을 판단한다」고 쓰지 않는다.

## 후보 출처의 이름
| 출처 | 내용 | 미리 만드나 |
|---|---|---|
| 온톨로지 경로 | 지식 그래프 관계를 추론 규칙대로 따라감(번호 인용, 용어 사용, 제목 언급 등) | 예 |
| 개정문 낱말 일치 | 개정에서 나온 낱말을 원문에서 검색(지워진 낱말 `DELETED_TERM`, 바뀌기 전 말 `OLD_PHRASE`, 새 말 `PHRASE`, 용어 핵심부 `TERM_CORE`) | 아니오(개정마다 낱말이 다름) |
| 의미 검색(RAG) | 임베딩 + 키워드 | — |

앞의 둘(지금까지 「규칙 후보」)은 찾은 이유를 코드로 설명할 수 있어 판단 모델로 거르고, RAG 후보는 luna가 고른다.

| 검색 풀 출처 | 개발 문항당 · 찾은 정답 · 혼자 찾은 정답 | 시험 |
|---|---|---|
| 온톨로지 경로 | 5.2 · 43 · 5 | 4.3 · 18 · 1 |
| 개정문 낱말 일치 | 3.2 · 19 · 1 | 4.2 · 21 · 0 |
| RAG | 56.5 · 70 · 28 | 57.6 · 43 · 10 |
| (제외) 도메인 그래프 | 32.5 · 42 · 1 | 41.1 · 30 · 0 |

## 도메인 그래프 제외 (결정)
도메인 그래프(한석희 scoped graph, `graph_source.GraphSource`)는 사실을 담는 범용 그래프이고 수정 종류별 추론 규칙이 없다.
- 최종 목록 정답 중 도메인 그래프만 찾은 것: 개발 0 · 시험 0. 도메인 그래프가 찾은 정답은 대부분 온톨로지 경로도 찾았다(조를 인용함 `specific_reference_in` 정답 개발 14/14 · 시험 7/8이 우리 `CITES_in` 등과 겹침). 같은 「인용」인데 우리 경로와 겹치는 후보는 4~8%뿐이고 나머지는 정답이 없다.
- 후보 폭증: 위임 연결(`regulation_delegation_out`)이 개발 2,053 · 시험 2,585개(정답 비율 0.5~0.7%), 문항당 최대 600개 이상.
- 확인 신호로는 쓸모가 있었다(RAG + 그래프 후보 정답 비율 0.018 · 0.010 vs RAG만 0.006 · 0.002). 그러나 그 정답은 luna가 이미 거의 다 골랐다(안 고른 것 개발 1 · 시험 0).

| 그래프 빼면 | 개발 | 시험 |
|---|---|---|
| 검색 재현율 | 0.989 → 0.978 (잃는 B096은 원래 luna 입력 전에 잘림) | 0.940 그대로 |
| 검색 풀 문항당 (최대) | 88.4 (660) → 62.5 (97) | 96.7 (634) → 63.5 (105) |
| 최종 재현율(추정: 기존 luna 선택 재사용) | 0.934 그대로 | 0.900 그대로 |

- 평가 후보 풀은 그래프 경로를 걷어 냈다(`out/relabel_v2/pool_<세트>.json`, 이전은 `pool_<세트>_with_domain.json`). 그래프는 다른 후보를 다 모은 뒤 덧붙이는 방식이라 걷어 낸 풀은 처음부터 빼고 검색한 것과 같다. 최종값은 luna를 다시 돌리지 않은 추정이다(luna 입력에서 그래프 우선 순서가 빠져 입력 50개 구성이 조금 달라짐).
- `graph_source.py`는 남겨 둔다(넘기면 예전처럼 동작). 다시 쓴다면 도메인 관계에 수정 종류별 추론 규칙을 붙이고 겹치는 관계는 근거 확인 표시로 쓰는 방식이어야 한다. 팀(한석희)과 공유 필요.
- 확인하지 못한 것: 드문 유형(이름 없는 위임 · 준용, 리포트 93에서 그래프만 찾음), 그래프 경로 설명이 luna 판단에 주는 효과.
