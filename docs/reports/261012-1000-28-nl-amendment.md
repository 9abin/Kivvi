## 요약
"인사규정 육아휴직 분할 횟수를 3회로 늘려줘" 같은 요청 → 대상 규정·조 찾기(규칙) → **삭제·신설·번호 이동은 규칙으로**, 문구 수정은 **로컬 LLM이 조문을 다시 쓰면 우리가 비교해 개정문 생성** → 적용기 + **의도 검사**로 검증 → 실패하면 오류를 돌려주고 다시(최대 3회) → 연쇄 수정 에이전트.
qwen2.5:7b, 요청 8개(내가 쓴 것, 독립 아님): **7/8 성공, 요청 밖 변경 0, 두 번 돌려 같은 결과**. 1개(N03)는 3번 모두 걸러져 실패 — 틀린 결과가 나가지 않음.

## 경과 (같은 요청 8개)
| 단계 | 성공 | 무엇을 바꿨나 |
|---|---|---|
| 개정문만 쓰게 함 | 2/8 | — |
| + 조문 다시 쓰기(B) → 우리가 비교해 개정문, 「제24조(인병휴가) 중」 정리 | 7/8 | 작은 모델은 개정문 문법보다 조문 다시 쓰기를 잘함 |
| 그러나 다음 회차 N07이 「제8조를 다음과 같이 한다」(기존 하부조직 조를 덮어씀)로 **적용은 되는데 틀림** | — | 형식 검증만으로는 부족 |
| + 의도 검사(신설·삭제·번호 이동 누락, 다른 제목으로 통째 교체, 요청 밖 변경) | 5/8 | 틀린 초안 0건 통과 |
| + 삭제·신설·번호 이동은 규칙으로, 조 제목이 조 번호보다 우선 | **7/8 (2회 동일)** | 규칙 2, LLM 5 |
qwen3.5:9b는 6/8로 7B보다 나쁘거나 비슷 → **qwen2.5:7b (4.7GB) 채택**. 요청당 4~11초.

## 주요 결정
| 결정 | 이유 | 대안 |
|---|---|---|
| LLM은 조문 다시 쓰기, 개정문은 우리가 비교로 생성 | 7B가 개정문 문법을 자주 틀림(따옴표 범위·항 지칭). 다시 쓰기는 잘함. 비교는 결정적이라 재현됨 | LLM에 개정문 직접 (2/8) |
| 의도 검사로 "적용은 되지만 틀린" 초안 재시도 | N07에서 기존 조를 덮어쓴 초안이 적용기를 통과 | 형식 검증만 |
| 삭제·신설·번호 이동은 규칙 | 구조 변경은 요청 문장에서 확실히 읽히고, LLM이 가장 약한 부분 | 모두 LLM |
| 요청에 적힌 조 제목 > 조 번호 | 「제128조를 제71조로」의 번호는 고칠 인용이지 대상이 아님 | 번호 우선 |
| 로컬 7B, 외부 API 없음 | 개정 초안은 민감(S) 정보, 폐쇄망 (AGENTS §4) | 클라우드 모델 |
