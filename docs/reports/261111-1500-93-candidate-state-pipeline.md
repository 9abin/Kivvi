## 요약
후보마다 state(출처 · 경로 · 단계별 결과 · 기록)를 두고, 출처에 따라 코드가 할 일을 정한다. 규칙 후보는 판단 모델로 거르고 근거는 코드가 만든다. 그래프 · RAG 후보는 luna가 후보 목록을 함께 보고 고르면서 고른 것에만 근거를 쓴다. 최종 문장은 LLM이 출처별 입력(규칙 = 원인 · 결과, 그래프 · RAG = 검증된 luna 근거)을 읽고 쓴다.

## 주요 결정
| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 출처 · 경로 · 라우팅은 코드가 state에 고정 | LLM이 「할 일인지」 추측하지 않게. 단계별로 무엇을 했는지 추적 · 평가가 된다 | 출처를 그때그때 경로 문자열에서 추측 (`is_rule`) |
| 규칙 후보는 판단 모델 거르기만, 근거는 코드 | 경로와 원문 인용이 코드로 확실하다(리포트 74). luna를 쓸 이유가 없다 | 모든 후보를 luna로 |
| 그래프 · RAG는 luna **목록** 리랭킹, 고른 것에만 근거 | 후보끼리 비교해 일관성, 같은 점수 묶음 없음, 호출이 개정당 1회라 싸다 | 후보별 0~3점(지금 방식), 관계 유형만 후보별로 |
| luna 입력에 「찾은 경로」(사실)는 넣고 단계 · 점수는 넣지 않는다 | 경로는 판단 재료, 단계 · 점수는 모델이 따라가 버린다 | 경로 없이 (지금 방식) |
| 후보 순서를 섞고 id는 C1… 별칭으로 | 검색 순위가 새어 들어가지 않게, id 옮겨 쓰기 오류 방지 | 검색 순서 그대로 |
| luna 근거 구절은 원문 대조 통과분만 다음 단계로 | LLM 인용의 33~50%가 원문과 글자가 달랐다(리포트 92) | 그대로 전달 |
| 답변 LLM 출력은 `explain.valid`로 검사 | 단정 표현 · 입력에 없는 조 번호 · 숫자 차단(기존 규칙 재사용) | 검사 없이 |
| luna 입력 = RAG가 찾은 후보 상위 50(도메인 그래프도 찾은 것 먼저), 도메인 그래프만 찾은 후보는 넣지 않음, orders 2 (`pick_for_luna` 기본값, 261111 val) | val 검색 단계: 그래프만 후보 10~20개를 더 넣어도 정답 +0, 함께 찾은 것 먼저면 상위 50 안 정답 15→16 | 출처별 상한 RAG 30 · 그래프 20 (처음 기본값) |
| 도메인 그래프는 `impact_view.run(graph=…)`일 때만 | 리포트 92에서 기본에 넣지 않기로 함. 이 구조에서는 luna가 거르므로 다시 잴 가치가 있다 | 기본 켬 |

## 확인한 것 (실행 아님, 로컬)
- 단위 테스트 11개(가짜 luna · 가짜 답변 모델) + 기존 전체 478개 통과.
- 도메인 그래프 연결부를 val 30문항에 불러 봄: 그래프 후보 1,625개(평가 때) → 1,976개(+351). 그래프 탐색은 같고 부르는 조건이 다르다.
  - 표현 수정 +315: 평가 때는 collect가 표현 수정이면 그래프를 부르지 않았다. 새 방식은 모든 수정 종류에서 부른다(V03 108, V23 199).
  - 조 삭제 +75 / −54: 평가 때는 조 전체 삭제를 「바뀐 항 없음」으로 읽었다(입력 버그와 같은 원인). 새 방식은 삭제된 조의 모든 항을 시작점으로 넣는다.
  - 번호 이동 범위 안의 조 +15: 평가 때는 뺐다.
  - 번호 이동 문항당 약 500개는 평가 때도 같았다(463~472).
  - **결정: 그대로 둔다.** 검색 단계라 놓치지 않는 쪽을 택한다. 거르기는 luna가, 비용은 자르기(n_graph)가 정한다. n_graph는 val에서 「상위 n 안에 남는 정답」으로 정한다(luna 호출 없음).

## val 결과 (261111, 평가셋 v2, 정답 = 확신 높음 · 중간 38개)
순서는 거르기 전에 이미 가중치로 정해진다: 등급(확정급 → 확인 권장 → 참고) → 찾은 경로 종류 수 → 경로 가중치 점수 → 항 질의 의미 검색과 순위 합치기 → 도메인 그래프만 찾은 후보는 맨 뒤.

```
가중치 순위
 ├─ 규칙 후보 ─▶ 판단 모델: 거르기만 (순서는 가중치 순위 그대로)
 └─ RAG + 도메인 그래프 후보 ─▶ 함께 찾은 것 먼저 RAG 상위 50 + 그래프만(위임 · 언급 연결) 10
                                 ─▶ luna: 거르기 + 순서 + 근거(원인 구절 · 결과 구절 · 이유)
```

| 목록 | 문항당 후보 | 재현율 | 상위 3 | 상위 5 | 상위 10 | 정밀도 |
|---|---|---|---|---|---|---|
| 검색 전체 | 125.6 | 97% | 37% | 50% | 68% | 1.0% |
| 거르기 전 (리랭커 입력) | 64.2 | 95% | 42% | 53% | 63% | 1.9% |
| **거른 뒤 (최종 목록)** | **8.4** | **92%** | 47% | 58% | **82%** | **13.9%** |

| 리랭커 | 후보 (전 → 후) | 넘겨받은 정답 중 남김 | 정밀도 (전 → 후) |
|---|---|---|---|
| 규칙: 판단 모델 (문턱 0.5) | 11.6 → 3.9 | 19/20 | 5.7% → 16.2% |
| RAG + 도메인 그래프: luna 목록 | 52.6 → 4.5 | 16/16 | 1.0% → 11.9% |

- 근거: luna 정답 후보의 원인 · 결과 구절 원문 일치 100%, 답변 검사 통과 250/252. 규칙 후보 원문 인용은 21/117(남은 약점). luna 비용 약 $0.24(호출 60회, orders 2).
- 이전 점수(0~3) 방식과 비교: 같은 입력에서 상위 10 76% → 82%, 목록 재현율 82% → 92%(단 점수 판정 없는 후보 30%를 0점으로 둠).

| 확인한 것 | 결과 | 결정 |
|---|---|---|
| 판단 모델 점수 순으로 규칙 후보 정렬 | 상위 3 47% → 39% | 되돌림. 판단 모델은 거르기만 |
| 함수(등급 · 경로)로 규칙 후보 거르기 | 최종 100: 등급 함수 3.9개 · 정답 40, 판단 모델 3.3개 · 48 | 판단 모델 유지 |
