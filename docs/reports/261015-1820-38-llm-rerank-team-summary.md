# 261015-1820 LLM 2단계 리랭커 도입 결과 정리 (팀 공유용)

저장소 `kvic-internal-regulations-review`. 상세는 [보고서 36](./261015-1536-36-llm-rerank.md)(도입·측정)과 [보고서 37](./261015-1650-37-llm-rerank-prompt-lab.md)(프롬프트 변형 실험).

## 0. 한 줄 결론

LLM 리랭커는 **검색 순위는 분명히 올리지만(R@5 +5~10p), 최종 답변 정확도는 사람이 나눈 필수 요지 기준(tiered)으로 정답 54 → 56, 흔들림 범위**다. 오답·금지 위반은 줄고 답못함은 늘며, 응답은 2.5초 느려진다. **기본값은 끔으로 두고**, 답못함 부작용을 막는 장치를 넣은 뒤 다시 판단한다.

## 1. 기준 구성과 바뀐 점

**기준 구성 (2026-10-15 확정)**: 팀 DB 항 단위 색인(`regulations_team`) → 항으로 검색·리랭크 → 답변에는 조 전체를 넘김(`RETURN_ARTICLE=1`). `HIGHLIGHT_HITS`·`LAW_CITES_FROM_HITS`도 기본 켬. 이 PC의 조 단위 색인 `regulations`는 실험용 잔재이며 기준이 아니다.

검색 파이프라인은 세 단계다.

1. **RRF 합침**: 벡터(BGE-m3) + BM25 결과를 RRF로 결합해 상위 30개 항을 뽑는다.
2. **cross-encoder**: `BAAI/bge-reranker-v2-m3`가 질문과 항을 쌍으로 다시 채점한다 (기존).
3. **LLM 리랭크 (신규, `LLM_RERANK=1`, 기본 끔)**: cross-encoder 상위 15개를 `gpt-4o-mini`가 항마다 독립 채점(0~10점)해 다시 정렬한다. 16위 이하는 그대로. 그 뒤 조 단위로 묶어 서로 다른 조 5개를 답변에 넘긴다.

왜 넣었나: 정답이 리랭크 창(30개) 안에는 있는데 6위 이하로 밀린 경우가 34~39묶음이었고, 창을 넓히거나 합치는 실험은 효과가 없었다. 병목이 cross-encoder의 판단이라 그 위에 LLM을 한 번 더 얹었다.

## 2. 최종 판단 기준: 답변 평가 (새 100문항, tiered 채점)

같은 100문항(`answer_eval_100_new.jsonl`)으로 cross-encoder만(`ce_v2`)과 LLM 리랭크(`llm_v2`)를 돌려 답변을 만들고, **사람이 정답요지를 필수·보조로 나눈 파일**(`answer_eval_100_tiered.jsonl`, 질문·id는 동일)로 채점했다. 필수 요지를 모두 담고 금지 위반이 없으면 정답, 보조 요지는 판정에 쓰지 않는다.

| tiered 채점 | cross-encoder | + LLM 리랭크 |
|---|---|---|
| 정답 | 54 | **56** |
| 부분 | 38 | 31 |
| 오답 | 3 | 5 |
| 답못함 | 5 | 8 |
| 금지 위반 | 3 | 4 |
| 문항별 (LLM 기준) | - | 좋아짐 11 / 같음 79 / 나빠짐 10 |

같은 설정을 다시 돌려도 판정이 10문항 안팎 흔들리므로, **tiered 기준으로는 차이가 없다**고 보는 것이 맞다.

**난이도·유형별 (tiered 정답 수)**

| 구분 | n | cross-encoder | + LLM |
|---|---|---|---|
| 쉬움 | 18 | 16 | 16 |
| 보통 | 41 | 23 | 24 |
| 어려움 | 41 | 15 | 16 |
| 일부만답가능 | 26 | 7 | **12** |
| 수치기준 | 24 | 17 | 18 |
| 잘못된전제 | 16 | 9 | 10 |
| 복수조문종합 | 10 | 6 | **4** |
| 예외단서 | 8 | 5 | 4 |
| 단일조문사실 | 7 | 5 | 5 |
| 규정에없음 | 5 | 4 | 3 |
| 개별사정 | 4 | 1 | 0 |

난이도별 차이는 없다. 유형별로는 "일부만 답 가능" 질문이 크게 좋아지고, 여러 조문을 모아야 하는 "복수조문종합"과 "규정에 없음"은 나빠진다. LLM이 보조 조문을 낮게 점수 매겨 떨어뜨리면 모델이 "확인되지 않음"으로 답하는 패턴이다(미국 출장 일비, 장기근속 포상, 예비군 공가).

**다른 두 채점 모드 (참고)**

| 모드 | 기준 | cross-encoder 정답/부분/오답/답못함 | + LLM | 승/패 |
|---|---|---|---|---|
| strict | 정답요지 전부 필요 | 31 / 54 / 9 / 6 (금지 8) | 33 / 53 / 6 / 8 (금지 5) | 11 / 8 |
| question | 채점 모델이 필수 요지를 스스로 고름 | 51 / 38 / 6 / 5 (금지 5) | **58** / 31 / 3 / 8 (금지 3) | 18 / 9 |

question 모드에서만 흔들림 폭을 넘는 개선(정답 +7, 오답 −3)이 보이지만, 채점 모델의 판단이 끼어 있어 tiered보다 후하다.

**RAGAS와 응답 시간**

| 항목 | cross-encoder | + LLM |
|---|---|---|
| 충실도 (faithfulness) | 0.878 | 0.871 |
| 답변 관련성 (answer relevancy) | 0.970 | 0.976 |
| 문맥 재현 (context recall, 81문항) | 0.714 | 0.712 |
| 첫 토큰 중앙값 | 8.1초 | 10.5초 |
| 답 완성 중앙값 | 10.9초 | 13.4초 |
| 근거 검사 끝 중앙값 | 16.1초 | 18.6초 |
| 보류 | 3 | 3 |

RAGAS 세 값은 모두 차이 없음. 지연은 LLM 15회 병렬 호출이 검색 뒤에 끼어 첫 토큰이 2.4초 늦어진 것이다. 같은 질문은 캐시로 0초.

## 3. 검색 단계 지표 (93문항, 팀 DB 항 단위)

답변 평가와 별개로, 검색 순위만 재는 평가셋(`questions_100_retrieval.jsonl`, 93문항, 정답 근거 묶음 147개)에서의 결과다.

| 지표 | RRF 합침 | cross-encoder | **+ LLM 리랭크** |
|---|---|---|---|
| Recall@1 (묶음) | 0.252 | 0.259 | **0.313** |
| Recall@3 | 0.449 | 0.490 | **0.578** |
| Recall@5 | 0.544 | 0.565 | **0.619** |
| Recall@10 | 0.619 | 0.714 | 0.721 |
| Hit@1 (문항) | 0.398 | 0.409 | **0.495** |
| Hit@5 | 0.688 | 0.763 | **0.796** |
| 전부 5위 안 (문항) | 44 | 46 | **50** |
| MRR | 0.538 | 0.563 | **0.637** |
| Context Precision@5 | 0.434 | 0.451 | **0.525** |
| 6위 이하 (묶음) | 49 | 34 | **26** |
| 창 밖 (묶음) | - | 12 | 12 |

문항별 첫 정답 순위: 개선 23 / 동일 58 / 악화 12. 참고로 조 단위 색인 `regulations`에서는 R@5 0.578 → 0.680, MRR 0.603 → 0.686으로 폭이 더 크다. 항 단위에서는 같은 조의 항들이 리랭크 창 30자리를 나눠 차지해 LLM이 손댈 수 있는 범위가 좁기 때문이다.

**검색 지표와 답변 지표가 어긋나는 이유**: 검색 평가는 정답 조가 5위 안에 있는지만 본다. 답변 평가는 그 조로 답을 맞혔는지를 본다. LLM 리랭커는 정답을 위로 올리는 만큼 보조 조문을 아래로 내리는데, 답변 모델은 보조 조문이 없으면 "확인되지 않음"으로 물러선다. 그래서 순위는 좋아져도 답못함이 늘어 상쇄된다.

## 4. 프롬프트로 더 올릴 수 있나 (보고서 37)

팀 DB 93문항에서 LLM 리랭크 뒤에도 5위 밖인 56묶음을 분류하면: 리랭크 창 밖 30, 창 안이지만 15개 밖 5, LLM이 정답에 7점 이하 21, 오답이 정답보다 높은 점수 0. 프롬프트가 손댈 수 있는 건 21묶음뿐이다.

변형 6개(정의 조문 감점 제거, 별표 조각 규칙, 위임 조문 규칙, 보조 검색어 포함, TOP 30)를 GPU 없이 돌린 결과, 최고 변형이 R@5 0.619 → 0.633(+2묶음)으로 **재호출 흔들림 폭과 같다**. 정의 감점 제거 단독은 오히려 나빴고(−4), TOP 30은 호출 2.3배에 +1묶음이다. 저평가 21묶음 중 구제된 건 최대 4묶음이고, 그중 2건(미국 일비, 본인 결혼 경조금)은 정답 라벨이 잘못된 쪽에 가깝다. 프롬프트는 바꾸지 않았다.

## 5. 지표 용어

- **Recall@k (묶음)**: 정답 근거 묶음 147개 중 k위 안에 든 비율. 한 질문에 정답 조문이 여럿이면 묶음도 여럿.
- **Hit@k (문항)**: 93문항 중 정답 하나라도 k위 안에 든 비율.
- **전부 5위 안**: 그 문항의 정답 묶음이 모두 5위 안에 든 문항 수. 답변 품질과 가장 직결.
- **MRR**: 문항별 첫 정답 순위의 역수 평균.
- **Context Precision@5**: RAGAS의 context precision과 같은 식. 상위 5개 안에서 정답이 나온 자리마다의 정밀도 평균.
- **6위 이하 / 창 밖**: 정답이 리랭크 창(30개) 안이지만 6위 이하 / 창에 아예 못 든 묶음 수.
- **strict / question / tiered**: 데이터셋이 아니라 채점 방식. 같은 답변을 세 기준으로 채점한 것.
- **충실도·관련성·문맥 재현**: RAGAS의 faithfulness, answer relevancy, context recall. 답변 생성 후 LLM이 매긴다.

## 6. 판단과 다음 단계

1. **기본값은 끔 유지.** tiered 기준으로 정답 +2, 답못함 +3, 지연 +2.5초라 켤 근거가 약하다.
2. **답못함 부작용 차단 후 재측정**: LLM 점수가 낮아도 cross-encoder 상위 몇 개는 버리지 않거나, 복수조문·규정없음 유형에서는 LLM 점수 가중을 낮추는 안전장치를 넣고 같은 100문항으로 다시 잰다.
3. **남은 손실은 1차 검색**: 창 밖 30묶음(20%)은 리랭커가 못 고친다. 동의어·BM25 가중치·쿼리 확장 과제로 분리.
4. **정답 라벨 점검**: 미국 일비(`별표5_04` → `별표5_01`), 본인 결혼 경조금(`복무규정 별표1`은 경조휴가 표).
