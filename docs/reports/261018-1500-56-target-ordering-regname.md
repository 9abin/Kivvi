# 261018-1500 규정 이름 대충 쓴 요청 인식, 위치 후보 5개, 순서 매기기(순위 섞기 + 적용 대상 규칙)

- 관련: [55 개정 위치 찾기 임베딩](261018-1100-55-target-embed.md), [51 독립 평가](261016-0100-51-independent-eval.md) §2(자연어 D 말투), §2-2(규정·조 찾기), [53 RAG 조합](261016-1800-53-rag-combo-results.md)(적용 대상이 다른 규정이 1위로 오는 문제)
- 변경 범위: `src/regcheck/nl.py`(비슷한 이름 찾기), `src/regcheck/target.py`(이름 인식 공유, 순서 매기기, 확실함 판단), `app/web_server.py`(`/api/find` 추정 · 애매한 이름의 같은 조 후보), `app/web/app.js`(「○○로 이해했습니다」), `app/web_agent.py`(후보 5개), `scripts/eval_target_rag.py`(후보 목록 저장), `scripts/eval_target_llm_rerank.py`(새로, 시험용)

## 요약
1. **규정 이름을 대충 쓴 요청**(「법인카드 지침」, 「운용지침」, 「보수복지규정」)을 비슷한 이름으로 알아듣는다. 짧고 거친 요청(D)의 규정 인식 18/30 → 28/30, 엉뚱한 규정 0건, 이름이 없는 질문 · 요청 108개에서 오작동 0건. 자연어 개정 전체(로컬 7B)에서 이름 때문에 실패하던 D 요청 6건이 살아났다
2. **화면 후보 3개 → 5개.** 어차피 사람이 고르므로 조 @5(79%)를 그대로 쓴다
3. **순서 매기기**: 리랭커 순위와 임베딩 순위를 같은 무게로 섞고, 요청이 말하지 않은 대상(해외 · 파견 · 공무직 · 임원 · 계약직) 전용 규정은 뒤로. 30B로 다시 매기기는 효과가 없어 버렸다

리포트 55와 합친 개정 위치 찾기(RAG 팀 독립 라벨, 질문 90개): **조 @1 41% → 57%, 조 @3 62% → 74%, 조 @5 71% → 79%, 규정 @1 58% → 77%.** 시작점 대비 짝지은 차이는 모두 유의하다(@1 +15.6%p [+5.6, +25.6], @3 +12.2 [+3.3, +21.1], @5 +7.8 [+1.1, +15.6]).

## 1. 규정 이름 인식
- 원인(리포트 51): D 말투 실패의 대부분이 모델 호출 전에 규정을 못 찾은 것. 이름이 띄어쓰기만 빼고 글자 그대로 있어야 했다
- 방법(`nl.similar_regulations`, `find_regulation`의 대체 경로): 요청에 「…규정/지침/규칙/정관/세칙/요령」이 있을 때만, 띄어쓰기 · 「·」 · 「/」 · 「및」 · 「(한국)벤처투자」 · 「에 관한」을 지우고 글자쌍 겹침(Dice)으로 점수. **1위 0.6 이상이고 2위와 0.1 이상 벌어지거나, 0.45 이상이고 0.2 이상 벌어질 때만** 고른다. 애매하면 고르지 않는다
- 결과(외부 모델이 쓴 요청 120건, 규정 지정 없는 A · D 60건): A 30/30 그대로, **D 18/30 → 28/30**, 다른 규정을 고른 경우 0. 남은 2건(「보안지침」, 「자금세탁방지 규정」)은 비슷한 규정이 여럿이라 고르지 않는 것이 맞다. 「보안지침」은 1위 후보가 틀린 규정(보안업무지침)이었다
- 오작동 확인: 규정 이름이 없는 직원 질문 100개 + 자작 요청 8개에서 비슷한 이름으로 고른 경우 0
- 화면(`/api/find`): 이름이 대충이어도 하나로 좁혀지면 그 조문을 바로 열고 「○○ 제n조(으)로 이해했습니다. 다른 규정이면 정확한 이름을 적어 주세요」를 띄운다. 애매한데 조 번호가 있으면 **이름이 비슷한 규정들의 그 조**를 후보로 보인다(「보안지침 제62조」 → 정보보안관리지침 제62조 하나. 보안업무지침에는 제62조가 없음). 조 번호를 버리고 일반 검색으로 가지 않는다
- 자연어 개정 전체(로컬 qwen2.5:7b, 같은 120건): 의도 일치 91 → 100. **이 중 규정 이름 수정으로 확실한 것은 D 6건**(X056 · X064 · X076 · X084 · X088 · X112). 나머지 증감(A +3, B +2, D 3건 하락)은 7B 출력의 흔들림이고, 떨어진 3건은 모두 개정 문장 형식 오류(이름과 무관). 이전 결과는 `out/nl_eval/qwen2.5_7b__nl_requests_ext_before56.json`에 보관

## 2. 순서 매기기
리포트 55 설정(Qwen3-4B 색인 + 800자)에서 후보 25개 안에 정답 조가 93%인데 상위 3개는 69%. 정답이 후보에 있는데 3위 밖인 22건을 읽으니 다수가 **적용 대상이 다른 전용 규정이 위로 온 경우**였다(「결혼 특별휴가」 → 해외 파견 지침 특별휴가 1위, 「주말 출근 대휴」 → 공무직 관리지침 1 · 2위). 나머지는 라벨이 애매한 경우(「법카 영수증 분실」 → 「분실시 처리」 조가 1위인데 정답 라벨은 대금 결제 조).

| 방법 (질문 90개) | 조 @1 | 조 @3 | 조 @5 | 시간 |
|---|---|---|---|---|
| 리랭커만 (55) | 38 | 62 | 69 | - |
| 30B가 상위 10개를 다시 매김 | 41 | 62 | 69 | +3.1초 |
| 적용 대상 규칙 | 41 | 63 | 69 | 0 |
| 순위 섞기 (같은 무게 RRF) | 44 | 66 | 69 | 0 |
| **섞기 + 대상 규칙 (채택)** | **51** | **67** | **71** | 0 |

- 30B 재정렬: @3 좋아짐 7 · 나빠짐 7. 쓰지 않는다
- 대상 규칙: 나빠진 질문 0
- 섞기 무게는 데이터에 맞춰 고르지 않았다(같은 무게 w = 1). w를 0.25 ~ 2.0으로 바꿔 본 값은 모두 비슷했다(@3 64 ~ 67)
- 「확실함」 판단은 섞은 뒤 1위의 점수가 아니라 상위 3개 중 최고 리랭커 점수로. 확실함 19건 중 조 @3 17건(89%). 이전(21건 중 20건)보다 조금 낮다

## 주요 결정
| 결정 | 이유 | 대안 |
|---|---|---|
| 비슷한 이름은 하나로 좁혀질 때만 자동 선택 | 잘못 고르면 그 뒤가 다 틀린다. 애매하면 묻는 쪽이 안전 | 항상 1위 선택 (「보안지침」에서 틀림) |
| 30B 재정렬을 버림 | 효과 0, 질문당 3초 | 상위 16 · 25로 늘려 보기 (천장 제한이 아니라 순서 판단이 안 됨) |
| 순위 섞기 무게 고정(1.0) | 질문 90개에 맞춘 값은 과적합 위험 | 가장 좋던 1.5 |
| 대상 규칙은 규정 이름 낱말로 | 단순하고 설명 가능. 대상 낱말 목록은 `target.AUDIENCE` | 질문자 정보(직군)로 거르기 (화면에 로그인 정보가 생기면) |
