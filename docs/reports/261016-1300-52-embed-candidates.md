# 261016-1300 임베딩 후보 예비 측정: bge-m3 대 Qwen3-Embedding (0.6B, 4B)

- 관련: [40 임베딩 기준선](261014-1700-40-embed-stage0.md), [51 평가 확대](261016-0100-51-independent-eval.md), `scripts/exp_embed_candidates.py`
- 목적: 4명이 나눠 돌릴 본 실험(임베딩 2 × 리랭커 2 × LLM 2) 전에, 어떤 임베딩을 도전 후보로 둘지 **우리 평가셋으로** 정한다 (문헌에는 한국어 직접 비교가 없었음).

## 조건 (고정)
- 후보 단계만(LLM 없음): 가빈의 벡터 + BM25 하이브리드(RRF 0.7:0.3, k=60), 후보 N개 = 청크 N개. 바꿔 쓴 검색어는 **저장된 캐시(luna가 쓴 것)** 로 고정.
- 문서 입력은 현행 v0(본문_검색). 질문만 모델별 방식: Qwen3-Embedding은 모델 카드 방식의 질문 지시문을 붙임(영어 지시문 1종, 지시문 민감도는 미측정).
- 평가셋: 개발용 `answer_eval_100_tiered.jsonl` (질문 99, **필수 근거 125곳**), 시험용 `answer_eval_holdout.jsonl` (질문 79, 근거 110곳, 필수/보조 구분 없음 → 전체 근거).
- 기준선 검증: bge-m3 하이브리드 @30 필수 **0.904**(전체 0.856)로 가빈 보고(0.905 / 0.858)와 일치.
- Qwen3-Embedding은 8GB GPU 제약 때문에 Ollama 양자화본(0.6B fp16, **4B q8_0**)을 썼다. 4B fp16(약 8GB)은 GPU에 안 맞고, CPU로는 수 시간 이상이라 불가.

## 결과: 후보 N개 안 근거 재현율 (조·별표 단위)
| 평가셋 | 방식 | @N | bge-m3 | Qwen3-0.6B | **Qwen3-4B (q8)** |
|---|---|---|---|---|---|
| 개발용(필수 125) | 하이브리드 | 10 | 0.712 | 0.768 | **0.816** |
| | | 30 | 0.904 | 0.864 | **0.960** |
| | | 50 | 0.920 | 0.920 | 0.976 |
| | 벡터 단독 | 30 | 0.824 | 0.800 | **0.936** |
| 시험용(근거 110) | 하이브리드 | 10 | 0.818 | 0.782 | **0.864** |
| | | 30 | **0.964** | 0.909 | 0.945 |
| | | 50 | 0.973 | 0.936 | 0.973 |
| | 벡터 단독 | 30 | 0.918 | 0.855 | **0.945** |

개발용 수치는 실행 출력에서 옮겼다(결과 파일이 시험용 실행에 덮어써짐. 스크립트는 평가셋별 저장으로 고침). 두 세트 합산(근거 235곳):
| 지표 | bge-m3 | Qwen3-4B (q8) | 차이 |
|---|---|---|---|
| 하이브리드 @10 | 179/235 = 76.2% [70, 81] | 197/235 = 83.8% [79, 88] | **+7.7%p** |
| 하이브리드 @30 | 219/235 = 93.2% [89, 96] | 224/235 = 95.3% [92, 97] | +2.1%p (구간이 겹침) |
| 벡터 단독 @30 | 204/235 = 86.8% [82, 91] | 221/235 = 94.0% [90, 96] | **+7.2%p** |
- 합산은 출력의 비율에서 복원한 개수라 반올림 오차가 있다.
- 기준 대비 필수 근거 @30 얻음/잃음: 개발용 4B 8/1, 0.6B 3/8. 시험용 4B 1/3, 0.6B 1/7.

## 해석
1. **0.6B는 후보에서 제외.** 두 세트 모두 기준선과 같거나 낮고(시험용 @30 0.909 대 0.964), 잃는 근거가 더 많다.
2. **4B는 순위 앞쪽(@10)과 벡터 단독에서 일관되게 앞선다.** 개발용·시험용 모두 @10이 높고(+10.4, +4.6%p) 벡터 단독 @30도 높다. 하이브리드 @30은 개발용에서 크게 앞서지만(+5.6%p) 시험용에서는 사실상 같다(-1.8%p, 기준선이 0.964로 천장에 가까움). 합산하면 @30 차이는 작고 구간이 겹친다.
3. **효과의 의미**: BM25와 합친 뒤 후보 30개를 넉넉히 잡는 현재 설정에서는 이득이 작지만, **후보 풀을 줄이거나(@10) 벡터 단독 구간이 중요할 때** 이득이 크다. 가빈 쪽에서 「풀이 너무 넓다」는 문제가 나왔으므로 4B는 풀을 줄여도 재현율을 유지할 수 있다는 점이 핵심 가치일 수 있다 (미검증: 후보를 줄인 실험을 하지 않았음).
4. 이 수치는 **luna가 쓴 바꿔 쓰기 캐시** 기준이다. 로컬 모델이 바꿔 쓰면 달라질 수 있다 (본 실험 A2에서 확인).

## 한계
- 후보 단계(LLM 전) 지표다. 최종 근거·정답률은 리랭커·선택·답변을 거쳐 봐야 한다.
- 질문 지시문 문구 1종만 썼다. 4B는 8비트 양자화본이라 원본(fp16)과 다를 수 있다.
- 합산해도 근거 235곳이라 구간이 넓다. 하이브리드 @30의 +2.1%p는 유의하지 않다.
- 운영 환경(NPU 등)에서 이 모델을 돌릴 수 있는지는 별개다.
- 에이전트에 채택하면 색인 재생성, 의미 이웃표 재계산, 임계값(0.78·0.82·간격) 재조정이 필요하다 → 효과가 확실할 때만.

## 정정
- 앞선 대화에서 「4B 임베딩을 CPU로 수십 분」이라 했으나 틀렸다. 청크 4,595개(약 90만 토큰)를 4B로 임베딩하면 CPU로는 수 시간 이상이다. GPU(양자화)에서는 약 4분이었다.
