- 입력: 로컬 다운로드 폴더의 `questions.md`(= `codex/four-domain-ontology-eval-20261106`의 `eval/four_domain/questions.md`와 동일) + 같은 브랜치의 `gold.jsonl`. 외부에서 만든 평가셋이라 우리 AI 라벨과 독립이다(정답은 그쪽의 AI 초안, 사람 검수 전).
- 도구: `scripts/four_domain_parse.py`(문항 파싱), `scripts/eval_four_domain.py`(1단계). 코드 변경: `change_query.py`(서식 · 별표 개정문), `impact_view.py`. 커밋하지 않았다.
- 문항: 인사 · 보수 · 휴가 · 휴직 4개 도메인 20개 관계를 상태와 조합으로 바꾼 120문항(새 문제 40 · 정상 변경 40 · 기존 문제 해소 40). 정답 문제는 값 불일치 57건과 깨진 인용 52건씩, 새 문제 109 + 해소 109.

## 1단계가 재는 것

각 개정 항목(616건: 값 바꾸기 536, 이동 80)을 개정문으로 만들어 우리 후보 수집(RAG + 그래프, 기본 화면)에 넣고, **정답 문제의 짝**(한쪽이 개정된 조이면 다른 쪽)이 후보에 오르는지 본다. 새 문제 · 해소 판정은 아직 하지 않는다. 한석희의 점수(RAG 83/120, 도메인 그래프 + RAG 93/120)는 Luna가 판정까지 하는 점수라 이 숫자와 비교할 수 없다.

## 찾은 구멍과 수정

- **우리 변경 분석이 서식 · 별표를 고치는 개정문을 해석하지 못했다**(「별지 제1호 서식 중 "매월 25일"을 …」). 616건 중 96건이 분석 실패였고, 개정된 쪽이 서식인 정답 24쌍은 0%였다. 실제 개정에도 서식 문구 수정이 있으므로 기능 구멍이다.
- 수정: 서식 · 별표를 임시 조로 감싸 같은 분석을 탄다(`change_query._appendix_pseudo`), `impact_view.run`이 조 단위 적용기 실패 시 서식 본문을 대상 본문으로 쓴다. 단위 테스트 2개 추가(전체 457개 통과).
- 효과: 분석 실패 96 → 12건(남은 12건은 「별표1를 별표9로 이동」), 짝 포착 84% → 87%, 개정된 쪽이 서식인 쌍 0% → 29%.
- **기존 평가는 변하지 않았다**: 전체 155문항의 후보가 한 문항도 달라지지 않았고 정답 포착 365/395 그대로.

## 남은 놓침 (28쌍)

- 개정된 쪽이 서식인 17쌍: 값(예: 「출근시 15일」)이 다른 조(복무규정 제21조 「15일의 유급휴가」)와 같은 사항인데, 서식 본문이 길어 질의가 값 주변을 담지 못한다. 서식은 의미 검색 색인에도 없다.
- 짝이 서식인 6쌍: 서식은 임베딩하지 않아 인용 · 제목 연결 없이는 후보가 되지 못한다.
- 별표 이동 3쌍(분석 실패), 조 ↔ 조 5쌍(모두 「해소 · 깨진 인용」, 이동 전 번호를 가리키던 인용).

## 한계
