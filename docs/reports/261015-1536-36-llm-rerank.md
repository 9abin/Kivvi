## 요약
교차 인코더(bge-reranker-v2-m3) 리랭크 뒤에 상위 15개를 LLM(gpt-4o-mini)이 문서별로 독립 채점(0~10)해 다시 정렬하는 2단계를 붙였다(`LLM_RERANK=1`, 기본 끔). 93문항 `rank_trace`로 끔/켬을 재 보니 §측정과 같다.

## 주요 결정
| 결정 | 이유 | 대안 |
|---|---|---|
| pointwise(문서마다 독립 호출, 0~10 정수), 병렬 | 호출 하나가 실패해도 그 문서만 폴백하면 되고, 캐시를 (모델, 질문, chunk_id)로 둘 수 있다. 15개를 스레드 풀로 동시에 보내 지연은 호출 1회분 | listwise(상위 15개를 한 번에 주고 순서를 받기): 호출 1회로 싸지만 파싱 실패 시 전부 폴백이고 캐시가 안 됨 |
| 채점 기준 3단(직접 규정 8~10 / 간접 3~7 / 무관 0~2) | 교차 인코더가 "주제는 같은데 요건이 다른 조"를 위로 올리는 경우를 가르는 것이 목적이라 "질문의 핵심 요건을 직접 규정하는가"를 축으로 둔다 | 예/아니오 이진 — 동점이 많아 교차 인코더 순서가 그대로 남는다 |
| 동점은 교차 인코더 순서, 실패 문서는 교차 인코더 자리 유지, 상위 15개 밖은 그대로 뒤에 | 2단계는 1단계를 "고치는" 역할이지 대체가 아니다. 모두 실패하면 결과가 1단계와 같다 | 실패 문서를 맨 뒤로 — 일시 장애 때 정답을 떨어뜨린다 |
| 입력은 `Searcher.rerank_text` 그대로 (머리말 `[문서명 장 조항]` 포함) | 교차 인코더와 같은 글자를 보게 해서 차이가 모델 판단에서만 나게 한다 | 조 전체·형제 항 포함 — 토큰이 늘고 비교가 섞인다 |
| 모델 기본 gpt-4o-mini | 문항당 15회 호출이라 빠르고 싼 모델. 누락 검사(`GAP_CHECK_MODEL`)와 같은 선택 | 답변 모델(gpt-5.6-luna) — 환경 변수 `LLM_RERANK_MODEL`로 바꿔 비교할 수 있다 |
| 캐시 `eval/runs/llm_rerank_cache.json` | 평가를 다시 돌릴 때 93×15 호출을 아낀다. 실패(None)는 캐시하지 않는다 | 캐시 없음 |

## 변경 사항
- `config.py`: `LLM_RERANK`(기본 끔), `LLM_RERANK_TOP`(15), `LLM_RERANK_MODEL`(gpt-4o-mini), `LLM_RERANK_CACHE`.
- `src/search/llm_rerank.py`: `LLMReranker.rerank(question, cands, text_of)` — 상위 top개를 `score()`로 병렬 채점(캐시 먼저), `reorder()`로 정렬. 각 후보에 `llm_rerank`(0~10 또는 None). `parse_score()`는 응답의 첫 정수(0~10)만 받는다.
- `src/search/search.py`: `Searcher.__init__`이 `LLM_RERANK`일 때 `self.llm_reranker`를 만들고, `search()`가 교차 인코더 리랭크 직후(용어집 제외·조 합치기 전) 호출한다. 결과 항목에 `llm_rerank` 필드 추가(끔이면 None). `last_reranked`(누락 검사가 6위 이하를 되짚는 목록)도 LLM 순서를 따른다.
- `src/eval/rank_trace.py`: `--llm-rerank`(`--llm-model`, `--llm-top`)로 "리랭크"(교차 인코더)와 "LLM리랭크" 순위를 같은 행에 기록, `--summarize <json>`으로 저장된 결과에서 검색_설계.md 5절 표(R@5/R@7/R@10/전부 찾은 문항/6위 이하/창 밖)를 다시 계산. 기존 `rank_trace_merge_off.json`으로 표의 숫자가 그대로 재현됨을 확인했다.
- 테스트 9개 추가(`tests/test_llm_rerank.py`: 점수 해석, 동점·실패·상위 밖 처리, 캐시).

- 창 밖(12·8)과 R@10은 바뀌지 않는다. 2단계는 창 안 순서만 고치므로 창 밖 묶음은 후보 단계(벡터·BM25·바꿔쓰기)의 일이다.
