## 2. 온톨로지 보강

### 2-1. 상하위 정의
- `Unit`(추상 클래스) ⊃ `Article` · `Supplement` · `Annex` · `Form`. `ONTOLOGY["superclasses"]`, `abstract_classes`.
- 규정 위계 `법령 > 정관 > 규정 > 지침`(내규관리규정 제2 · 7조)을 `regulation_hierarchy`로 정의하고, `Regulation.tier` 속성이 이를 가진다(이미 있던 속성을 정의에 올림).
- 테스트: 상위 클래스가 클래스에 있고, 모든 관계 끝점이 정의된 클래스 안에 있음.

### 2-2. 약칭(동의어) 사전 — `kg_onto.extract_aliases`
- 「A(이하 "B"라 한다)」에서 앞말 A가 알려진 개체(법령 · 규정 · 위원회 · 용어)일 때만 B를 약칭으로 둔다. 후보 155건 중 34개가 남았다.
- 거른 것: A가 개체가 아닌 경우(「회사」 45건), B가 A를 품은 경우(「수수 금지 금품등」), 용어와 겹치지 않는 변형(「행동강령책임관」).
- **검색에 쓰는 것은 8개**(법령 약칭 6: 민원처리법 · 금융실명법 · 공공기록물법 · 특정금융정보법 · 범죄수익은닉규제법 · 테러자금금지법, 위원회 약칭 2). 나머지 26개는 「법」 「규정」 「위원회」처럼 이름의 일부이거나 상대 지칭이라 문서 안 해석에만 쓴다(`generic`).
- 수집 경로 `ALIAS`(참고 단계): 바뀐 · 지운 말이 개체 이름이나 약칭이면 같은 개체의 다른 표기를 쓰는 조를 낸다.
- 일반 동의어 사전은 만들지 않았다. 전문가 없이는 근거를 댈 수 없기 때문이다.

### 2-3. 법령 이름 정규화와 법령 조 노드
- 법령 이름: 띄어쓰기만 다른 이름을 한 노드로 합치고 법률 DB(284건) 제목을 대표 이름으로 쓴다. 「법」 「시행규칙」처럼 어느 법인지 모르는 이름은 노드로 만들지 않는다.
- `LawArticle` 노드 128개, `CITES_LAW_ART` 177건: 본문의 「법령」 제N조, 약칭 제N조, 그 규정이 「법」으로 정의한 법의 제N조, 「같은 법 · 영」 제N조(바로 앞 법령 또는 규정이 정의한 법의 시행령)를 푼다. 조 제목은 법률 DB에서 가져온다(113개 중 109개).
- 조 단위 인용은 법령 단위 인용(`CITES_LAW`)도 된다(123 → 255).
- 법령 개정(`analyze_law`): 개정문이 말한 제N조의 법령 조 노드가 있으면 시작점에 더한다. `CITES_LAW_ART` 경로는 확정급이다(번호로 직접 인용한 것과 같은 근거).
- 구현 중 찾은 버그: 상대 지칭(「법 제N조」)에서 정규식 그룹 번호를 잘못 읽어 조 번호가 `제법조의14`로 나왔다. 표본을 읽어 찾았고 고쳤다.

## 5. 팀의 휴직 온톨로지 DB와 우리 키워드 층 비교 (`scripts/exp_leave_db.py`)

대상: 한석희 브랜치의 `hyujik-user-original.db`(사용자가 만든 원본, 개념 6 · 연결 151)와 `domain_ontology.reviewed.db`(Luna 재검토로 4개 도메인 개념 44 · 연결 1,997, 그중 1,846개는 사람 검수 전). 외부 파일이라 읽기 전용으로만 열었다. 후보 수집 코드는 건드리지 않고 주제 층 인터페이스(`expand`)를 맞춘 실험용 어댑터(`DbLayer`)로 꽂았다.

**구조 차이**

| | 우리 키워드 층 (`topic_layer.py`) | 팀 휴직 DB |
|---|---|---|
| 개념 | 휴직 종류 6(공통 포함), 낱말 사전으로 자동 배정 | 휴직 ⊃ {명령 · 인병 · 청원 · 육아 · 가족돌봄}, 사람이 정한 위계(BROADER) |
| 속성 | 낱말 사전 7종(기간 · 분할 · 보수 …) | 개념마다 속성 정의와 값(38개, 예: 육아휴직 분할 = 최대 2회, 총 3회) |
| 연결 | 항 단위 (종류, 속성) 배정 | 항목 → 개념 연결 151개(정의 · 근거 · 언급)와 연결이 뒷받침하는 속성, 상위항 38개, 대표 근거 7개 |
| 근거 · 이력 | 없음 | 인용문, 사람의 수정 이력 46건 |
| 단위 | 조 · 별표 · 서식 | 조의 항 · 호 · 목 (별표 · 서식 없음) |

**커버리지**: 우리 층 배정 32개 조 대 DB 49개 조, 교집합 29. DB만 있는 20개 조는 거의 「휴직」이 한 번만 나오는 조(성과급, 교육훈련, 복지포인트, 도서 반납 등)이고 우리 층의 「두 번 이상」 조건이 뺀 것이다. 우리만 있는 3개는 별표. 개념 대응은 맞는다(명령휴직 = 우리의 직권휴직, 인병 = 질병).

**후보 비교** (휴직 시험 28문항, 정답 21건 / 보수 시험 8문항, 정답 11건. 정답은 AI 라벨)

| 휴직 (RAG 없이, 층 자체의 정보량) | 전체 후보 안 정답 | 층이 더한 정답 | 층이 더한 후보 |
|---|---|---|---|
| 층 끔 (그래프 · 문구만) | 13/21 | | |
| 우리 키워드 층 | 16 | +3 | 56 |
| DB 원본 (같은 개념 · 같은 속성) | 14 | +1 | 9 |
| DB 원본 + 개념 위계 | 15 | +2 | 26 |
| 우리 + DB 원본(위계) | 18 | **+5** | 82 |

- 두 층이 찾는 정답이 다르다. 우리 층은 별표(L25)와 L11의 두 조를, DB는 우리가 놓친 L24(임직원교육훈련지침 제9조, 「휴직」 한 번 언급)와 L08(위계 경유)을 찾는다.
- 더한 후보당 정답: 우리 3/56, DB 1/9(위계 쓰면 2/26), 합치면 5/82. 사람이 만든 DB는 연결이 적은 대신 정확하다.
- **RAG가 있으면 어느 층도 정답을 더하지 못한다**(층을 꺼도 20/21 포착). 이전 결과(리포트 81)와 같다.
- **AI가 확장한 검토본은 정밀도가 낮다.** 휴직 항목에서 검토본으로 같은 질의를 하면 +1에 후보 201개(원본은 +1에 9개). 보수 항목은 우리 층 +3(후보 48개), 검토본 +2(후보 100개). 사람 검수 전 연결 1,846개는 후보를 늘리는 쪽이다.

**읽는 법과 한계**
- 정답 21건 중 층이 더한 것은 1~5건이다. 우열을 말할 표본이 아니라 서로 다른 정답을 찾는다는 방향만 본다.
- 시험 항목을 우리 층을 쓰던 중에 만들었고, 정답 라벨의 후보 풀에 우리 층 후보가 들어 있다. 풀 밖의 DB 후보는 정답 여부를 몰라 정답으로 세지 않았다(휴직 검토본 비교에서 풀 밖 후보 175개). 그래서 DB에 불리하다.
- DB는 별표 · 서식을 갖지 않는다.

**판단**
- DB의 가치는 이 후보 수집보다 **속성 정의와 값, 근거 인용, 수정 이력**에 있다. 불일치 검토(`v_candidates` 뒤 값 비교)와 근거 카드에 쓰기 좋은 형태다.
- 후보 수집에는 **사람이 만든 원본 연결을 우리 키워드 층과 합치는 쪽**이 근거가 있다(합치면 +5). AI 확장분은 사람 검수 전이라 쓰지 않는다.

### 5-1. 연결 표로 가져오기 (구현)

- `scripts/extract_hyujik_links.py`: 외부 DB(읽기 전용)에서 **연결 표만** `out/hyujik_links.jsonl`(git 제외)로 뽑는다. 조 id · 개념 · 관계 · 속성 · 결정자와 개념 위계, 원본 DB의 sha256뿐이고 규정 원문 · 속성 설명 · 메모는 싣지 않는다. 연결 151행, 조 49개. 항목 id 151개가 우리 파싱 항목에 전부 대응된다.
- `src/regcheck/linked_layer.py`(`LinkLayer`): 주제 층과 같은 인터페이스(`expand`)라 `collect(leave=...)`에 넣을 수 있다. 기본값은 꺼짐이며 기존 경로는 바꾸지 않았다. 옵션: `hierarchy`(개념 위계), `trusted_only`(사람 확정 연결만), `same_concept_any_attr`. 단위 테스트 6개.
- 연결의 결정자는 **사용자 16 · 자동·확정 16 · 초안 119**다. 사람이 확정한 것은 32개이고 나머지는 초안 표시다(DB 버전 표기는 「검토 확정」).
- 어댑터가 DB 직접 읽기와 같은 결과를 재현한다(휴직, RAG 없이: DB +1/9, 위계 +2/26, 우리 + DB(위계) +5/82). 결정자 필터를 더한 결과:

| 휴직, RAG 없이 | 층이 더한 정답 | 층이 더한 후보 |
|---|---|---|
| DB 확정 연결만 + 위계 | +1 | 3 |
| DB 전체 + 위계 | +2 | 26 |
| 우리 + DB 확정만 | +4 | 59 |
| 우리 + DB 전체(위계) | +5 | 82 |

초안 연결 119개가 정답 1건을 더 보태고 후보도 늘리지만 잡음이라 할 정도는 아니었다. 정밀도가 떨어진 쪽은 **AI가 확장한 검토본**이다(§5).

- 아직 하지 않은 것: DB 작성자와의 사용 합의, 연결 표의 저장소 반영(`out/`에만 있음), 기본 층 목록에 넣는 일, 새 봉인 휴직 문항으로 확인. 코드는 커밋하지 않았다.
