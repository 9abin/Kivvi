# 261102-1600 2차 봉인 평가 계획

- 관련: [74 전체 구조](261102-1530-74-impact-pipeline-overview.md), [68 평가셋 설계](261030-1800-68-impact-evalset-design.md), [69 라벨 키트](261030-1830-69-impact-label-kit.md)
- 이유: 1차 봉인은 2026-11-02에 이미 열렸고, 그 뒤 규칙(전이 규칙, 단계 경계)과 프롬프트를 개발 분할에서 바꿨다. 효과를 말하려면 **한 번도 보지 않은 새 문항**이 필요하다.

## 구성

- 새 가상 개정 12건(I25~I36): 값 변경 2, 삭제 2, 번호 이동 2, 정의 변경 2, 위임·법령 변경 2(법령 개정 1 포함), 표현 수정 1, 고립 수정 1. 1차에서 쓴 규정은 제외.
- 키트: `eval/impact_label_kit_r2/` (규정 원문 90건 + 지시서 + 검사기). 1차 산출물은 넣지 않았다. **저장소에 올리지 않는다**(규정 원문 포함).
- 라벨러: 1차와 같은 방식의 독립 세션 A(개정 작성), B1 · B2(영향 라벨), C(불일치 결정). 서로의 산출물을 읽지 않는다.

## 동결 (라벨 작성 전)

- 코드 · 프롬프트 · 그래프 해시를 `out/freeze/freeze_r2_20261102.json`에 기록했다. 프롬프트 P3, 모델 `gpt-5.6-luna`.
- 이 시점 이후 점수를 보고 코드 · 규칙 · 프롬프트를 고치지 않는다. 고치면 새 문항이 아니게 된다.
- 작성 지시를 만든 쪽(이 문서의 작성자)은 개정문과 라벨을 미리 보지 않는다.

## 순서

1. 세션 A: `지시서.md`의 「역할 A」 → `산출/changes.jsonl`, 검사 `python validate.py changes 산출/changes.jsonl`
2. 세션 B1, B2(서로 독립): 「역할 B」 → `산출/labels_B1.jsonl`, `labels_B2.jsonl`
3. 세션 C: 「역할 C」 → `산출/labels_final.jsonl`
4. 라벨이 끝난 뒤 한 번만 실행: 후보 수집(RAG만 / 그래프만 / 합침) + LLM 판단 표시(P3). 비교는 문항 단위 bootstrap, 후보 상한 10 · 20.
5. 사람 확인(불일치 · 무영향 문항 위주). 결과는 확인 전 초안이라는 표시와 함께 보고한다.

## 세션에 붙여 넣을 말

각 세션을 `eval/impact_label_kit_r2/` 폴더에서 연다.

- A: 「지시서.md를 읽고 역할 A를 수행해.」
- B1 / B2: 「지시서.md를 읽고 역할 B1(또는 B2)를 수행해. 다른 라벨러의 산출물은 읽지 마.」
- C: 「지시서.md를 읽고 역할 C를 수행해.」

## 한계

- 라벨은 AI 초안이다. 영향 범위의 정의는 현업 판단 사항이라 이 평가에서 결론을 내지 않는다.
- 문항 12개는 적어서 구간이 넓다. 경로별 정밀도 · 확정급 정밀도 90%가 유지되는지를 주로 본다.
