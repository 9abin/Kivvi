# 97. 판단 모델 입력 자르기 수정 (채택) · luna 프롬프트 원칙 (버림)

작성 261112. 관련: [리포트 95](261112-1800-95-decide-threshold.md), [리포트 96](261112-2000-96-codex-cross-review.md). 규칙(경로 · 문턱) 추가 없이 프롬프트 · 입력만 손보는 범위로 했다. 둘 다 시험 실패를 본 뒤 나온 것이라 시험 숫자는 **후속 개발 결과**다(처음 고정 실행 0.860과 구분).

## B. 판단 모델 입력 자르기 (채택)
- 원인: `decide_state`가 확인 대상 조문을 앞 700자로 잘랐다. 시험 T073(직무전결규정 별표 5,369자)은 근거 「라. 직원의 신원보증보험 가입」이 1,792자 위치라 모델이 못 봤다(`lv` 0.07).
- 고침: `final_view.cand_window` — 700자를 넘으면 바뀌는 말(`evidence.change_keys`: 고쳐지는 조 제목 · 바뀌기 전 말 · 지워진 말 · 용어 · 다른 규정이면 규정 이름, 앞쪽 우선)이 처음 나오는 곳 주변을 보이고 조 머리 60자를 남긴다. 말이 없으면 그대로. 파이프라인(`run_pipeline`) · 평가(`run_eval.py pairs`) 모두 쓴다.
- 입력이 바뀐 쌍: 개발 73 · 시험 92(700자 초과 + 바뀌는 말이 뒤쪽). 그 쌍만 다시 채점해 `out/relabel_v2/decide_scores.json`에 합쳤다(이전 점수는 `decide_scores_700.json`).

| | 개발 이전 → 후 | 시험 이전 → 후 |
|---|---|---|
| 전체 재현율 | 0.934 → 0.934 | 0.860 → **0.880** |
| Recall@10 | 0.901 → 0.901 | 0.840 → 0.860 |
| 문항당 | 5.27 → 5.27 | 5.38 → 5.42 |
| 0.7 기준 새로 통과 / 탈락 | 3 / 2 | 8 / 4 |

- 개발 이득 없음(이 문제에 걸린 개발 정답 없음), 손해도 없음. 시험은 T073 하나(0.07 → 1.65).
- 다른 세션 제안(개정 낱말 겹침을 문서 빈도 역수로 가중한 600자 구간 + 앞 80자)도 같은 결과였다. 바뀌는 말을 명시적으로 쓰는 이 방식이 원문 인용(`evidence`)과 같은 기준이라 이쪽을 남긴다.

## D. luna 프롬프트 원칙 (버림)
넣은 것: 「후보 원문과 개정에서 인용 · 정의 · 조건 · 직무의 구체적 연결을 글자로 짚어 설명할 수 있으면 고른다. 주제나 업무 분야만 비슷하면 고르지 않는다」 + 「개정이 인용하는 조 · 장 · 절 · 서식 번호를 바꾸면 새로 가리키게 되는 대상도 확인할 조(A)」. 개발 100, 원래 · 새 프롬프트를 후보 순서 seed 0 · 1로 두 번씩.

| | 전체 재현율 seed 0 / 1 | Recall@10 seed 0 / 1 | 문항당 |
|---|---|---|---|
| 원래 | 0.945 / 0.967 | 0.912 / 0.934 | 5.48 / 5.41 |
| 새 원칙 | 0.912 / 0.945 | 0.879 / 0.912 | 5.33 / 5.36 |

- 두 seed 평균 차이 −0.027 [−0.061, 0.000]. 「주제만 비슷하면 고르지 않는다」가 luna를 엄격하게 만들어 정답도 빠졌다. 인용 번호 원칙은 개발 사례가 B021 하나(원래도 찾음)라 효과를 볼 수 없었다.
- luna 흔들림: 같은 원래 프롬프트도 seed만 바꾸면 정답 2개가 오간다(0.945 / 0.967).

## 놓친 정답을 열어 본 결과
- luna가 안 고른 개발 4개(B027 · B060 · B073 · B100)와 시험 T098은 모두 luna 입력에 있었고 근거가 900자 안이었다. 다시 돌리면 B027 5/5 · B060 2/5 · B073 3/5 · B100 1/5로 골라 흔들림이 크다. 또 프롬프트 관계 정의(A 인용 · C 전제)가 「후보가 바뀌는 것을 인용 · 사용」 한 방향뿐이라 반대 방향(후보가 그 대상을 정의 · 두는 조, 개정 조가 새로 가리키게 되는 조)이 정의에 없다. T098 라벨은 「개정된 인용이 맞는지」를 묻는 오류 발견에 가깝다.
- 판단 모델이 거른 시험 2개: T030 제24조(`lv` 0.56)는 같은 인용 「제36조(개인정보의 파기)」를 가진 제13조 · 제35조(주제가 파기, 1.59 · 1.86)와 달리 주제가 보조기억매체라 낮았다 — 인용보다 주제 유사성에 끌림. 시스템이 이 개정을 「값 변경」으로 분류해 질문도 「바뀌는 값」을 물었고, 라벨도 약하다(제36조는 이동하지 않음). T076은 수정 종류별 질문 `p` 0.92인데 거르기에 쓰는 일반 수준 질문 `lv` 0.46.

- luna 관계 정의에 반대 방향 보충(엄격 원칙 없이), 반복 실행으로 비교.

## 판단 모델 수준 질문 단계 설명 보강 (채택, 261112)
- 바꾼 것: `final_view.LEVELS` 네 단계에 기준을 적었다(질문 문구는 그대로). 0 「개정과 이어지는 말이나 내용이 없다」, 1 「업무 분야나 주제만 비슷하고 바뀌는 조 · 말 · 사항을 인용 · 사용 · 따로 정하지 않는다」, 2 「같은 사항을 따로 정하거나 바뀌는 절차 · 직무 · 서식 · 용어를 전제로 쓴다」, 3 「바뀌는 조 · 장 · 서식을 번호나 제목으로 인용하거나 바뀌는 말을 그대로 쓴다」.
- 개발(규칙 후보 794쌍, 같은 입력에서 원래 · 새 설명 모두 재채점): AUC 0.874 → 0.895, 차이 +0.020 [+0.002, +0.041]. 0.7 기준 재현율 그대로(0.934), 문항당 5.20 → 5.34. 같은 비율로 남기면(문턱 0.74) Recall@10 0.901 → 0.912, 문항당 5.16. 가장 낮던 정답(정의 변경 USES_TERM, 0.08~0.13)이 0.44~0.64로 올랐다(아직 0.7 아래라 예외는 유지).
- 시험(1회, 후속 개발): AUC 0.917 → 0.910(오르지 않음). 전체 재현율 0.880 → 0.900(T076 0.46 → 0.86), Recall@10 0.860 그대로, 문항당 5.42 → 5.94. 노렸던 치우침(T030 제24조, 같은 인용인데 주제가 달라 낮음)은 0.56 → 0.54로 해결되지 않았다.
- 문턱은 0.7 그대로 둔다(0.74는 개발에서 목록 크기를 유지하는 값, 결정 보류).
- 판단 모델 점수: 규칙 후보 쌍(개발 794 · 시험 806)을 새 설명으로 다시 채점해 `out/relabel_v2/decide_scores.json`에 합쳤다(이전은 `decide_scores_lv_orig.json`).
