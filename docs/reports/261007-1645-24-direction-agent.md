## 요약
중심을 "오류를 알려 주는 점검기"에서 **"개정 요청 하나로 연쇄 수정까지 담은 개정 패키지를 만들어 오는 에이전트"**로 옮긴다. 기준선 점검은 설치 때 한 번 쓰는 기능으로 내린다.
주 사용자는 내규담당부서·준법감시인(내규관리규정 제20~21조 조정, 연 49건). 차별점은 내규 간 연쇄 영향 + 규칙 기반 검증 + 개정 이력.

## 주요 결정
| 결정 | 이유 | 대안 |
|---|---|---|
| 에이전트 = 개정 패키지 생성 (알림 아님) | 월 4건 안팎 쓰는 도구는 "알려 주기"보다 "만들어 오기"여야 쓸 이유가 생김. 찾는 일 → 고르는 일 | 점검 결과 목록만 (아쉬움, 사용자 의견) |
| 주 사용자 내규담당부서·준법감시인 | 제21조가 모든 제·개정에 저촉·중복 조정을 의무화. 일반 직원은 챗봇 영역 | 전 직원 |
| LLM은 문안만, 적용·점검·검증은 규칙 | 로컬 LLM 품질 불확실(3B 부족, 9B 필터링 효과 없음). 생성형 개정 적용 연구 성공률 63%. 규칙 검증이면 LLM이 틀려도 걸러짐 | LLM 에이전트가 판단까지 |
| 대비표·검색은 기본 기능으로만 | 이미 있는 기능(alio-mcp, 나라이넷, 법령안편집기) | 대비표를 중심으로 발표 |
| 기준선 점검은 설치 때 한 번 | 한 번 정비하면 끝나는 가치. 발표의 근거(문제 증명)로 씀 | 기준선 중심 |
| 시연 = 과거 재현 + 직제 개편 | 이 회사에서 실제 일어난 일(2025.3 급여규정, 2026.8.28 15개 동시 개정) | 가상 시나리오 |
