# N 평가셋 채점 규칙 v5.1 (고정)

적용 gold: n_gold_80_v5_1.jsonl. 이 규칙과 gold를 함께 해시로 고정한 뒤 답변을 연다. 답변을 본 뒤 기준을 바꾸면 해당 문항은 개발용으로 표시한다.

## 1. 채점 대상과 단위

- 채점 대상은 사용자에게 표시된 `answer`다. 보류 전 원답(`withheld`)은 채점하지 않고 생성오답률·차단성과·오탐 분석용으로만 별도 집계한다.
- 채점 단위는 문항별 `필수_하위질문`이다. `핵심` 배열 원소 수는 채점 단위가 아니다(원소 하나에 여러 하위질문이 있을 수 있다).
- 각 하위질문은 충족 / 부분 / 미응답 / 오류로 판정한다. 의미 동치를 인정하며 문장 순서, 같은 용어, 숫자의 불필요한 반복을 요구하지 않는다.
- `언급시검사`는 답에 등장할 때만 조건·범위·값(별표의 행·열·직급·지역·통화·예외조건 포함)을 확인한다. 없다는 이유로 감점하지 않는다. `보충`도 감점하지 않으며 나오면 정확성만 검사한다.

## 2. 문항 등급 (서로 배타, 위에서부터 먼저 해당하는 것)

1. 오답: 표시된 답에 금지내용 위반, 잘못된 결론·조건·수치·단위, 대상 치환, 결론과 본문의 모순이 하나라도 있다. 핵심이 맞아도 뒤의 잘못된 보충은 오답이다.
2. 보류: 필수 하위질문 어디에도 실질적으로 답하지 못했다(관련 조문 목록만 표시, 고정 안내문만 표시, 확인 질문만 함). 단 아래 3항의 "확인되지 않음이 정답인 하위질문"에 답한 경우는 보류가 아니라 해당 하위질문의 충족으로 본다.
3. 정답: 모든 필수 하위질문이 충족이고 적용 조건·범위를 지켰으며 오류가 없다.
4. 부분: 적어도 하나의 필수 하위질문에 충족 또는 부분으로 답했고 나머지가 누락·부족이며 오류는 없다.
5. 실행오류: API 실패·파일 누락 등. 답변 등급과 별도 집계하며 분모에서 제외하고 건수를 보고한다.

시스템 모드(answer/partial/none), 의미 등급, 대상 치환 여부, 보류 여부, 실행오류를 별도 필드로 저장해 "확인되지 않음"을 정답으로 한 답과 시스템 보류를 구분한다.

## 3. 확인되지 않음·정보 부족·확인 질문

- gold가 "확인되지 않음"을 요구하는 하위질문은 규정에서 확인되지 않는다고 말하는 것(제도 부재의 단정이 아닌 표현)이 충족이다. "없다/금지된다"로 확대하면 오류다.
- 질문에 없는 직급·근속·나이·고용구분·출장 국내외·업무상 여부 등 적용을 결정하는 정보는 확인 질문 또는 조건부 분기로 처리해도 된다. 이미 설명할 수 있는 일반 기준을 모두 생략하고 정보만 묻는 답은 보류다.
- 확인 질문은 질문에 없고 실제 적용을 결정하는 정보를 요청할 때 유효하다. 확인 질문만으로 충분한 문항은 없다. 필수 하위질문이 둘 이상이면 확인 질문은 해당 하위질문만 미룬 것이고 나머지가 미응답이면 부분 이하다.
- `허용되는_정보부족_답변`은 정답기준의 면제 목록이 아니라 허용 가능한 구성요소다. `부분답_예시`가 있으면 그 답은 부분으로 판정한다(N008, N038, N073).

## 4. 근거 확보

- 단위는 조문이며, 하위질문별로 `핵심근거`의 조문 중 최소 충분한 묶음을 확보했는지를 본다. 같은 내용을 지지하는 다른 조문 경로도 인정하고 배열 전체를 AND 조건으로 쓰지 않는다.
- `보충근거`는 확보하지 못해도 감점하지 않는다. `적용배제근거`는 필수로 세지 않으며 그 내용을 해당 사안에 적용하면 오답이다.
- 근거 확보율은 검색 결과가 아니라 시스템이 답변 근거로 사용한 `entries` 기준으로 계산하고, 삭제 상태 조문은 현행 근거로 세지 않는다.

## 5. 집계

- 주 점수는 확정후보 62건이다. 미확정 18건은 별도로 집계하며 주 점수에 합산하지 않는다. 자료밖_필요 문항과 법령본문_필요 문항은 부분집합으로 따로 보고한다(내부자료로 답할 부분은 같은 기준으로 채점하고 외부 법률상 결론은 주 점수에서 확정하지 않는다).
- 실행오류 판정은 의미 등급 판정보다 먼저 분리한다. 실제 답변이 없으면 오답과 보류를 부여하지 않는다.
- 조건별 표에는 정답 / 부분 / 오답 / 보류 / 실행오류를 모두 보고하고, 성공 실행 대비 정답률의 분모를 명시한다. 전체 요청 80건 대비 실행 성공률과 표시 답 정답률도 따로 보고한다.
- 주 끔/켬 비교는 80문항(확정후보는 62문항) 최초 끔/켬 쌍 중 양쪽 초회 실행이 모두 성공한 공통 문항만 같은 분모로 계산한다. 한쪽만 실패한 문항은 짝 누락으로 따로 보고하고 정상 문항 퇴행 표에서 제외한다.
- 유형(유형1~4)과 용어집 조건(끔/켬)별로 건수를 보고한다. 사용자가 요청한 지표는 필요한 근거 확보, 대상 치환 오답, 불필요한 보류(gold가 답변 가능한 문항에서의 보류, 사람 검토로 판정), 정상 문항 퇴행(끔에서 정답·부분이던 확정후보 문항이 켬에서 더 나빠진 경우)이다.
- 용어집 규칙 발동은 실행 기록으로 분류한다: 제외 발동 / 검색 확장만 / 둘 다 미작동. 규칙 발동 여부별로 위 지표를 따로 본다.
- 전체 정확도만으로 일반적 개선을 주장하지 않는다. 효과 판단과 기본값 결정은 사용자가 결과를 본 뒤 한다.

## 6. 실행 조건과 추가 실행

- 끔/켬은 같은 입력, 코드, 데이터, DB, 모델, 프롬프트에서 용어집 설정만 다르다. 설정 해시와 runner 해시를 실행 전에 run manifest에 저장한다.
- 실행 순서는 교차한다: 문항 번호가 홀수면 끔→켬, 짝수면 켬→끔. 순서를 기록한다. 이미 성공한 예비 실행(N001~N010) 답변은 전체 실행의 초회 답과 섞지 않는다.
- 추가 실행은 초회 점수와 분리한 선택적 진단이다. 사람이 검토한 초회 최종 등급이 끔/켬에서 다른 문항에 한해 양쪽 1회씩 같은 조건으로 재실행하며, 대상 ID 목록을 추가 실행 전에 저장한다.
- 반복 답이 유리하다고 초회 답을 교체하거나 정답을 골라 쓰지 않는다. 주 비교 점수는 초회 쌍으로만 계산한다. 차이가 있는 문항만 고른 반복 결과는 전체 안정성이나 개선율의 추정 자료가 아니며, 양쪽 2회 결과가 같아도 안정적 해결로 확정하지 않는다.
- 같은 입력의 반복 실행에서도 약 25% 문항이 달라지는 노이즈가 개발 단계에서 관찰됐다. 1회 실행의 문항 단위 차이는 확정 근거로 쓰지 않는다.

## 7. 사람 확인과 라벨 표기

- 1차 판정은 LLM이 한다. 사람은 오답·부분·보류 전수와 끔/켬 등급 불일치 문항 전수, 그리고 정답 판정의 무작위 20%를 확인한다. 보류도 검토 대상이며 문항별로 답변 가능한 핵심이 있었는지로 불필요한 보류를 판단한다.
- 사람이 확인한 문항은 "확인 후 라벨", 확인하지 않은 정답 문항은 "LLM 잠정 라벨"로 구분해 저장하고, 전체 집계는 둘이 혼합된 집계임을 명시한다.
- 정답 20% 표본의 추출 단위는 표시 답 건수, 분모는 조건(끔/켬)별 정답 판정 건수, 올림하여 계산하고, 난수 seed와 대상 ID 목록을 판정 직후 저장한다. 사람 검토 시 용어집 끔/켬 조건은 가능하면 가려서 같은 기준으로 평가한다.
- 표본에서 정답 오판이 발견되면 나머지 정답에도 오류가 있을 수 있다는 한계를 보고한다. 추가 검토 범위는 응답 내용을 고치는 일과 구분한다.
