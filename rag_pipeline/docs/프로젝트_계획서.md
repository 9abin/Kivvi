# 사내 규정 질의응답 RAG 챗봇 — 진행 계획서

**팀**: MINI CNS
**프로젝트**: 한국벤처투자 내부규정 질의응답 RAG 기반 챗봇
**문서 목적**: 처음부터 지금까지의 진행 과정, 결정 사항, 남은 작업을 정리한다.
**기준 시점**: 2026.10.06

---

## 1. 목표와 범위

### 1.1 목표
내부규정 90건을 조문 단위로 검색해서, 근거 조항과 함께 답하는 사내 규정 질의응답 챗봇을 만든다.

### 1.2 범위
- **포함**: 규정 90건 전처리, 검색 색인, 질의응답, 평가
- **제외**: 검수 챗봇(사내 문서 수정 제안), 외부 법령 본문 연결(외부 DB에서 별도 처리)

### 1.3 기대 답변 방식
- 근거 조항을 인용한다 ("감사규정 제5조 제2항에 따르면…").
- 문서 간 충돌은 위계(정관 > 규정 > 지침)와 개정 순서로 판정한다.
- 근거를 찾지 못하면 "찾지 못했습니다. 담당 부서에 확인해 주세요"라고 답한다.
- 원문과 다른 표기를 답변에 쓸 때는 정정 안내를 함께 붙인다.

## 2. 전체 흐름

```
[원본 90건] → ① 전처리 → ② 색인 → ③ 검색 → ④ 답변 → ⑤ 평가
                ↑ 보정 목록(사람 판정)
```

| 단계 | 내용 | 상태 |
|---|---|---|
| ① 전처리 | 추출, 정제, 조·항 청킹, 참조 해석, 보정 적용 | **완료** (사람 판정 포함, 외부 참조 제외) |
| ② 색인 | BGE-m3 임베딩, PostgreSQL(pgvector) 저장 | 완료 (4,465개 색인) |
| ③ 검색 | 벡터 + BM25 하이브리드, RRF 결합, 메타데이터 필터, 리랭킹, 인용 1단계 확장 | 구현 완료 (정확 조회, 근거 조립, 운영 점검 포함). 가중치·예산은 골든셋 후 조정 |
| ④ 답변 | OpenAI API로 답변 생성, 조항 인용, 없음 규칙 적용, 충돌 판정 | 1차 구현 완료 (`gpt-4o-mini`, 인용 번호 검사, Streamlit 화면). 검증 전 |
| ⑤ 평가 | 골든셋 작성, 지표 측정, 기본 RAG와 고도화 비교 | 미착수 |

## 4. 완료한 작업 (시간 순)

### 4.1 1단계: 원문 검토 (23건)
- 감사규정 ~ 벤처투자회사 지침 구간 23건의 오탈자, 인용 관계, 조번호를 검토했다.
- 결과: `규정검토_오탈자_인용관계.md`
- 주요 발견: 감사지침이 감사규정의 옛 조번호를 인용하는 문제, 중복 조번호, 옛 명칭 잔존.

### 4.2 2단계: 전체 추출 (90건)
- HWP 84, HWPX 3, PDF 3 모두 추출했다. 실패 0건.
- 해결한 추출 문제
  - HWPX 머리글·바닥글 장식선 객체가 본문을 끊는 문제 → 해당 객체를 건너뜀
  - HWPX 줄바꿈 태그 뒤 글자가 빠지는 문제 → 꼬리 텍스트 포함
  - 깨진 글자 토큰, 머리글 번호 → 정제 규칙으로 제거

### 4.3 3단계: 청킹 규칙
- 조·항 단위로 나누고, 부칙은 따로 분리했다.
- 가지번호(`제8조의2`), 표기 오류(`제9조2`), 목록 번호 뒤 참조는 조 제목으로 보지 않도록 처리했다.
- 줄바꿈 없는 항(`…다.② …`)도 번호 순서가 맞으면 나눈다.
- 원문 항 번호가 중복된 경우 검색용 번호만 다시 매기고, 원문은 그대로 둔다.
- 조문이 없는 문서(윤리헌장)는 수동 청크로 처리했다.
- 결과: 청크 4,579개 (삭제 조문 25개 포함).

### 4.4 4단계: 참조(인용) 해석
- 약칭 사전을 26개 문서에서 만들었다(예: "감사지침의 '규정' = 감사규정").
- 참조를 상태로 나눴다.
  - 정상연결, 외부, 옛 규정 참조, 정정 확정, 근거 없음, 미해결
- 자동 연결 규칙을 추가했다: "정관 제N조" → 한국벤처투자 정관, "○○지침"의 "규정" → 같은 이름의 "○○규정".

### 4.5 5단계: 사람 판정 (보정 목록)
- 보정 목록(`data/manual/corrections.json`)에 155건을 기록했다.
  - 오탈자 130건 (확정 129, 치환 쌍 적용)
  - 참조 정정, 근거 없음, 옛 규정 판정, 항 번호 정정
- 주요 판정
  - 성과급지침 2조: 인사규정 39조의2 → 34조
  - 회계규정 72조: 제128조 → 71조
  - 인권경영 26조⑥: 19조②~21조 → 18~20조
  - 복지·후생 7조 2호: 13조② → 4조②
  - 내부통제 33조③: 제25조 → 제35조
  - 정관 39조의2·42조의2, 직제규정 3조의2: 없음 확인 (근거 없음)
  - 직제규정 부칙 ⑤항: 여비규정 22조의3 연결
  - 옛 규정 참조 116건: 검토 완료
- 외부 법령 참조 20건: 외부 DB 작업으로 넘김 (스킵)

### 4.6 6단계: 보정 적용과 검증
- 오탈자는 검색 텍스트에만 반영하고, 답변 인용은 원문 표기 + 정정 안내를 쓴다.
- 참조 정정은 `cites`에 반영한다.
- 보정 검증: 대상 조문과 치환 글자가 없으면 경고를 출력한다.

### 4.7 7단계: 재현성 정리
- 같은 명령을 두 번 실행한 결과가 해시까지 같음을 확인했다.
- 작업 중 만든 임시 파일은 `archive/`로 옮겼다.
- 치환 쌍 추출 도구, 테스트 19개, README(환경 조건과 실행 순서)를 갖췄다.

## 6. 남은 작업

### 6.1 제가 할 작업
1. **검색 색인(pgvector)**: 색인 대상 청크 4,465개(부칙·삭제 조문 제외)를 BGE-m3로 임베딩하고 Kiwi 형태소 토큰과 함께 저장. 완료.
2. **검색 구현**: 벡터 검색, BM25, RRF 결합, 메타데이터 필터(문서·위계·개정일).
3. **인용 1단계 확장**: 검색된 청크의 `cites`를 따라 연결 조문을 함께 가져오기.
4. **답변 생성**: OpenAI API 연결, 조항 인용 형식, "없음" 답변 규칙, 정정 안내 붙이기.
5. **문서 간 충돌 판정**: 정관 > 규정 > 지침, 나중 개정 우선.
6. **골든셋 초안**: 단순 조회, 다문서 종합, 개정 충돌, 답 없는 질문, 판단 불가 질문.
7. **평가 실행**: Recall@k, 출처 정확도, 적절한 거절률. 기본 RAG와 고도화 버전 비교.

### 6.2 팀이 결정하거나 확인할 작업
1. **외부 법령 DB**: 외부 문서 참조 20건(미해결 스킵) 및 외부 법령 연결 방식은 별도 진행
2. **골든셋 담당**: 질문 작성과 정답 확인 (실무 지식 필요)
3. **리랭커 모델**: 선정
4. **UI 프레임워크**: 선정
5. **인용 처리 방식 최종 합의**: 팀 메모에 "최종 합의 미확인"으로 남아 있음
6. **원본 연혁 확인 결과 공유**: 정관 39·42조의2, 직제 3조의2는 우리 자료 기준 "없음"으로 처리했음

## 8. 주요 결정 사항 (이력)

| 항목 | 결정 | 근거 |
|---|---|---|
| 벡터 저장소 | PostgreSQL + pgvector | 팀 공유와 키워드 검색을 한 DB에서 처리. 키워드 순위는 BM25 (검색 단계에서 계산) |
| 임베딩 | BGE-m3 | 기획서 확정 |
| LLM | OpenAI API | 사용자 결정 (기획서의 로컬 LLM에서 변경) |
| 인용 처리 | `cites` 메타데이터 + 1단계 확장 (그래프 DB 미사용) | 필요한 동작이 1단계 확장뿐 |
| 청크 ID | `{고유번호}_제N조[의K][_M항]` | 알리오 고유번호로 문서 충돌 방지 |
| 보정 방식 | 원문 불변, 별도 보정 목록 | 내부 공문서를 임의로 바꾸지 않기 위함 |
| 검색 텍스트 | 확정된 오탈자 반영 | 검색 적중률 |
| 답변 인용 | 원문 표기 + 정정 안내 | 원문과 다른 글자를 노출하지 않기 위함 |
| 옛 규정 참조 | 자동 연결하지 않음, 검토 완료로 처리 | 부칙은 과거 개정 경과 |
| 외부 법령 | 이번 작업에서 스킵, 외부 DB에서 처리 | 범위 관리 |
| 근거 없는 조문 | "담당 부서에 확인" 안내 | 추측 답변 방지 |

## 10. 재현 방법

자세한 실행 방법은 `README.md`를 본다. 요약은 다음과 같다.

uv run python run.py
uv run python -m unittest discover tests
